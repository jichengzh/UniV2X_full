# L1 修法提案: 纯追踪 (Pure Pursuit) 轨迹跟踪 — 原理性论证

> 作者: team-lead, 2026-06-10。供用户拍板。
> 依据: `l1_architecture_problems_v1.md` (五问题) + T1 多路实证 (r104/r136 行人横穿=τ_ego 敏感, r305/r331 洗牌噪声)。
> 主张: 用 **纯追踪 (pure pursuit) 几何轨迹跟踪** 替换当前"全局路由转向 + 冻结速度标量"。**单一推荐方案 + 原理根据**。

---

## §1 先确立被违反的原理 (诊断的本质)

自动驾驶栈的标准**关注点分离 (separation of concerns)**:

> **规划器 (planner)** 输出一条**参考轨迹** —— 它已经把避障、车道保持、转弯收弯、减速意图全部编码进 waypoints。
> **跟踪控制器 (tracking controller)** 的唯一职责 = 让车**忠实跟随这条轨迹**。

当前 V2 L1 **违反了这条原理**: 它在转向上**丢弃** planner 的轨迹, 改去跟一条独立的全局路由点 (`target_point`, weight=1)。后果 = planner 算出的避障**永远到不了转向执行器**。这不是参数没调好, 是**架构层把"该执行什么"和"如何执行"接错了线**。

⇒ 任何修复的第一性要求: **让控制器跟踪 planner 的轨迹本身**, 而非另一条路由。

---

## §2 提议的控制律: 纯追踪 (Pure Pursuit)

**纯追踪是几何路径跟踪的经典闭式解** (Coulter 1992, *Implementation of the Pure Pursuit Path Tracking Algorithm*, CMU Robotics Institute; 至今 Apollo/Autoware 的横向基线之一)。

给定参考轨迹 + 前视距离 `L_d`, 取轨迹上距车 `L_d` 的**前视点** `(g_x, g_y)` (车体系: x=横向, y=纵向):

```
α  = atan2(g_x, g_y)              # 车头朝向与前视点的夹角
κ  = 2·sin(α) / L_d               # 需要的转弯曲率 (1/R), 让车沿圆弧恰好过前视点
δ  = atan(κ · L_wheelbase)        # 自行车模型 → 前轮转角
steer = clip(δ / δ_max, -1, 1)    # 归一化到 CARLA [-1,1]
```

几何含义: **车沿一段恰好穿过前视点的圆弧行驶**。前视点取自 planner 轨迹 ⇒ 车沿 planner 规划的路径走。

---

## §3 为什么纯追踪在这里是有原理根据的 (五条, 逐一对应五问题)

### 原理1 — 几何精确性 (对应问题1A: 撞墙)
纯追踪驱动车沿**圆弧精确穿过轨迹上的前视点**, 是闭式几何解, 不是靠反馈"凑"。planner 已判定该轨迹可行/安全 ⇒ 几何跟踪**复现规划意图**, 车沿规划路径过弯, 不再朝 10m 外的路由点切弯撞墙。**消除 DS=65 的 layout 碰撞基线**。

### 原理2 — 无状态 ⇒ 根除 rate-mismatch (对应问题4: Fix-D)
纯追踪转向**只依赖当前 pose + 前视点**, 无积分/微分历史。
⇒ 对 20Hz-vs-5Hz 的 PID 窗口腐蚀**天然免疫** (deque 积分窗、stop_steps 4× 累积全部消失)。
⇒ **Fix-D 双控制器 hack 可以删掉** —— 不是绕过, 是从构造上不存在这个问题。

### 原理3 — τ_ego 透明性 (对应问题1B: τ_ego 动不了转向)
前视点取自**锚定的 (可延迟的) 轨迹**在时间索引位置上的点。延迟轨迹 (τ_ego) ⇒ 直接延迟控制器跟踪的参考 ⇒ **转向变成 τ_ego 敏感**。
⇒ 这才让**转向类避障场景** (变道/绕行) 也能显现 τ_ego 退化 —— 当前只有刹车类 (行人) 能显现 (r104/r136), 转向类被架构屏蔽了。

### 原理4 — 避障真正到达执行器 (对应问题1A)
因为跟踪的是 planner 轨迹 (内含避障), 避障机动**直达转向**。这是原理1的因, 撞墙消除是果。

### 原理5 — 已知稳定性 + 单一旋钮 (对应问题: 6-增益 PID 难调)
纯追踪稳定性被充分刻画: **前视距离 `L_d` 是唯一参数**。
- `L_d` 大 → 平滑稳定但切弯; `L_d` 小 → 跟踪紧但低速振荡。
- 标准做法: **自适应 `L_d = clip(k_v · v, L_min, L_max)`** (与速度成正比)。
⇒ 一个有理论保证、单参数、可解析调的控制器, 替掉当前 6 个 PID 增益的黑箱。

---

## §4 速度: 跟轨迹的速度剖面 (对应问题2)
不再冻结单标量。从时间索引段算期望速度:
```
v_des(t) = ‖wp[i+1] − wp[i]‖ / Δt_wp   (i = 当前时间索引, Δt_wp=0.2s)
```
⇒ 复现 planner 的减速意图 (如为行人减速); 配合 τ_ego, 速度剖面也变旧 ⇒ 晚刹车 ⇒ **保留并强化已验证的行人碰撞信号 (r104/r136)**。

---

## §5 τ_ego 深化 (对应问题5, 可选叠加)
当前 I-2 只延迟 plan 输出。可进一步把**感知输入** (喂 planner 的 occupancy/box) 也延迟 Δ_ego, 让推理帧 waypoints 本身就旧 = 整条链延迟。与纯追踪正交, 后续叠加。

## §7 风险与缓解 (诚实)
1. **纯追踪已知失效模式**: `L_d` 过大切弯、过小低速振荡。缓解 = 自适应 `L_d ∝ v` + 夹断 (标准做法)。
2. **需重新验证**: 新控制器要走自己的 V0 (几何单测: 前视点选取、κ 公式、圆弧穿点) + V1 (闭环 RC=100 + 撞墙是否真消除)。不能假设直接好。
3. **复用已有基建**: `l1_trajectory_controller.py` 的 `get_local_ref`/`time_index_ref`/坐标变换已造好, 纯追踪只替换 `run_l1_step` 里的转向求解 (替掉 V2X_Controller.run_step 那段), 估 **~80 LOC**。
4. **标定细节**: CARLA steer 是归一化 [-1,1] 非物理角; δ_max / L_wheelbase 需按 ego 车辆标定 (一次性)。

---

## §8 这个修法买到什么 / 不改变什么 (期望管理)
- **买到**: ①消除撞墙基线 (DS 天花板从~65 抬向 100) ②转向类避障场景变 τ_ego 敏感 ③删掉 PID hack, 控制器可解析调。
- **不改变 (但强化)**: 行人刹车的 τ_ego 信号 (r104/r136) 本就靠速度路径工作; 速度剖面跟踪会强化它。
- **诚实**: 纯追踪本身不保证立刻 RC=100, 需 V0/V1 验证。撞墙是否消除是 V1 的硬验收。

---

## §9 与场景筛选的关系 (两条线如何合)
- **短期 (便宜, 不依赖本修法)**: 用 r104/r136 类**行人横穿 (Scenario3)** 路线 + n≥3 重复, 现有 L1 即可出干净的"加速→驾驶分(行人安全)"曲线 —— 因为这条信号走速度路径, I-2 已支持。
- **本修法 (增强)**: 纯追踪让**转向类避障**也 τ_ego 敏感 + 消除撞墙基线 ⇒ 信号更强、更普适、baseline 更干净 (论文更硬)。
- ⇒ 建议: **先用 Scenario3 路线锁定核心卖点曲线 (本周), 纯追踪作为下一步架构升级 (让全 benchmark 可用 + 转向避障故事)**。
