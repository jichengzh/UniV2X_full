## §0 一句话 — 为什么这是最高杠杆的下一步

当前仿真只注入了 **τ_RSU(路侧时延)**, 而 **τ_ego(自车推理时延)=0**。后果是致命的:

> **本项目软硬件协同加速降的就是 τ_ego(Orin e2e 真测 FP32 219→INT8 p75 108ms, 降 ~111ms)。但闭环里 τ_ego=0 ⇒ 不同加速档的 ego 反应延迟全相同(=0) ⇒「加速→更快反应→更安全」这条论文核心因果链, 在仿真里恒为空。**

补 τ_ego 是让"加速对驾驶分的收益"从恒 0 变成**可测曲线**的唯一途径(supervisor ISS-046)。这比继续铺 RSU sweep 杠杆高得多——RSU 时延是 V2X 协同特有维度(有研究价值), 但 **τ_ego 才是连接"我们的加速工作"与"闭环驾驶收益"的桥**。

## §1 两个时延、两条路径 — 物理模型 (匹配的数学骨架)

τ_comm(协作)与 τ_compute(自车)作用在管线**不同位置, 绝不能合成一个标量**。统一量 = **逐路径信息年龄(per-path information age)**。CARLA 50ms/帧, 全量化为帧数。

| 路径 | 信息年龄 | 物理含义 | 施加位置 | 状态 |
|------|---------|---------|---------|------|
| **协作路 (RSU/CAV)** | `age_collab = τ_collab_compute + τ_comm + τ_wait` | 协作 BEV 算完→传到→等到融合有多旧 | **融合前、只作用 RSU 路**: Δ_RSU=ceil(age_collab/50) 后推帧 + ZOH。**不推迟自车出控制** | ✅ 已实装(§3.8) |
| **自车路 (ego)** | `age_ego = τ_ego_compute (+τ_act)` | 基于帧 t 数据算的 plan 要到 t+age_ego 才生效 | **推迟自车出控制**: 帧 k 执行的 plan 来自帧 k−Δ_ego 的感知, Δ_ego=ceil(τ_ego/50)。**整条控制链滞后** | ❌ τ_ego=0, 本策略要补 |

**本质区别(实现必须落实)**:
- **τ_RSU 只改"协作 BEV 内容有多旧"** → 影响融合质量 → 间接影响 planner 输出。**不改 ego 出控制的时刻。**
- **τ_ego 改"整个 plan 何时可用"** → ego 感知/融合/规划全往后推 Δ_ego 帧 → 控制反应整体滞后, 降闭环相位裕度(超调/避障滞后/碰撞)。**直接改 ego 出控制的时刻。**
- ⇒ **正交的两个旋钮, 必须分别注入。合成标量 = 物理错误。**

## §2 时间轴匹配 — 两延迟在帧 k 上如何叠 (★核心)

在仿真帧 k(每帧 50ms):

```
ego 本车感知:  帧 k 实时采集, 但 plan 受 τ_ego 推迟:
               帧 k 实际执行的 plan = 基于帧 (k−Δ_ego) 的 ego 感知算出的
协作 RSU 感知:  ego 在帧 (k−Δ_ego) 计算时, 用的是当时能拿到的最新 RSU 结果,
               那一份 RSU 来自帧 (k−Δ_ego−Δ_RSU)  ← 两延迟串联
控制输出:      帧 k 执行帧 (k−Δ_ego) 算出的 plan
               (L1: 沿轨迹按时间索引推进; L0: 冻结指令 = 非物理, 不可用)
```

**关键: RSU 陈旧度是叠加在"ego 实际用的那一帧"上的 → Δ_ego 与 Δ_RSU 串联**。即帧 k 执行的控制, 其协作信息总年龄 = (Δ_ego + Δ_RSU) 帧。这与真实系统一致: ego 推理在 k−Δ_ego 发生, 那一刻 fuse 的 RSU 已经是 Δ_RSU 旧的。

## §3 实现设计 (★工程提纲)

| 步 | 内容 | 依赖 | LOC 估 |
|----|------|------|--------|
| **I-1 L1 轨迹跟踪控制器** | planner 输出 waypoints 锚定**世界系 + t_anchor**; PID 每 tick 跟踪"最近可用 plan", 按 (t_now−t_anchor) 时间索引插值取参考点(非永远跟 wp[0])。**τ_ego 生效的前提**(L0 冻结指令无法表达"沿旧轨迹推进、对新障碍滞后") | planner 输出转世界系 | ~60+40 |
| **I-2 τ_ego 注入** | config `simulation.tau_ego_ms` → Δ_ego=ceil(τ_ego/50); 帧 k 执行的 plan 来自帧 k−Δ_ego 的感知(整条 ego 感知→融合→规划链后推 Δ_ego) | I-1 | ~50 |
| **I-3 LatencyScheduler 取代 skip_frames=4** | 当前 skip=4(200ms)是写死 ego 节拍、与 τ_ego 无关。改为**作业完成驱动**: ego 下次推理不早于上次完成(+τ_ego); 推理慢则下帧 plan 晚到, 节拍随加速档变 | I-2 | ~80 |
| **I-4 加速档↔τ_ego 映射表** | 接团队 E7 真测: {FP32 219→Δ_ego=5, FP16 136→Δ_ego=3, INT8 p75 108→Δ_ego=3, 剪枝各档待 hw 补}。不同档喂不同 Δ_ego | hw 真测 | 数据 |
| **I-5 串联匹配** | 帧 k: ego plan 来自 k−Δ_ego, 其 RSU 来自 k−Δ_ego−Δ_RSU(§2)。复用已建 RSU 路 ZOH/buffer, 只需把"ego 用的参考帧"从 k 改成 k−Δ_ego | I-2 + §3.8 | ~30 |

**两个独立 config 旋钮**: `simulation.tau_ego_ms`(驱动 Δ_ego) + 现有 `latency_trace`/`latency_inject_ms`(驱动 Δ_RSU)。

**★τ_ego 与 L1 捆绑实现**: L0 零阶保持冻结的是控制指令, 无法物理正确表达 age_ego 的滞后(沿旧轨迹推进 vs 锁死方向盘是两回事)。**τ_ego 注入了但用 L0 = 被扭曲**, 故 I-1(L1) 是 I-2(τ_ego) 的硬前提, 必须先做。

## §4 留给你拍板的 4 个设计决策 (★supervisor 提的开问题 + 我的推荐)

| # | 开问题 | 我的推荐 | 理由 |
|---|--------|---------|------|
| **D1** | Δ_ego 与 Δ_RSU **串联还是并列**? | **串联**(§2) | 真实系统: ego 在 k−Δ_ego 计算时 fuse 的 RSU 已是 Δ_RSU 旧 ⇒ 总年龄 Δ_ego+Δ_RSU。物理正确 |
| **D2** | τ_act(作动延迟)是否**单列**? | **v1 并入 age_ego 不单注**(或忽略) | CARLA 低速场景 τ_act 小; 高速再单列。先不增复杂度 |

## §5 实验设计 — 补 τ_ego 后能证明什么 (★项目卖点闭合)

**核心实验 = 加速档 sweep → 驾驶分曲线**(当前恒平, 补 τ_ego 后应分化):

| 加速档 | τ_ego(Orin 真测) | Δ_ego | 预期驾驶分 |
|--------|-----------------|-------|-----------|
| FP32 零优化 | 219ms | 5 | 最低(反应最慢) |
| FP16 | 136ms | 3 | 中 |
| INT8 p75 | 108ms | 3 | 较高 |
| INT8+剪枝(最优) | <108ms | 2 | 最高(反应最快) |

- **在难场景(r146/r160, 待探针证 norsu<满分)上跑** ⇒ 若驾驶分随 τ_ego 下降单调升 = **"加速→更快反应→更安全"因果链在闭环被证**, 这是论文核心。
- **双轴联合**: 固定 τ_ego 扫 τ_RSU(V2X 协同价值) + 固定 τ_RSU 扫 τ_ego(加速价值) + 联合网格(D 维闭环投影)。
- **对照**: τ_ego=0(理想机, 现状)作上界; 各真实加速档作可达点。

## §8 诚实 caveat

1. **τ_ego 实现工程量比 RSU 路大**: L1 控制器 + scheduler 是真改造(~200+ LOC), 非配置开关。不是一天的活。
2. **L1 改造可能改变 baseline 驾驶行为**: 上 L1 后即便 τ_ego=0, 驾驶分也可能与当前 L0 不同(控制机制变了)。需先验"L1 + τ_ego=0 ≈ 合理 baseline"再加 τ_ego。
3. **加速档↔τ_ego 映射依赖 hw 真测**: FP32/FP16/INT8 的 Orin e2e 已有(E7); 各剪枝率档的 τ_ego 需 hw-optimizer 补, 否则映射表不全。
4. **driving 信号仍依赖场景**: 即便补了 τ_ego, 若难场景探针证明场景太易(norsu 满分), τ_ego 也测不出驾驶分分化 —— §6 步骤1 是硬前提。
