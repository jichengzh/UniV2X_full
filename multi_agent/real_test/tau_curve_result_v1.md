# τ_ego 延迟→V2X驾驶 曲线 — 最终结果 (tau_curve_result_v1)

> 2026-06-13 主控亲跑 + 核验。平台 H800/GPU0-4, 配置 `_1notraffic`, CoDriving, Town05-short。

## TL;DR — 稳健 null 结果
注入 ego 推理延迟 τ_ego = 0→500ms (Δ_ego = 0→10 帧 ego-plan stale), **对碰撞率 / 驾驶分 / 路线完成率三轴均无可测影响**。

| τ_ego(ms) | n | ped碰撞率 | DS mean±95%CI | RouteCompletion |
|---|---|---|---|---|
| 0 | 38 | 0.26 | 86.3 ± 7.4 | 100 |
| 100 | 39 | 0.18 | 89.4 ± 7.5 | 100 |
| 200 | 39 | 0.23 | 88.5 ± 6.7 | 100 |
| 300 | 39 | 0.23 | 86.7 ± 7.9 | 100 |
| 400 | 39 | 0.15 | 91.2 ± 6.7 | 100 |
| 500 | 39 | **0.23** | **85.9 ± 7.3** | 100 |

te500 与 te0 统计上无法区分 (碰撞率 0.23 vs 0.26; DS CI 完全重叠)。0.15-0.26 的起伏 = 脚本行人边际碰撞噪声 (n=39 时率的 95%CI ≈ ±0.13, 各点重叠)。

## 关键: 这是真 null, 不是工程假象
- **Δ_ego 延迟确实生效** (核验 B server 日志): te100→Δ2帧 / te200→Δ4 / te300→Δ6 / te400→Δ8 / te500→Δ10, 逐档真注入。**不是** 项目史上 INT8→fp16 / mask-pruning 那种"优化静默 no-op"。
- te0 基线本身非确定: 13 条冻结路 te0 已有 ~26% 行人碰撞 (6 条 r0/1/5/11/310/325 确定 100; 7 条 r7/16/17/24/302/326 在零延迟就抖)。Phase A 的 N=1 快筛漏检 (r24 筛 100 实际 3/3 撞) → **印证 N≥3 必要**。

## 机理 (为什么延迟不伤驾驶)
1. **碰撞方差被脚本行人边际几何主导** (~20% 即便 te0): Scenario3 行人 KeepVelocity 横穿, ego 避让余量本就在 CARLA 物理非确定带, 撞不撞主要由这个边际决定, 不由 plan 新鲜度决定。
2. **ego plan 在 10 帧内空间上几乎不变** → 用 500ms 前的 plan 仍能 track (轨迹是空间路点, 非时间临界)。RC 恒 100 = ego 从不卡死, 佐证延迟没让它失稳。
3. **选样张力**: 要 te0 干净基线 → 只能选高余量路; 但高余量路恰恰对延迟不敏感。历史敏感路 (r6@te219 / r3@te500 崩) 因 te0 就撞被排除。"te0干净 + 高延迟才崩"的甜点区对本模型/场景近乎空集。

## ★ 方法学定论 — 注入点可能错了 (下一步关键)
当前 τ_ego 只延迟 **ego plan 输出** (L1PlanStore), **感知保持新鲜**。但真实推理延迟应延迟 **感知→检测** (行人被晚检测到 → ego 晚反应 → 撞)。感知新鲜、只 plan 陈旧、且 plan 空间平滑时不伤驾驶 = 合理。
⇒ 若要 τ→驾驶退化曲线有信号, **应把延迟注入感知链路 (延迟行人/障碍检测), 而非只延迟 plan**。这是把 null 变信号最可能的杠杆。
