## 1. 本次补充结论

之前的 Phase C stable smoke 描述不够硬, 容易让后续 agent 误以为 AP 只是生成一个 `ap_job_queue.jsonl`, 或继续按旧规则使用单 GPU3 + idle gate。这里明确修正:

1. Phase C 首批 AP stable smoke 必须包含真实微调闭环, 不是 predicted/model-fit/import-only。
2. 首批新配置固定 5 个, 使用 H800 GPU0-4 五卡并行微调。
3. 每个新配置默认只做 1 次 finetune, `epoches=31`, 即从 init@23 到 epoch31 的约 8 个 finetune epochs。
4. AP finetune 和 AP eval 不要求 GPU 完全空闲; 只要求显存足够、不 OOM, 并记录 `nvidia-smi`/`pmon` 并发状态。
5. latency/energy 的 GPU idle gate 不适用于 AP finetune/eval。
6. 数据集固定为 DAIR-V2X-C train/val; AP measured row 只能来自 full val_1789 eval。

## 3. AP 新配置产出链路

每个新配置必须完成同一条链路:

```text
width spec
  -> structural_prune_pyramid 生成 full-model config + init ckpt
  -> flat ckpt check
  -> train_ddp.py --half 单卡微调
  -> 锁定 best checkpoint
  -> ONNX export
  -> TRT FP16 engine build
  -> DAIR-V2X val_1789 AP eval
  -> canonical AP row 或 quarantine row
```

不能把以下内容写为 measured AP:

```text
predicted AP
model-fit AP
interpolated AP
只有 backbone ONNX/TVM artifact 的配置
没有 full-model ckpt/config 的配置
随机初始化或 ckpt 格式错误产生的 AP
mini-val 或小样本 smoke AP
```

## 4. 微调协议

### 4.1 默认次数

| 项 | 默认规则 |
|---|---|
| 每个新配置 finetune 次数 | 1 次 |
| 每个新配置 AP eval 次数 | 1 次 full val_1789 |
| 默认 epoch | `epoches=31` |
| 初始化 checkpoint | base/pruned init 的 `net_epoch_bestval_at23.pth` |
| 实际微调长度 | 约 8 个 epoch, 从 epoch23 到 epoch31 |
| repeat | 不默认对 5 个新配置全做 repeat |

需要追加 repeat 或延长训练的触发条件:

1. AP70 高于 base 或明显违背局部趋势。
2. best checkpoint 出现在最后 epoch, 表明可能未收敛。
3. AP 曲线波动大或 train/val log 明显异常。
4. 该点进入 paper/final claim 子集。

追加策略:

| 场景 | 处理 |
|---|---|
| AP 异常但训练正常 | 同配置补第 2 seed |
| bestval 在最后 epoch | 延长到 `epoches=48` |
| 仍未收敛或 paper 关键点 | 延长到 `epoches=70`, 并做 2 seed |
| 训练/eval 崩溃 | quarantine 当前配置, 不写 measured AP |

剪枝后必须检查:

2. `config.yaml` 中训练预算被设置为 `epoches=31`。

4. 如果 checkpoint 是 `{"model_state_dict": ...}` 包裹格式, 必须 unwrap 后再训练。

### 4.3 单卡 DDP 微调

每张 GPU 一个单卡 DDP 进程:

```bash
CUDA_VISIBLE_DEVICES=<GPU> \
PYTHONPATH=/home/jichengzhi/heal_research/HEAL \
/home/jichengzhi/miniconda3/envs/UniV2X_2.0/bin/python \
  -m torch.distributed.launch \
  --nproc_per_node=1 \
  --use_env \
  --master_port=<29700+GPU> \
  /home/jichengzhi/heal_research/HEAL/opencood/tools/train_ddp.py \
  --hypes_yaml /home/jichengzhi/heal_research/checkpoints/stage1/Pyramid_DAIR_m1_stage2_ap_<label>_2026_06_26/config.yaml \
  --model_dir /home/jichengzhi/heal_research/checkpoints/stage1/Pyramid_DAIR_m1_stage2_ap_<label>_2026_06_26 \
  --half
```

GPU 规则:

| 项 | 规则 |
|---|---|
| GPU 分配 | GPU0-4 固定对应 5 个配置 |
| 并行度 | 5GPU 同时跑, 每卡 1 个配置 |
| idle gate | 不要求 GPU 完全空闲 |
| memory gate | 必须显存足够, 不得明显 OOM |
| 并发记录 | 启动前保存 `nvidia-smi` 和 `nvidia-smi pmon -c 1` |
| failure handling | 单配置失败只 quarantine 该配置, 其他配置继续 |

## 7. Phase C AP 完成判定

只有满足以下条件, 才能说 Phase C stable smoke 的 AP 首批配置稳定产出:

1. 10 个已有 source/import 配置都有 canonical AP row 或明确 replay/quarantine 状态。
2. 5 个新微调配置全部完成完整链路, 或每个失败点都有明确 quarantine reason。
3. 至少 3 个 replay anchor 通过 `abs(AP70_observed - AP70_expected) <= 0.003`。
4. measured AP row 中 0 条来自 predicted/model-fit/interpolated AP。
5. `ap_stability_summary.md` 能直接展示 label、width、GPU、finetune 次数、epoches、dataset/split、AP30/AP50/AP70、claim_status。
