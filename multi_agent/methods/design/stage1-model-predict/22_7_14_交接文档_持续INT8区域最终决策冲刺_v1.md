# 交接文档 22：持续 INT8 区域最终决策冲刺

**日期**：2026-07-11  
**范围**：CoDriving `32x64x128` 前两个高 FLOPs Conv，H800，TVM `0.20.dev1070+gb628d91fa`  
**目标**：在有限时间内给出可执行的最终结论：继续 TVM 自动 INT8，或停止该后端上的 INT8 攻坚并采用 FP16/TRT INT8。

## 1. 决策问题

本轮不再无限扩点，也不再回到手写 `im2col+MMA`。只回答：

1. 当前 TVM 自动后端是否已经形成 region 内持续 INT8？
2. 若已经形成，INT8 仍慢的可消除成本集中在哪里？
3. 在一次边界归因和一次自动融合改造预算内，完整 INT8 region 能否显著快于同构 FP16？
4. 若不能，论文和框架应如何保留 INT8，而不继续消耗主要研究时间？

## 2. 已有自动真测

| realization | median latency | 与 FP16 比较 | TensorCore | 进程离散度 |
|---|---:|---:|---:|---:|
| rank1 FP16 core | 0.106195 ms | baseline | 1/1 | 0.441% |
| rank1 INT8 core | 0.073650 ms | 1.442x speedup | 1/1 | 0.317% |
| rank1 complete INT8 | 0.149648 ms | 慢 40.91% | 1/1 | 0.420% |
| top-2 FP16 region | 0.167482 ms | baseline | 2/2 | 0.096% |
| top-2 INT8 region | 0.216462 ms | 慢 29.25% | 2/2 | 0.234% |

这些结果来自高层 Relax `nn.conv2d`、自动 lowering、MetaSchedule 和固定数据库三独立进程复测。没有使用显式 TE im2col、手写 matmul PrimFunc 或历史 hand-rewrite。

## 3. 对“Conv 间恢复精度”的修正

对 `measure_t128_int8_rank2_region_p1/scheduled_tir.py` 的静态审计已经证明：当前 region 不是每个 Conv 后恢复 FP16。

实际调用链为：

```text
FP16 region input
-> 独立 input quantize PrimFunc，输出 INT8
-> Conv1 INT8 TensorCore + fused scale/bias/requant/ReLU，直接输出 INT8
-> Conv2 INT8 TensorCore + fused scale/bias/dequant，最终输出 FP16
```

关键证据：

```text
lv  : input quantize output, dtype=int8
lv1 : Conv1 fused epilogue output, dtype=int8
gv  : Conv2 fused exit output, dtype=float16
```

因此：

- Conv1 与 Conv2 之间没有完整 FP16/FP32 activation tensor；
- Conv1 epilogue 内确实使用标量 FP32 scale/bias 表达式，但直接写 INT8 region tensor；
- 当前 TVM 已实现“region 间保持 INT8”，但仍有三个独立 PrimFunc/kernel：入口 quantize、Conv1、Conv2；
- 两个 Conv 内部均存在 INT32 accumulator 的 local/shared/global-style materialization 与 epilogue；
- 剩余问题不应再描述为“每层都 Q/DQ”，而应描述为入口 Q、INT32 accumulator/epilogue、kernel/layout 边界和有效利用率。

## 4. 对 TensorRT 的谨慎口径

不能只凭 TRT 总延迟宣称“两个 Conv 被融合成一个大 kernel”。必须用 engine inspector/layer profile 验证。成熟 TRT 后端更可能同时具备：

- region 内保持 INT8 或内部 packed TensorCore layout；
- Q/DQ folding；
- bias、activation 和 requant epilogue fusion；
- tactic 选择、layout propagation 和较低 launch/materialization 成本。

本轮比较的是这些能力的综合差距，不预设 TRT 一定生成单个 mega-kernel。

## 5. 最终决策冲刺

### D0：静态边界审计

状态：**已完成**。

输出：

- region call graph；
- 每个 PrimFunc 输入/输出 dtype；
- TensorCore Conv 数；
- INT32/FP32/FP16/INT8 中间 buffer；
- 是否存在 Conv 间 FP16/FP32 activation materialization。

当前结论：Conv 间持续 INT8 已成立，不能再把主要问题归因于“Conv 间恢复 FP16”。

### D1：TVM kernel 时间归因

只对 top-2 FP16/INT8 region 各执行一次 profiler run，正式 latency 仍使用已有三进程结果。记录：

| 项目 | 目的 |
|---|---|
| kernel count/name/duration | 入口 quantize 和两个 Conv 各占多少时间 |
| INT32 accumulator store/epilogue | 是否存在主要 materialization 成本 |
| DRAM bytes/throughput | 是否由中间写回主导 |
| TensorCore utilization | INT8 core 是否因 tile/padding 利用率下降 |

若 H800 禁止 Nsight Compute counter，则保留 Nsight Systems/CUPTI kernel 时间和 scheduled TIR 静态证据，不等待管理员权限。

### D2：TRT 同构机制对照

优先复用已有 CoDriving TRT INT8/FP16 engine 与 inspector；只有现有证据不能覆盖前两个 Conv 时，才构建相同双 Conv Q/DQ micrograph。记录：

- layer/tactic 数；
- layer precision 与 tensor format；
- Q/DQ 是否被折叠；
- 两个 Conv 是否独立；
- FP16/INT8 paired latency。

### D3：唯一一次 TVM 自动改造

只允许实现通用 compiler/backend 改造，不允许手写模型专用算子：

1. 自动识别 `Conv -> bias -> requant -> ReLU -> Conv` 连续量化 region；
2. region 内保持 INT8；
3. 自动融合可融合 epilogue，避免独立 dequant/requant PrimFunc；
4. 若入口 quantize 是主因，支持由上游量化 producer 直接提供 INT8，或扩大自动 region 以摊销一次入口；
5. realization 由 capability scan 和实测产生，不绑定具体 Conv ID。

当前 runner 已满足第 1--3 项的基本图结构，因此 D3 只有在 D1 找到新的、可消除的大成本时才继续；不得重复实现已经存在的 persistent INT8 region。

## 6. 硬停止条件

本轮最多完成 D0--D3，不扩更多 width、不做大规模 AP、不继续手写 kernel。

### 继续 TVM INT8

必须同时满足：

1. 自动 source-Conv 路径；
2. top-2 region `2/2` TensorCore；
3. numerical mean error `<=0.05`；
4. 三独立进程 median 显著低于 FP16 `0.167482 ms`；
5. 差异大于跨进程离散度；
6. 改造是通用自动后端能力。

### 停止 TVM INT8 攻坚

以下任一成立即停止：

1. persistent INT8 已成立但仍慢，且 D1 没有足以覆盖 `48.981 us` region 差距的单一可消除成本；
2. 唯一一次通用自动改造后仍不快于 FP16；
3. 需要模型专用名单、手写 im2col/MMA 或大规模重写 TVM 才可能继续；
4. 速度改善导致 numerical gate 再次失败。

## 7. 停止后的框架与论文口径

若停止 TVM INT8：

1. **不写成 NVIDIA/H800 上 INT8 普遍无效。** rank1 INT8 core 已证明硬件计算优势存在。
2. 结论限定为：在当前 CoDriving/Pyramid 模型、剪枝空间、H800 和当前 TVM 自动后端实现下，完整 INT8 region 的边界/调度成本使 FP16 更优。
3. TVM compiler profile 保留 pure INT8 逻辑臂，并通过新 gold 冷启动和回流学习其当前性能劣势，不写人工禁用规则；mixed 历史证据保留，但在联合准入前不进入 active manifest。
4. NVIDIA TRT profile 保留 INT8 搜索臂；已有 paired engine 证据用于说明成熟后端可以实现 INT8 收益。
5. 论文贡献仍是后端条件化自动搜索：精度选择依赖 compiler capability 和实测代价，而不是固定“INT8 必然优于 FP16”。

## 8. 当前状态

- D0：完成，persistent INT8 已成立；
- D1：完成，Nsight Systems kernel 时间归因见第 9 节；
- D2：完成，复用同 width CoDriving TRT paired measurement 和 inspector；
- D3：根据硬停止条件取消；
- 最终结论：停止当前 TVM 自动后端上的 INT8 性能攻坚，TVM 采用 FP16，TRT 保留 INT8。

## 9. D1：TVM Nsight Systems 结果

Profiler run 与正式 latency 分开。正式结论仍采用三独立进程 median；以下 kernel median 只用于归因。

### 9.1 FP16 top-2 region

| kernel | median duration |
|---|---:|
| Conv1 + bias + ReLU | 111.808 us |
| Conv2 + bias | 53.728 us |
| 合计 | 165.536 us |

### 9.2 INT8 top-2 persistent region

| kernel | median duration |
|---|---:|
| input FP16 -> INT8 quantize | 46.128 us |
| INT8 Conv1 + fused requant/bias/ReLU | 94.224 us |
| INT8 Conv2 + fused exit dequant/bias | 61.952 us |
| 两个附属小 kernel | 约 7.840 us |
| 主要 kernel 合计 | 约 210.144 us |

与正式三进程结果一致：

```text
FP16 region median = 167.482 us
INT8 region median = 216.462 us
gap                =  48.981 us
```

归因：

1. Conv1 INT8 相比 FP16 节省约 `17.584 us`；
2. Conv2 INT8 相比 FP16增加约 `8.224 us`；
3. 入口 quantize 单独消耗约 `46.128 us`，是最大的可见边界；
4. 即使理想地完全删除入口 quantize，当前 INT8 主要 kernel 仍约为 `164.016 us`，只比 FP16 `165.536 us` 快约 `0.9%`，没有超过现有跨进程噪声/部署变化的稳健余量；
5. 若计入两个附属小 kernel，完全删除入口 quantize 后仍不快于 FP16。

因此没有发现一个在当前 top-2 region 内消除后即可稳定覆盖 `48.981 us` 差距的单一成本。继续需要把 INT8 region 扩到更大图范围、让上游直接产生 INT8 并重新解决数值/AP，这已经超出本轮一次通用改造预算。

原始证据：

- `results/codriving_source_conv_auto_20260711/raw/profiles/fp16_rank2_region.nsys-rep`
- `results/codriving_source_conv_auto_20260711/raw/profiles/int8_rank2_region.nsys-rep`
- 对应 `*_cuda_gpu_kern_sum.csv`

## 10. D2：TRT 后端上界

同一 `32x64x128` CoDriving backbone 的既有 paired measurement：

| backend/precision | p50 latency | p99 latency | energy/inference |
|---|---:|---:|---:|
| TRT FP16 | 0.424384 ms | 0.428096 ms | 0.147428 J |
| TRT INT8 | 0.296528 ms | 0.301408 ms | 0.079616 J |

TRT INT8 相对 FP16：

- latency speedup：`1.431x`；
- energy reduction：约 `46.0%`。

Inspector 对该 width 的结果：

- 32 个 Conv 使用 INT8 weight/tactic；
- 30 个 Conv 的全部输出保持 INT8；
- 仅 2 个 Conv 存在 float output；
- 全 engine 只有 1 个 reformat layer。

这证明 INT8 在 H800/NVIDIA 上不是无效精度，而是强依赖后端能否在更大图范围传播 INT8 format、折叠 Q/DQ 并选择成熟 tactic。现有证据不支持“TRT 把两个 Conv 合成一个 kernel”的强说法，但支持“TRT 在全 backbone 上维持大范围 INT8，显著减少边界”的结论。

## 11. 最终停止决定

### 11.1 决定

**停止继续攻击当前 TVM 自动后端上的 INT8 性能。**

原因：

1. 自动 source-Conv、MetaSchedule、`2/2` TensorCore 和 Conv 间 persistent INT8 均已成立；
2. 完整 top-2 region 仍比 FP16 慢 `29.25%`；
3. profiler 表明完全删除最大单项入口 quantize 也只能达到约持平，不能形成稳健加速；
4. 下一步若继续，需要扩大到全 backbone INT8 format propagation、重新处理残差/分支/scale alignment 和 AP，工作量不再是一次局部融合修复；
5. TRT 已经给出同硬件、同模型 width 下 `1.431x` INT8 加速，说明论文不需要证明 TVM INT8 必然成功。

### 11.2 框架落地口径

- `TVM + H800 + 当前 CoDriving/Pyramid compiler profile`：FP16 是当前实测优选；本轮 diagnostic INT8/mixed 行不进入 final gold。后续新 96 中，同 pipeline、正式校准且 numerical/AP 合格的 TVM INT8 行即使更慢，也必须作为 gold 负性能样本保留，由搜索器学习其劣势；mixed 在联合准入前不进入 active manifest。
- `TRT + H800 + CoDriving compiler profile`：保留 FP16/INT8 搜索臂，INT8 有真实 latency/energy 优势。
- capability scan 输出后端支持的 precision propagation、Q/DQ folding、reformat 和 tactic 证据；不把 `backend_name -> precision` 写成人工规则。
- 论文结论是 backend-conditioned precision search，而不是“INT8 总快”或“FP16 总快”。

### 11.3 后续不再做的工作

- 不再为 TVM 手写 im2col/MMA；
- 不再为 top-2 region 增加更多局部 Q/DQ 变体；
- 不再在没有全图 format propagation 方案时扩大量 width；
- 不再把 diagnostic calibration 数据送入 gold cold-start 或 final frontier。

## 12. 下一步 canonical 架构优化计划

下一阶段不再优化 TVM INT8 kernel，而是重构自动搜索架构，使框架在不知道“TVM 应选 FP16、TRT 应选 INT8”这一人工结论的前提下，通过能力扫描、gold cold-start 和实测回流自行学到条件差异。

### 12.1 冻结后的设计边界

第一版 active genome：

```text
([p1,p2,p3], q_mode)
q_mode = fp16 | int8
```

约束：

1. compiler/backend 名称不进入 genome，也不作为直接预测特征；
2. capability scan 输出数值化的 dtype、TensorCore、precision propagation、Q/DQ folding、reformat、fusion 和 tuning 能力；
3. backend 名称只用于测量 dispatch、artifact 定位和审计；模型只读取 capability profile 的数值特征和 digest；
4. TVM INT8 臂不删除，即使预计较慢也必须按 gold 协议测量；
5. `mixed_policy_id` 默认 `none`，只有同 pipeline、正式校准、numerical/AP 通过且形成非支配点后，才由 active manifest 条件激活；
6. historical hand-rewrite、旧 mixed latency 和 diagnostic calibration 不得进入最终 latency/energy/AP gold。

### 12.2 A0：统一 measurement contract 与证据路由

复用并接通：

- `framework/stage2/measurement_contract_v3.py`；
- `scripts/stage2_validate_measurement_rows_v3.py`；
- artifact registry 与 final-frontier validator。

新增统一入口规则：

```text
measured + formal calibration + numerical pass + approved automatic realization provenance
-> 可进入对应 metric 的 gold training pool

diagnostic/historical/hand-rewrite
-> 只能进入 diagnostic registry 或 historical-prior router
```

`approved automatic realization provenance` 至少包括：

```text
TVM: source_ir_automatic + source IR/trace/tuning DB digest
TRT: compiler_engine_automatic + source ONNX/build config/engine inspector digest
```

需要扩展 `measurement_contract_v3` 的 lowering/realization origin 枚举和校验，不能用 TVM 专属的 `source_ir_automatic` 条件排除 TRT gold，也不能因为 TRT 是 engine build 就绕过 source/build provenance。

负性能不是 rejection reason。TVM INT8 只要 pipeline 合法、数值和 AP 合格，即使 latency 慢于 FP16，也是有效 gold 训练行。

停止条件：同一 validator 能分别输出 `gold_training`、`final_frontier`、`feasibility_failure`、`historical_prior` 四个互斥视图，且 diagnostic 数据无法绕过门禁。

### 12.3 A1：能力扫描与 active manifest

在 `framework/capability_schema.py`、`framework/stage1/hardware_scan.py` 和现有 `stage2_smbo_qxs_entry_v2.py` 能力扫描基础上形成 v3 profile：

```text
compiler_profile_id
hardware capability digest
compiler/runtime fingerprint
supports_fp16_tensorcore
supports_int8_tensorcore
int8_precision_propagation_ratio
qdq_fold_ratio
reformat_count/rate
fusion coverage
build success rate
```

禁止将当前目标模型或候选配置的 `INT8/FP16 latency ratio`、energy ratio 写入 capability profile。若评估标准化 micro-probe，必须使用与 Pyramid/CoDriving 无关的固定合成图，并作为独立消融，不得默认启用。

active manifest 只枚举逻辑动作 `fp16/int8`。realizer/runner 绑定放在 measurement dispatch 表中，不拼进 `strategy_id`。

停止条件：在不读取 backend 名称的预测特征中，TVM/TRT profile 仍可通过数值 capability 向量区分；manifest 中不存在 `tvm_int8`、`trt_int8` 这类人工组合动作。

### 12.4 A2：旧 180 数据显式路由

原始 180 文件只读，按任务分流：

| 路由 | 使用范围 |
|---|---|
| `width_ap_prior` | width/FLOPs/AP 结构趋势和新 width 选点 |
| `disagreement_probe` | 找出 hand-rewrite prior 与自动后端差异大的补测点 |
| `historical_ablation` | `historical prior vs gold-only` 消融 |
| `backend_gold` | 禁止进入 |
| `final_frontier` | 禁止进入 |

不再使用模糊 sample weight 掩盖证据差异；每条旧行必须通过 `source_class` 和显式 router 决定用途。

停止条件：cost-model gold loader 在输入旧 180 文件时，对 backend latency/energy head 返回 0 条；width/AP prior loader 能保留合法结构字段。

### 12.5 A3：生成修订后的 Gold Cold-start 96 计划

新公式：

```text
2 models x 12 widths x 2 q_mode x 2 compiler profiles = 96
```

每个 `(model,width)` 形成 TVM/FP16、TVM/INT8、TRT/FP16、TRT/INT8 四条配对行。24 个 width-model 组固定拆为 20 组训练、4 组 locked holdout，即 `80 + 16`，同组不得跨集合。

建议新建 v3 planner，而不是继续让 `stage2_v2_gold_coldstart96.py` 的 8-combination mixed 设计承担双重语义：

```text
scripts/stage2_gold_coldstart96_plan_v3.py
framework/tests/test_stage2_gold_coldstart96_plan_v3.py
```

停止条件：manifest 恰好 96 行、24 个完整配对组、无 mixed 行、无 backend token 泄漏进 `strategy_id`，所有 holdout 组完全隔离。

### 12.6 A4：统一 cost-model bundle

建立单一 feature encoder 和多头模型接口：

```text
feasibility head
AP value head
latency value head
energy value head
uncertainty/disagreement head
optional rank head
```

输入由 genome、图分析和 capability 数值组成；禁止 backend name、具体 Conv ID、trust label、frontier membership。AP、latency 和 energy 可使用不同的合法训练视图，但共享 row/pipeline fingerprint。

先实现接口和 baseline regressor，不预先写死 LightGBM rank loss、AP residual 或某种树模型。模型选择在 locked holdout/replay 上比较后决定。

停止条件：bundle 可 `fit/predict/update/save/load`；保存 training SHA、feature schema SHA 和 profile digest；backend-blind 对照能够复现实验性错误排序。

### 12.7 A5：搜索、测量与回流闭环

统一流程：

```text
capability scan
-> active manifest
-> gold/prior routers
-> cost-model fit
-> NSGA-II candidate generation
-> uncertainty/disagreement acquisition
-> backend-specific real measurement dispatch
-> measurement_row_v3 validation
-> feedback update
-> trusted Pareto
```

必须包含两条论文对照：

1. `backend-blind`：移除 capability context，检验是否把 TRT 的 INT8 优势错误迁移到 TVM；
2. `unconditional INT8`：软硬件分离、所有后端默认 INT8，检验其在 TVM profile 上的减速。

停止条件：同一框架、同一逻辑 genome 能在 TVM profile 学到 FP16 更优、在 TRT profile 学到 INT8 更优；这个结果必须来自 cold-start 和回流，不允许硬编码 `if backend` 规则。

### 12.8 实施顺序与本阶段交付

严格顺序：

```text
A0 contract/router
-> A1 capability profile + active manifest
-> A2 historical-180 router
-> A3 cold-start96 v3 planner
-> A4 cost-model bundle
-> A5 NSGA-II + measurement feedback
-> backend-blind/unconditional-INT8 ablation
```

本阶段交付：

1. canonical schema、capability profile 和 active manifest；
2. 180 prior router 与 96 gold planner；
3. 可训练、更新和持久化的 cost-model bundle；
4. Pyramid/CoDriving 共用的搜索入口；
5. TVM/TRT 共用逻辑 genome、分后端测量的闭环 smoke；
6. backend-blind 与 unconditional-INT8 两项决定性对照。

本阶段不交付：新的 TVM INT8 kernel、默认激活的 mixed policy、未经 gold 门禁的 Pareto 或人工 backend-precision 规则。

## 13. Capability 泄漏反思与诊断验证正确收口

### 13.1 已发现的问题

2026-07-11 的首版 `capability_profiles_v3.json` 错误包含：

```text
int8_over_fp16_latency_ratio:
  TVM = 1.2924545
  TRT = 0.6987257
```

这些值不是静态硬件扫描结果，而是从 `results/codriving_source_conv_auto_20260711/final_backend_decision.json` 中读取已有 TVM top-2 region 和 TRT backbone 实测结果后计算得到。随后 diagnostic smoke 再使用同一性能关系验证“TVM 选 FP16、TRT 选 INT8”，构成目标泄漏和循环论证。

因此撤回以下口径：

> 旧 capability-conditioned smoke 已证明框架能从前置能力扫描自动学习不同后端的精度选择。

旧 smoke 只证明 cost-model 代码能够消费 `q_mode x capability` 交互项。`29.24%` 仍是此前 TVM region 的真实诊断结果，但不能作为 capability 输入，也不能作为新框架自动发现结论的证据。

### 13.2 能力信息分层

能力输入拆成三层，禁止混用：

| 层级 | 内容 | 是否可进入默认 capability | 代价 |
|---|---|---:|---:|
| S0 静态硬件/工具链 | SM、TensorCore 精度支持、alignment、编译器版本与 build capability | 是 | 近似为零 |
| S1 标准结构探针 | 固定合成图的 build success、TensorCore coverage、INT8 propagation、Q/DQ fold、reformat、fusion | 待消融决定 | 低 |
| S2 性能探针 | 固定合成图的 FP16/INT8 latency、energy | 默认否，仅实验候选 | 中到高 |

S0/S1/S2 均不得读取 Pyramid、CoDriving、96 点候选或任何历史最终性能结果。后端名称和 `dispatch_key` 只用于执行路由，不进入 predictor feature。

### 13.3 两条路线的公平比较

不预先决定采用纯静态扫描还是标准化 micro-probe，使用 locked cold-start/holdout 做三组递增消融：

| 组 | predictor 输入 | 目的 |
|---|---|---|
| C0 | genome + 图特征 + S0 | 无额外运行探针的基线 |
| C1 | C0 + S1 | 判断低成本编译结构证据是否改善跨 compiler profile 排序 |
| C2 | C1 + S2 | 判断性能探针的额外收益是否值得成本 |

旧历史性能比率版本只作为 `LEAKED-ORACLE` 负面对照，明确标记 invalid，不参与模型选择或论文主表。

比较指标：

1. locked holdout latency/energy 的 `MAE`、`MAPE` 和 pairwise ranking accuracy；
2. AP/feasibility 预测质量；
3. TVM/TRT 上 FP16-vs-INT8 选择正确率；
4. 搜索达到同等 hypervolume 所需真实测量数；
5. capability probe 的 GPU 时间、编译时间和失败率；
6. 探针形状变化后的稳定性，防止只对单一 shape 有效。

### 13.4 路线二准入门槛

S1 默认优先评估；S2 只有同时满足以下条件才进入正式框架：

1. 相对 C1，locked holdout precision-choice accuracy 至少提高 `5` 个百分点，或 latency ranking error 相对下降至少 `10%`；
2. 至少在 Pyramid/CoDriving 两个模型方向一致，不允许只改善一个模型；
3. 三套固定 probe shape 子集的结论稳定；
4. 单 compiler profile 的总 probe 时间不超过首轮 96 点实测预算的 `5%`；
5. probe 结果只描述标准合成图，不直接复用为目标模型 gold label。

若 S2 未达到门槛，则正式框架采用 C0 或 C1；不能因为 S2 更接近已有结论就保留。

### 13.5 无泄漏探针设计

S1 使用固定、模型无关的最小图族，每个 compiler profile 完全相同：

```text
P1: Conv stride1, aligned channels
P2: Conv stride2, aligned channels
P3: two-Conv chain, 检查 INT8 activation propagation
P4: Conv + residual add, 检查 scale/format boundary
P5: group Conv, 检查 group/layout buildability
P6: Q/DQ + Conv chain, 检查 Q/DQ folding 和 reformat
```

S2 若被执行，只对上述六类图各选择小/中两个固定 shape，测 FP16/INT8 latency；energy 仅在 latency 探针达到稳定性门槛后追加，避免一开始扩大成本。所有 shape 在看目标模型结果前冻结，并记录生成脚本 SHA、ONNX SHA、build config SHA 和 compiler fingerprint。

### 13.6 正确验收顺序

```text
封住历史性能特征入口
-> 生成 S0 bootstrap profile
-> 实现并运行 S1 结构探针
-> 用新 cold-start gold 做 C0/C1 locked-holdout 对照
-> 仅在 C1 仍不足时运行小规模 S2
-> 按 13.4 门槛决定最终 capability 版本
-> 重新进行 backend-blind 与 unconditional-INT8 消融
```

在 C0/C1/C2 至少完成 C0/C1 真实对照前，不再宣称 capability-conditioned 框架已实验收口。

### 13.8 S1 中性结构探针真实结果与 C0/C1 初步判断

2026-07-11 已在 H800 上完成六类中性图的 build-only 扫描。图由固定合成 shape 生成，与 Pyramid/CoDriving 无关；INT8 使用显式 Q/DQ ONNX，没有手写计算算子。TVM 使用 `0.20.dev1070+gb628d91fa`，TRT 使用 `<PRIVATE_HOST>`。本实验没有执行 latency/energy 测量。

产物：

- `results/s1_neutral_probes_v3_20260711/models/probe_manifest.json`；
- `results/s1_neutral_probes_v3_20260711/runs_final/tvm_records.json`；
- `results/s1_neutral_probes_v3_20260711/runs_final/trt_records.json`；
- `results/s1_neutral_probes_v3_20260711/c0_c1_replay_eval.json`。

六类图与 build 状态：

| Probe | 图结构 | TVM FP16/INT8 build | TRT FP16/INT8 build |
|---|---|---:|---:|
| P1 | stride-1 Conv | 2/2 | 2/2 |
| P2 | stride-2 Conv | 2/2 | 2/2 |
| P3 | two-Conv chain | 2/2 | 2/2 |
| P4 | Conv + residual add | 2/2 | 2/2 |
| P5 | group Conv | 2/2 | 2/2 |
| P6 | Conv + output Q/DQ boundary | 2/2 | 2/2 |

总 build：TVM `12/12`，TRT `12/12`。TVM 总 wall time `10.23 s`，TRT 总 wall time `44.15 s`，合计约 `54.38 s`。

INT8 Conv 结构结果：

| Profile | INT8 Conv / eligible Conv | propagation ratio | Q/DQ fold ratio |
|---|---:|---:|---:|
| TVM | `0/7` | `0.000` | `0.000` |
| TRT | `6/7` | `0.857` | `0.467` |

细节：TRT 的 P1/P2/P3/P4/P6 进入 INT8 convolution，P5 group Conv 没有进入 INT8；TVM 六类图均能 build，但 lowered TIR 中 Conv 本体保持 float，Q/DQ 被展开为独立量化/反量化 PrimFunc。这是编译结构证据，不是性能结论。

`reformat_rate` 和 `fusion_coverage` 的跨编译器提取语义仍不够一致，因此只保留为 inspector 审计信息，未进入 C1 predictor feature。正式 C1 当前只使用：

```text
build_success_rate
int8_precision_propagation_ratio
qdq_fold_ratio
```

使用旧 v2 CoDriving 表中 48 条具有 latency/energy 的 TVM/TRT FP16/整网 INT8 行做 replay，按 width 分组，32 行训练、16 行 holdout：

| 方案 | precision-choice accuracy | latency MAPE | energy MAPE |
|---|---:|---:|---:|
| C0 静态硬件能力 | `50%` | `329.98%` | `162.59%` |
| C1 + S1 结构能力 | `100%` | `124.17%` | `48.38%` |

20 个 width-grouped split 中，C1 的 precision-choice accuracy 均高于 C0，latency MAPE 也均低于 C0；平均 precision-choice accuracy 为 C0 `50%`、C1 `100%`。

严格结论：

1. **C0 静态能力在当前 TVM/TRT 两个已见 profile 上不足。** 两者共享 H800 静态硬件特征，模型无法只靠硬件支持位判断 INT8 是否有效。
2. **S1 结构探针是有用且低成本的 capability context。** 它在不读取目标性能结果的情况下暴露了 INT8 Conv propagation 和 Q/DQ folding 差异。
3. **当前结果不证明对未见 compiler profile 的泛化。** train/holdout 都包含 TVM/TRT，只隔离 width；C1 数值也承担 profile 区分作用。论文不能把 replay 写成跨后端泛化证据。
4. **当前 value MAPE 仍较高。** C1 已改善排序和精度选择，但不能据此宣称 latency/energy 数值模型完成。
5. **暂不启动 S2 性能探针。** 先用新版无泄漏 gold cold-start 和至少一个未见 compiler/hardware profile 验证 C1；只有 C1 在该验证中仍无法稳定排序，才按 13.4 门槛评估 S2。

因此本节点状态是：S1 build-only 扫描已真实闭合，C0 已被当前双 profile replay 否定，C1 已证明对已见 profile 有用；C1 的跨 profile 泛化与最终 value accuracy 尚未收口。

4. H800 上没有发现可直接替代的第三个、同时具备 FP16/INT8 gold 的自动 compiler profile。CUTLASS BYOC 只有不完整入口证据，不能伪装成第三 gold profile。

因此进一步验证保持两条合法队列：

```text

```

在 V1 或 V2 产生新证据前，不启动 S2，也不使用 H800 的旧 S1 profile 替代 4090 profile。
