## 0. 冷启动硬约束: H800 + TVM, 不是 TRT

本文件所有后续任务必须先遵守以下口径:

1. 当前 Stage2 LUT 的主加速路线是 **H800 + TVM / TVM VM**, 不是 TensorRT/TRT。除非另有明确新任务, 新的 latency、energy、AP measured LUT 行不得把 TRT 产物当作 H800 TVM 实测。
2. 本阶段面向 RSU 路测设备感知侧加速, 当前可以优先做 `backbone_only`、`backbone_subnet` 或真实 `subnet` scope 的量化和测量; 这不等价于全网络量化。
3. 当前默认不声称 full-network quantization。所有新行默认 `full_network_claim=false`; 只有新增 engine/layer 级证据证明端到端模块均纳入量化策略时, 才能改变该字段。
4. INT8 的本轮默认方法是 TVM-first: `quant_method=h800_tvm_int8_backbone_subnet_experimental`, `backend=h800_tvm`, `engine_kind=tvm_vm`。若 TVM INT8 当前只能做到 micro/stage0 probe, 必须写真实局部 `quant_scope` 并标记 no-claim/quarantine, 不能写成 backbone/subnet measured。
5. TRT FP16/INT8、TRT PTQ、TRT hybrid AP 等只能作为历史参考或对照证据, 必须标成 `trt_reference` 或 `historical_reference_only`; 不能进入 H800 TVM measured claim。

## 1. 本次策略调整

当前 Stage2 LUT 的首要目标调整为:

```text
先跑通 dense core width x quantization x latency/AP/energy 的全链路, 再逐个修正异常点。
```

原因:

1. original60 已有 H800 + TVM + backbone-only 的 FP16 latency/energy 首轮数据, 但搜索空间仍缺少量化维度。
2. 当前 AP 链路已经能产出真实 measured AP, 但 AP 异常点和 ONNX sanity 失败不应继续阻塞全链路 smoke。
3. 若只保留 FP16, 后续性能预测器无法学习 `precision/quantization` 对 latency、energy、AP 的影响。
4. 下一阶段应允许失败点进入 `gap/quarantine/quality_gate`, 保证队列继续推进。

因此, 下一阶段不是先把 `s0_024`、`s1_048`、`s2_160` 全部修干净, 而是把 `precision={fp32, fp16, int8}` 明确纳入 LUT schema、job plan、row validator、summary table 和实验队列。

## 3. 新增 LUT 维度和 row contract

### 3.0 量化方法口径

必须先明确: 当前不能声称已有“全网络 INT8 量化”。同时必须明确: **Stage2 当前主加速路线是 H800 + TVM / TVM VM, 不是 TensorRT/TRT**。

本阶段以 RSU 路测设备感知侧的 backbone/subnet 加速为主, 可以暂不考虑全网络量化。但所有新的 measured LUT 行必须优先使用 H800 TVM 路线; TRT 只能作为历史参考、AP hybrid 参考或对照证据, 不能作为本轮 H800 measured LUT 的默认后端。

现有证据分为几类:

| 证据来源 | scope | 方法 | 是否全网络量化 | 备注 |
|---|---|---|---|---|
| `multi_agent/data/stage2_lut_generation_v1/existing_h800_tvm/pyramid_h800_tvm_int8_scope_limited_ms.csv` | `stage0_conv_only` | H800 TVM TOPI/NCHWc/NCHW INT8 micro/stage0 | 否 | 明确写有 `NOT full-backbone` |
| `multi_agent/data/stage2_lut_generation_v1/existing_h800_tvm/codriving_h800_tvm_s0_and_int8_probes_ms.csv` | `s0_or_s1_micro_probe` / `stage0_standard_conv_micro` | H800 TVM INT8 micro probe | 否 | 只证明局部 INT8 kernel/probe |
| `scripts/phase2/t1_q_partner_build.py` | `backbone_subnet` | TensorRT FP16/INT8, calibrator=minmax | 否 | 4090 历史证据, 只作参考, 非当前 H800 TVM 主路径 |
| `scripts/phase2/plan5_phaseC_hybrid_eval.py` | PyTorch full model + TRT backbone 替换 | hybrid TRT real INT8 AP eval | 否 | 只作 AP/历史参考, 非当前 H800 TVM 主路径 |
| `scripts/phase1/m4_8_trt_build_bench.py` | ONNX engine scope 由输入 ONNX 决定 | TRT PTQ INT8, FP16 fallback | 不保证 | 工具存在, 但本轮不把 TRT 作为 measured LUT 默认后端 |
| dataset_v2 中 `pathA_forced_int8`、`pathB_head_int8`、`perstage_AP_v2` | 历史混合数据 | forced/mixed/per-stage | 否或需逐行确认 | 可作参考, 不作为 H800 TVM measured quant LUT 默认口径 |

因此下一阶段量化 LUT 必须写清楚 `quant_method` 和 `quant_scope`, 不能只写 `precision=int8`。

### 3.0.1 本轮默认量化方法

本轮 quant anchor smoke 的默认方法必须为 TVM-first:

| precision | quant_method | quant_scope | calibration | 说明 |
|---|---|---|---|---|
| `fp32` | `h800_tvm_relax_fp32` | `backbone_only` / `backbone_subnet` | `none` | TVM FP32 baseline, 若当前 TVM 脚本不支持则写 gap |
| `fp16` | `h800_tvm_relax_metaschedule_fp16` | `backbone_only` / `backbone_subnet` | `none` | 当前 H800 TVM 主链路 |
| `int8` | `h800_tvm_int8_backbone_subnet_experimental` | `backbone_only` / `backbone_subnet`; 若只到局部则写真实局部 scope | required for real W/A quant | TVM INT8 优先; 不得默认切换到 TRT |

解释:

1. 本轮 H800 measured LUT 的默认后端是 `h800_tvm`, 不是 `trt_int8` 或 `TensorRT`。
2. TVM INT8 若当前只能做到 `stage0_conv_only`、`s0_or_s1_micro_probe` 或 `stage0_standard_conv_micro`, 必须把 `quant_scope` 写成对应局部 scope, 不得写成 `backbone_only`、`backbone_subnet` 或 `full_network` measured。
3. 若 H800 TVM full-backbone/subnet INT8 暂时不可用, 对应 `(label, int8)` 行写 `tvm_int8_backbone_subnet_not_ready` 或更具体的 gap/quarantine reason, 不得自动用 TRT 结果补 measured LUT。
4. TRT PTQ minmax、TRT FP16、TRT INT8、forced-all-int8、per-stage mixed、w-only、entropy 等历史路线可以保留为 reference/import evidence, 但必须写 `backend=trt_reference` 或 `measurement_source=historical_reference_only`, 不进入 H800 TVM measured claim。
5. INT8 的校准方法要随 TVM 实现写清楚; 若只是随机/合成 int8 micro kernel latency, 不能写成真实 AP/energy/latency 的 W+A quant measured row。

### 3.0.2 全网络量化的状态

全网络量化在本阶段定义为:

```text
端到端模型所有可量化主干、融合、head/decoder 计算模块均进入明确量化策略, 并且有 engine/layer 级证据说明哪些层 INT8、哪些层 fallback。
```

当前状态:

1. 当前 Stage2 H800 measured LUT 主体不是全网络量化, 而是 H800 + TVM + backbone-only 的 FP16 数据。
2. 当前 H800 INT8 证据不是 full-backbone, 更不是 end-to-end full-network。
3. 当前 AP hybrid 证据是 PyTorch full model + TRT backbone 替换, 不是全网络 INT8, 也不是当前 H800 TVM 主路径。
4. 因此下一阶段不得写 `quant_scope=full_network` 或 `claim_status=full_network_int8_measured`, 除非新增 engine/layer 级证据。

### 3.0.3 新增必要字段

量化相关 row 必须补充:

| 字段 | 示例 | 用途 |
|---|---|---|
| `quant_method` | `h800_tvm_int8_backbone_subnet_experimental` | 区分 TVM/TRT、minmax/entropy/w-only/mixed/forced |
| `quant_scope` | `backbone_subnet` | 区分 micro/stage0/backbone/end2end/full_network |
| `calibrator` | `tvm_quant_calibration_manifest` 或 `none_for_micro_probe` | INT8 校准方法或局部 probe 说明 |
| `calibration_inputs` | `spatial_features,t_ego` 或当前 TVM 输入名 | 多输入校准覆盖 |
| `fallback_policy` | `tvm_int8_lowering_policy` 或 `not_applicable_micro_probe` | 说明 TVM lowering/fallback 口径 |
| `layer_precision_summary` | `unknown` 或 JSON 摘要 | 后续从 TVM module/TIR/op inventory 补充 |
| `full_network_claim` | `false` | 防止误读为全网络量化 |

没有 layer/op 级统计时, `layer_precision_summary` 写 `unknown_pending_tvm_inventory`, 但 `full_network_claim` 必须为 `false`。

### 3.1 主键扩展

下一阶段 LUT 行必须从仅围绕 width 的口径扩展为:

```text

```

字段含义:

| 字段 | 要求 |
|---|---|
| `precision` | 必须显式写 `fp32`、`fp16` 或 `int8` |
| `quant_scheme` | FP32/FP16 写 `none` 或 `fp16_cast`; INT8 写具体 calibration/quantization 方案 |
| `quant_method` | 本轮默认 INT8 写 `h800_tvm_int8_backbone_subnet_experimental`; TRT 只能写 reference |
| `quant_scope` | 本轮默认以 TVM 实际 scope 为准; 不得把 micro/stage0 写成 backbone/full_network |
| `schedule_profile` | 区分 `default`、`metaschedule_tuned`、历史 high-budget DB 或其他 profile |
| `tune_budget` | 当前 original60 shallow DB 应记录约 `32`; 历史 MS-1000 证据不得混写 |
| `calibration_source` | INT8 必填, 没有 calibration source 时写 gap, 不写 measured INT8 |
| `calibration_digest` | 有 cache 或 calibration manifest 时写 digest; 没有则写 `unknown` 或 gap reason |
| `calibrator` | TVM INT8 若有 calibration manifest 必须记录; 没有则写 gap 或 `none_for_micro_probe` |
| `calibration_inputs` | 多输入 TVM module 必须列出所有 calibration input |
| `fallback_policy` | 写 TVM lowering/fallback 口径; TRT fallback 不属于本轮主路径 |
| `layer_precision_summary` | 有 TVM module/TIR/op inventory 时写层级统计; 没有时写 `unknown_pending_tvm_inventory` |
| `full_network_claim` | 当前默认 `false` |
| `engine_kind` | 主路径为 `tvm_vm`; TRT 只能标 `trt_reference` |
| `engine_digest` | 有 engine/compiled artifact 时写 digest; 大文件不入 git |
| `measurement_source` | 如 `true_measurement`, `true_eval`, `true_import`, `weight_identity_transfer`, `no_claim` |
| `claim_status` | 控制是否可用于 measured LUT 或 paper claim |
| `quality_gate_status` | 记录 first seed、quarantine、outlier、calibration missing 等 |

### 3.2 AP 规则

AP 仍遵守硬规则:

1. 只能写真实 `true_eval`、`true_import` 或明确 `weight_identity_transfer`。
2. 禁止把 predicted/model-fit/interpolated AP 写成 measured AP。
3. FP32/FP16/INT8 的 AP 不得默认互相复制。
4. 若当前 AP evaluator 不能评测某个 precision/engine, 必须写 `no_claim_ap_eval_backend_missing`。
5. 若 INT8 缺 calibration、engine build 或 eval 失败, 写对应 quarantine/no-claim, 不阻塞后续配置。

### 3.3 latency/energy 规则

latency/energy 仍遵守 H800 runbook:

1. latency/energy job 启动前必须通过目标 GPU idle gate。
2. 必须保存 `nvidia-smi` 和 `pmon` preflight。
3. GPU 非空闲、显存异常、已有 compute process 时写 `preflight_blocked`, 不写 measured row。
4. CUDA illegal memory access、engine build 失败、energy 读数异常时写 quarantine, 不终止全队列。

## 5. 分阶段计划

### Phase Q0: schema 和生成器补丁

目标: 先让量化维度进入所有核心表, 避免实验结果落盘后无法区分 FP32/FP16/INT8。

任务:

1. 扩展 latency row schema 和 validator:
   - 增加 `precision`, `quant_scheme`, `engine_kind`, `engine_digest`, `tune_budget`, `schedule_profile`。
2. 扩展 energy row schema 和 validator:
   - 增加 `precision`, `quant_scheme`, `engine_kind`, `calibration_source`, `quality_gate_status`。
3. 扩展 AP row/source map/gap report:
   - 增加 `precision`, `quant_scheme`, `ap_eval_backend`, `measurement_source`, `claim_status`, `quality_gate_status`。
4. 扩展 job plan generator:
   - 支持按 `(label, precision)` 生成 latency/AP/energy 任务。
5. 扩展三指标 summary exporter:
   - 表格主键从 `label` 升级为 `(label, width, precision, quant_scheme, schedule_profile)`。
6. 增加 failure reason 枚举, 至少包含:
   - `quant_precision_not_supported`
   - `quant_scope_not_full_network`
   - `tvm_int8_backbone_subnet_not_ready`
   - `tvm_int8_scope_limited_micro_only`
   - `trt_reference_not_h800_tvm_measured`
   - `int8_calibration_missing`
   - `int8_engine_build_failed`
   - `int8_layer_precision_summary_missing`
   - `ap_eval_backend_missing`
   - `no_claim_missing_true_source`
   - `onnx_sanity_failed`
   - `latency_preflight_blocked`
   - `energy_preflight_blocked`
   - `cuda_illegal_memory_access`
   - `energy_zero_or_unstable`
   - `trend_anomaly_pending_repeat`

### Phase Q1: anchor quant smoke

目标: 在 8 个 anchor 上跑通 `fp32/fp16/int8` 的三轴状态链路。

执行规则:

1. latency:
   - 优先跑 H800 + TVM + backbone-only。
   - FP16 可复用当前链路, 但必须在新表中显式写 `precision=fp16`。
   - INT8 必须优先尝试 H800 TVM backbone/subnet 路线。
   - H800 TVM INT8 若当前只支持 micro/stage0, 只写 `quant_scope=stage0_conv_only` 或对应真实 scope, 并标记 `tvm_int8_scope_limited_micro_only`。
   - FP32/INT8 若当前 TVM engine/module 不支持, 写 gap/quarantine, 不停止任务; 不用 TRT 替代 H800 TVM measured row。
2. energy:
   - 跟随 latency 成功行。
   - 同一 `(label, precision, schedule_profile)` 写对应 energy。
   - energy 为 0 或明显异常时写 `energy_zero_or_unstable`, 不强行 claim。
3. AP:
   - FP16 继续使用已验证 AP 链路。
   - FP32 优先使用真实 PyTorch/ONNX eval; 无合法路径则写 no-claim。
   - INT8 必须有 TVM quant module 或 TVM INT8 backbone/subnet 替换路径和实际 eval 路径; 缺任一环节写 no-claim/quarantine。
   - INT8 AP 若只能采用 PyTorch full model + TRT backbone 替换, 必须写 `measurement_source=historical_reference_only` 或 `trt_reference`, 不得写成 H800 TVM measured AP。
4. 所有失败:
   - 写 job_state。
   - 写 gap/quarantine。
   - 写 summary 状态。
   - 继续后续配置。

### Phase Q2: original60 quant coverage 扩展

目标: anchor quant smoke 通过后, 把 original60 的 FP32/INT8 维度补起来。

优先级:

1. latency coverage first:
   - original60 已有 FP16; 先补 FP32 和 INT8 latency state rows。
   - `s2_096`、`lhc_17` 仍保持 latency quarantine, 不因它们阻塞整体。
2. energy follower:
   - 对 latency measured 的 `(label, precision)` 补 energy。
   - `frontier_25`、`frontier_26` 维持已知 energy quarantine, 可单点复测。
3. AP no-claim first:
   - 没有合法 source/eval backend 的 precision 先写 no-claim。
   - 有合法 source 的点再进入 AP eval queue。
4. summary:
   - 输出 human-readable 三指标总表。
   - 输出机器可读 JSON/CSV。

### Phase Q3: 异常修复队列

目标: 全链路跑通后, 再逐类修正异常。

优先处理:

1. `s0_024`、`s1_048` AP second seed/repeat。
2. `s2_160` ONNX sanity/export fail。
3. INT8 calibration 缺失或不稳定。
4. INT8 engine build/eval 失败。
5. TVM INT8 module/TIR/op precision summary 缺失。
6. full-network quantization 是否需要单独立项。
7. energy 为 0 或读数不可信。
8. original60 shallow DB 的 high-budget retune/golden anchor gate。
