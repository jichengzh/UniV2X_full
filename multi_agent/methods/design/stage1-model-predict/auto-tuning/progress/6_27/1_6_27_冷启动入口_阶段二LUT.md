## 4. GPU 和实测规则

latency/energy:

1. 必须在目标 GPU 完全空闲或通过 idle gate 后运行。
2. 启动前记录 `nvidia-smi` 和 `pmon`。
3. 目标 GPU compute process 非空、util 明显非空闲、显存异常占用时, 该 GPU 不可用于 latency/energy。
4. 失败写 job state/quarantine, 不要静默跳过, 不要因单点失败终止全队列。

AP:

1. AP finetune/eval 不要求 GPU 完全空闲, 但必须记录显存和进程状态。
2. AP 只能写真实 `true_eval`、`true_import` 或明确 `weight_identity_transfer`。
3. 禁止把 predicted/model-fit/interpolated AP 写成 measured AP。
4. 训练、ONNX、TRT 或 eval 任一步失败时, 当前配置写 quarantine/no-claim, 不写 measured AP。

### 4.1 量化与后端硬规则

清空上下文后必须先记住:

1. 当前 Stage2 H800 LUT 的主加速路线是 **H800 + TVM / TVM VM**, 不是 TensorRT/TRT。
2. 本阶段面向 RSU 路测设备感知侧加速, 可以优先做 `backbone_only`、`backbone_subnet` 或真实 `subnet` scope 的量化和测量; 这不等价于全网络量化。
3. 新的 measured LUT 行默认 `backend=h800_tvm`, `engine_kind=tvm_vm`; INT8 默认 `quant_method=h800_tvm_int8_backbone_subnet_experimental`。
4. 当前默认不声明全网络量化, 新行默认 `full_network_claim=false`。不得把 backbone/subnet 或 micro/stage0 probe 写成 `full_network` measured。
5. 如果 H800 TVM INT8 只能做到 `stage0_conv_only`、`s0_or_s1_micro_probe` 或其他局部 probe, 必须写真实 `quant_scope` 和 no-claim/quarantine reason, 不得用 TRT 结果补成 H800 TVM measured。
6. TRT FP16/INT8、TRT PTQ、TRT hybrid AP 只能作为历史 reference 或对照证据; 必须写 `trt_reference` 或 `historical_reference_only`, 不能进入 H800 TVM measured claim。
