## 3. INT8 为什么速度不敏感

目前能写的解释是: INT8 弱加速与当前 TVM VM INT8 route 的 QDQ / float32-heavy lowering 一致, 但还不能写成完整因果闭环。

### 3.1 直接现象

| label | FP32 ms | true-FP16 ms | INT8 ms | direct observation |
|---|---:|---:|---:|---|
| `base` | 6.208528 | 53.277002 | 59.078584 | base 有强烈 schedule/route 不公平风险, 不能直接归因 |
| `s0_024` | 39.522546 | 37.734585 | 41.040342 | FP16 略快, INT8 反而略慢 |
| `s1_048` | 44.503228 | 42.327026 | 46.150869 | FP16 略快, INT8 反而略慢 |

### 3.2 支持“INT8 没有干净命中 native INT8 kernel”的证据

INT8 route evidence:

```text
raw/int8_route/20260627_083401/{base,s0_024,s1_048}/layer_precision_summary.json
raw/int8_route/20260627_083401/{base,s0_024,s1_048}/quant_recipe.json
raw/int8_route/20260627_083401/{base,s0_024,s1_048}/calibration_manifest.json
```

Root-cause profile evidence:

```text
raw/quant_speed_root_cause/20260627_quant_speed_profile_v1/{base,s0_024,s1_048}/int8/tvm_operator_inventory.json
exports/quant_speed_manual_lowered_evidence_int8_qdq_v1.json
```

关键观察:

- INT8 ONNX 是 QDQ-heavy: `QuantizeLinear` / `DequantizeLinear` 节点很多。
- INT8 TVM lowered inventory 中 `float32` token 远多于 `int8` token。
- manual lowered evidence 中出现 `dequantize*`、`fused_conv*_quantize*_dequantize*` 函数名, buffer 里能看到 int8 输入与 float32 dequantized / scale buffer 混用。
- 这说明当前 INT8 path 更像“int8 artifact + QDQ 转换 + float32-heavy lowered route”, 不是干净的端到端 int8 kernel coverage。

### 3.3 为什么还不能算完整解释

H800 per-op/equiv retry:

```text
raw/quant_speed_root_cause/20260627_per_op_or_equiv_h800_light_v5/run_manifest.json
raw/quant_speed_root_cause/20260627_per_op_or_equiv_h800_light_v5/base/fp32/tvm_equiv_operator_timing.json
```

结果:

- status: `partial`
- success: `1`
- failed: `8`
- 唯一成功 cell: `base/fp32`
- `base/fp32` artifact p50: `6.212230 ms`
- selected equivalent operator p50 sum: `0.154017 ms`
- coverage ratio: `0.024793`

因此 v5 只证明 helper 在 H800 上能跑通一小部分 sampled equivalent timing, 不能量化 INT8 的 QDQ / dequantize / layout / VM overhead 到底占多少。其余 8 个 cell 失败在 direct PrimFunc microbench 的 memory verification / host-memory binding 阶段。

当前根因结论必须保持:

```text
partial: INT8 QDQ/float32-heavy lowering is a supported candidate contributor, not causal closure.
```
