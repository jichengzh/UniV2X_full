## 2. 异常点复核

### 2.1 异常筛选规则

按三精度 AP70 横向对比筛选:

- 强异常: 同一 label 下某个 precision AP70 与 FP32 差距大于 0.05，或 AP70 接近 0。
- 边界低值: 三精度同时低，且 INT8 相比 FP32/FP16 有小幅退化。

筛选结果:

| label | 现象 | 本轮处理 |
|---|---|---|
| `frontier_01` | FP32 AP70 正常，FP16/INT8 AP70 为 0 | 复测 INT8 full-val，确认仍为 0，且为 empty predictions all samples |
| `frontier_31` | FP32/FP16/INT8 都偏低，INT8 略低 | 复测 INT8 full-val，复核值与旧值基本一致 |

### 3.4 5.4 Evidence registry 未完全产品化

- 每类 metric 的 row 文件。

- source/provenance/quality gate/status 字段。

仍未完全产品化:

- `Stage2EvidenceRegistry` 还没有成为所有 runner 的唯一写入口。

- 5.4 之前的数据覆盖缺口已经清理。
- 5.4 的工程产品化缺口没有完全清理，但不再阻塞 5.5 论文实验链路启动；它应作为 paper artifact freeze 和 reproducibility appendix 的 P0 hardening。

## 4. 5.5 论文实验链路完全收口计划

### P0: 冻结 paper evidence pack

目标: 固定论文使用的数据版本，避免继续补点导致表格漂移。

产物:

```text
exports/original60_quant_three_metric_summary_latest.{json,csv,md}
rows/*.jsonl
exports/original60_quant_trusted_freeze_latest.{json,md}

```

必须完成:

1. 运行 summary validator 并保存 PASS 输出。
2. 生成 anomaly review，至少包含 `frontier_01`、`frontier_31`。
3. 把 `frontier_01` 标成 `blocked_empty_predictions_fullval`，不作为普通 measured AP gain/loss 样本。
4. 明确 claim scope: H800 + TVM + Pyramid + backbone/subnet/dense-core，不外推 full-network end-to-end。

### P1: 主结果表 E1

目标: 形成论文主表，回答三精度下速度、能耗、AP 的 trade-off。

表格维度:

| 维度 | 内容 |
|---|---|
| model | Pyramid LiDAR |
| hardware | H800 |
| backend | TVM |
| scope | backbone/subnet/dense-core |
| precision | FP32, FP16 rewritten, native INT8 |
| metrics | latency_ms, energy_j_per_inference, AP70, AP50, AP30 |

必须输出:

1. 每个 precision 的 median/mean/min/max。
2. Pareto top-K: 以 AP70 下限和 latency/energy 排序。
3. 排除/包含 `frontier_01` 两版统计，说明异常点对均值的影响。
4. 不使用 4090/TRT dataset_v2 作为 H800 主结论，只能放历史背景或附录。

### P2: Joint vs single-axis/serial/noS 消融

目标: 回答 joint codesign 是否优于单轴或串行搜索。

需要构建的组:

```text
joint: 当前 original60 中可代表联合优化的 Pareto/frontier 点
P-only: 只改宽度/剪枝，不改 Q/S
Q-only: 同一结构下 FP32/FP16/INT8 横向
S-only/noS: 使用已有 search space/stage1 manifest 构造 noS 或固定 S 的对照
serial: P -> Q -> S 或 Q -> P 的排序策略
random: 在 original60 或扩展 LUT 中随机采样同预算点
```

最低可接受版本:

- 使用 original60 当前 60 点做 post-hoc 消融。
- 如果 noS/serial 原始点不足，先标为 estimated/proxy，不进入主 claim，只进分析图或附录。

### P3: 机制实验 E3

目标: 解释为什么 joint search 有意义，而不是只报告表格。

必须完成:

1. Rank-flip 图: latency rank、energy rank、AP rank 在 FP32/FP16/INT8 下是否改变。
2. P(IC_BN)-hub 或结构敏感性图: 哪些 width/stage 配置容易产生 AP 退化。
3. 异常点机制:
   - `frontier_01`: full-val empty predictions anomaly。
   - `frontier_31`: 低 AP 可复现边界点。
4. 量化维度机制: INT8 不是全网络量化；当前是 TVM native INT8 backbone/subnet + PyTorch head/postprocess AP eval。

### P4: Cost model / LUT 质量 E6

目标: 证明 LUT 可以作为性能预测器基础，而不是只是一张测量表。

需要输出:

1. LUT coverage matrix: 60 labels x 3 precision x 3 metric。
2. 预测任务切分:
   - latency predictor
   - energy predictor
   - AP predictor
3. 留一/分层交叉验证:
   - MAE/RMSE
   - Spearman rank
   - top-K hit rate
4. outlier-aware 版本:
   - include all
   - exclude `frontier_01`
   - robust loss / rank-only

### P5: 搜索成本 E5

目标: 说明产品化 LUT/worker 相比盲测能减少多少测量成本。

指标:

```text
真实测量次数
失败/blocked 次数
AP full-val 平均耗时
latency/energy 单点耗时
生成一个 60 点三精度表的 wall-clock 估算
top-K 收敛曲线
```

必须包含失败成本:

- checkpoint 命名不被 worker 接受。
- softlink 在 4090 本地不可用。
- full-val gate blocked。
- AP row allowed 与 measured summary 的区别。

### P6: Full-model/Amdahl 边界 E8

目标: 防止把 backbone/subnet 加速误写成全模型端到端加速。

必须完成:

1. 列出当前加速 scope。
2. 给出 Amdahl 分解或保守估计。
3. 如果没有 full-network 实测，不写 full-network speedup claim。
4. 如果要写端到端，需要单独启动 full-network profiling，不复用 dense-core latency。

### P7: Cross-model / Cross-hardware E4/E7

当前建议:

- 主论文核心先以 Pyramid + H800 + TVM 收口。
- CoDriving/H800 或 4090/TRT 只作为补充证据，不能混入主表。
- 若时间不足，cross-model/cross-hardware 放入 limitation/future work，并解释已经保留 search space/registry 接口。
