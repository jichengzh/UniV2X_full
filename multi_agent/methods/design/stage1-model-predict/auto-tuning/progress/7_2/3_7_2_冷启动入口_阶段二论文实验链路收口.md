## 4. 下一阶段执行计划

### P0: 固定训练数据与证据口径

目标: 把 original60 三精度总表冻结为 cost model 的训练/校准数据，而不是把它当成最终 Pareto 结果。

必须做:

1. 运行 validator，保存 PASS 输出。
2. 生成 cost-model training freeze:

```text
exports/original60_cost_model_training_freeze_latest.json
exports/original60_cost_model_training_freeze_latest.md
```

3. 生成 anomaly/exclusion review:

```text
exports/original60_quant_anomaly_review_20260702.json
exports/original60_quant_anomaly_review_20260702.md
```

必须包含:

- `frontier_01`: blocked empty predictions all samples。
- `frontier_31`: recheck AP70=0.5642041439038464。

训练数据使用规则:

- original60 用于训练、校准、验证 cost model。
- original60 内部可以做描述性统计和异常分析。
- 不从 original60 内直接宣布最终 Pareto 前沿。
- `frontier_01` 必须在训练中有明确策略: exclude、downweight、单独 anomaly class，三者择一并记录。

### P1: Cost model 训练

目标: 训练外层多指标 cost model，用于预测软件配置 $x$ 经条件化调度后的 AP、latency、energy 表现。

必须完成:

1. 构建训练表:

```text
cost_model/train/original60_training_table_latest.{csv,json}
```

2. 明确 feature schema:

```text
cost_model/schema/stage2_cost_model_feature_schema_v1.md
cost_model/schema/stage2_cost_model_feature_schema_v1.json
```

至少包含:

- 软件配置特征: width、precision、quant policy、label/source family。
- 硬件反馈特征: backend、schedule policy、route type、tuned/default、measured/proxy status。
- 证据质量特征: measurement_source、quality_gate_status、anomaly flag。

3. 训练三个预测头:

```text
AP predictor
latency predictor
energy predictor
```

4. 输出训练报告:

```text
cost_model/reports/stage2_cost_model_training_report_latest.md
cost_model/reports/stage2_cost_model_metrics_latest.json
```

最低指标:

- MAE/RMSE。
- Spearman/Kendall。
- top-K hit rate。
- include all / exclude `frontier_01` 两版。

### P2: 完整搜索链路 smoke

目标: 验证“冷启动 -> 候选生成 -> cost model 预测 -> 高质量点选择 -> 实测 -> 证据回流 -> 重训”的完整链路能跑通。

必须完成一轮小规模闭环:

1. 从完整搜索空间生成候选池，不限制在 original60 内。
2. 用 cost model 预测 AP/latency/energy。
3. 选择一小批高价值候选:

```text
K=5~10
```

4. 对这些候选生成工程产物。
5. 在 H800 上实测 latency/AP/energy；失败点写 blocker，不填 measured。
6. 将新增证据写入 row/registry。
7. 刷新训练集并重训 cost model。

smoke 产物:

```text
search_runs/stage2_search_smoke_*/candidate_pool.csv
search_runs/stage2_search_smoke_*/predictions.csv
search_runs/stage2_search_smoke_*/selected_for_measurement.csv
search_runs/stage2_search_smoke_*/measurement_rows/
search_runs/stage2_search_smoke_*/evidence_update_report.md
search_runs/stage2_search_smoke_*/retrain_report.md
```

### P3: 扩展搜索空间探索

目标: 在完整搜索空间中持续探索，而不是停留在 original60。

执行方式:

1. 每轮生成大候选池:

```text
N=500~5000 candidates
```

2. cost model 批量预测。
3. 按 acquisition 选择下一批实测点:

```text
Pareto-near score
uncertainty score
coverage expansion score
anomaly avoidance / anomaly probing score
```

4. 每轮实测预算建议:

```text
latency: 20~50 points
AP: 5~15 points
energy: 10~30 points
```

具体数量按 GPU 空闲情况调整。latency/energy 仍遵守一张 GPU 一个进程。

### P4: 高质量候选实测与证据回流

目标: 把 cost model 预测出的高质量候选转化为可声明的 measured evidence。

每个被选候选必须经过:

1. buildability check。
2. latency measurement。
3. energy measurement。
4. AP full-val 或约定阶段 AP eval。
5. row import。
6. summary/registry update。
7. cost model retrain。

质量门控:

- AP 不允许用 no_claim 或 smoke 伪装 measured。
- latency 单位统一 ms。
- energy 方法必须与 FP32/FP16/INT8 既有口径一致。
- blocked/proxy/failed 必须单独记录。

### P5: 收敛与最优候选确认

目标: 通过多轮搜索闭环得到最终候选，而不是从 original60 里直接挑。

需要输出:

```text
search_runs/stage2_search_main_*/convergence_curve.csv
search_runs/stage2_search_main_*/measured_candidate_table.csv
search_runs/stage2_search_main_*/final_candidate_shortlist.csv
```

必须包含:

- 每轮候选池大小。
- 每轮实测点数量。
- 每轮新增最优值或 Pareto 改善。
- cost model 预测误差随轮次变化。
- 最终 shortlist 的真实 AP/latency/energy。
