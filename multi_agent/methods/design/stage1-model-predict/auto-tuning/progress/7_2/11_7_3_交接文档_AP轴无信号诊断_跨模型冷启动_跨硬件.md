## §0 接手须知(自包含)

**框架一句话**:输入(网络 + 硬件)→ 输出该硬件 measured Pareto 前沿(AP × latency × energy)。
嵌套双环:外环 NSGA/精确非支配(软件配置 = width 剪枝 × precision 量化),内环 TVM schedule。
当前坐标:Pyramid(LiDAR 协同检测)+ H800,latency_kind = pyramid_backbone subnet。

**本轮(10_7_3)已闭合的**:
1. 三精度 measure_config 统一接口(fp32 FFMA / fp16 WMMA / int8_tc MMA);口径复现通过。
2. 精度轴**两层不对等已修**:① shape(fp16 从 256² 统一到 128×256);② 优化层级(int8 从
   naive SIMT 升级到 im2col+MMA 张量核,60/60 build+tensorize)。
3. cost model 在 fair-axis 重训(lat spearman 0.991)。
4. 三臂消融 fair-axis:**joint>serial 稳健(p=4.9e-4)**,且证明其主因是 argmin drift 而非
   dp4a buildability 墙(int8_tc 无此墙)。

**本轮暴露的真问题(本文档主题)**:三臂用的 AP 是**代理**(naive-int8 finetune 值 + 0.008

## §1 问题一(★最高优先级):AP 轴没有信号,残差建模也救不了

### 1.1 现象与已知事实(勿再被误导)
- **base 全模型 AP50 = 0.791**(DAIR val)—— 任务天花板本就低。
- backbone 剪枝:AP50 0.791→0.757(span 0.034),**AP70 0.631→0.530(span 0.101 = 信号最强)**;
  但 span 相对管线噪声(~0.001)虽可分辨,对搜索而言太弱。
- cliff 实验(prune 到 pyramid_backbone 0.36M ≈ base 的 -90%,wpg=4):AP50 仍稳在 0.74–0.75,
  **可达范围内无精度悬崖**。
- V2X-ViT 原始剪枝(未 finetune)AP50 0.710→0.025 **真崩**,finetune 后恢复。
- **int8 的 AP 从未真测**:naive int8 用 simulated fake-quant(不可信),int8_tc 用 dummy scale
  (纯延迟)。所以"精度轴"里 int8 那一档目前是假的。
- finetune 预算:≤31 epoch / ≤18 anchors。

### 1.2 三个候选解释(用户提出)+ 各自的可判别诊断
这三个解释**不是互斥的**,需要一个能把它们分开的实验。核心判别实验见 §1.3。

**假设 A — 评价方法是否公平?**
- 疑点:① DAIR val 是否饱和/太易(base 0.791 已顶到任务上界,压缩再差也测不出);② 指标选择
  (AP50 最平,AP70 信号最强,是否该用 AP@0.8 / 按距离·遮挡·类别分层的 mAP?);③ **int8 的 AP
  是假的**(fake-quant / dummy),根本没测真量化损失 —— 这本身就是"不公平"的最大来源。
- 诊断:(a) 出 AP@{0.5,0.7,0.8} + 按 range/occlusion/class 分层曲线,看高 IoU / 难 bin 是否有
  更大 span;(b) **给 int8_tc 接真量化(真 scale 校准 + 真 activation),测真 int8 AP**(接
  `stage2_h800_native_int8_real_activation_bridge`),这是 Problem3(旧编号)也是这里的前置。

**假设 B — 量化/剪枝方法太"高级",对这网络真能无损压缩?**
- 疑点:模型对 DAIR **严重过参数化**(base 0.791 = 任务上界,不是模型上界;pyramid_backbone 占
  参数 68.9% 但砍到 -90% AP 只掉 0.04)。即压缩近无损**是真的**,因为有大量冗余 slack。
- 诊断:(a) 换**无 slack 的载体**——更难数据集 / 更紧凑模型 / 更高 IoU 任务,让 base 本身不饱和,
  压缩才有代价;(b) 在 Pyramid 上把压缩推到**真崩**(极端 bit:int4/二值;极端剪枝直到 AP 崩)
  来定位悬崖,把退化 Pareto 变真曲线。**注意区分**:剪枝在可达区无损 ≠ 真 int8 无损(未测)。

**假设 C — finetune 次数太多,过拟合把损失洗掉了?**
- 疑点:≤31 epoch 是否让压缩模型在 val 上过拟合,人为抹平了本应存在的 AP 损失?
- 诊断:出 **AP-vs-finetune-epoch 曲线** + **train/val gap** + **zero-shot(0 finetune)AP**。

**假设 D(★用户新增)— 换评价体系:接入 V2Xverse 闭环驾驶评价?**
- 动机:开环 AP 是**单帧检测质量**,对过参数化网络饱和;但真正关心的是**下游驾驶**。闭环
  (V2Xverse CARLA)测 driving score / collision rate / route completion,是**任务级、安全敏感**
  的指标 —— 小的 AP 退化(漏检几个框)在闭环里可能被放大成碰撞/偏航,信号更强;反之若闭环也
  平,则**坐实过参数化对本任务真无损**(假设 B 的最强证据)。无论哪种结果都比开环 AP 更有说服力。
- **已有基础设施(勿重造)**:① V2Xverse + H800 torch2 闭环双进程 IPC 已跑通(`PROGRESS_h800_sim
  _smoke_v1`);② **AP-knob→DS 曲线已标定**(丢检测框模拟精度损失:drop0→0.9 = AP50 0.84→0.27,
  DS 单调退化、盲驾崩)—— 证明**闭环对 AP 变化是有信号的**,只是没在真压缩模型上试过;③ 感知
  延迟 τ_perc 有单调退化曲线(τ_ego 为 null)。
- 关键未知:真压缩(int8_tc + 剪枝)的 AP 变化(span 0.04–0.1)是否**足够大**到移动闭环 DS?
  这正是 §1.3.D 最小探针要回答的。
- 注意:闭环把**延迟/能耗/AP 三轴一次性汇成一个任务指标**(慢的模型帧对齐滞后也伤 DS),这对
  框架是加分(单一可优化目标),但也意味着要控制变量(固定路测场景/seed,隔离算力,见
  `HANDOFF_h800_closedloop` ambient traffic 非确定性坑)。

### 1.3 ★核心判别实验(一次实验分开 A/B/C)
固定一个压缩配置(如 int8_tc 全网 + backbone 中等剪枝),做:
1. **zero-shot AP**(0 epoch,权重直接压缩):测原始损伤 Δ0。
2. **AP-vs-epoch 曲线**(0,1,2,4,8,16,31 epoch),同时记 train/val gap。
3. 判读:
   - 若 **Δ0 就很小**(zero-shot 已近无损)→ **假设 B**(真过参数化/无损),AP 轴天然弱。
   - 若 **Δ0 大但少数 epoch 快速恢复且 train/val gap 不涨** → **假设 B**(恢复是真的,冗余撑底)。
   - 若 **恢复需很多 epoch 且 train/val gap 持续扩大** → **假设 C**(finetune 过拟合掩盖了真损失);
     对策 = 减 epoch / 早停 / 用 hold-out test 而非 finetune val 评 AP。
   - 若 **连 fp32 base zero-shot 都已在 val 顶格 / 高 IoU 也无 span** → **假设 A**(指标/数据饱和);
     对策 = 换指标(AP70/AP80/分层)或换载体。
4. **必做的正交项**:把 int8 从 fake-quant 换成**真量化 AP**(见 §1.2 假设 A 诊断 b)。在没有真
   int8 AP 之前,"AP 轴无信号"里至少有一部分是"根本没测量化那一维"造成的假象,必须先排除。

### 1.3.D 假设 D 最小闭环探针(与 §1.3 判别实验并行,低成本先验证"闭环是否有信号")
目标:用**最少**的闭环跑量,回答"真压缩模型在 V2Xverse 闭环里 DS 是否可分辨"。
1. **3 个配置**(跨开环 AP 谱):① base fp32(AP70≈0.63);② 中档(int8_tc + backbone 中等剪枝,
   AP70≈0.58);③ 激进(cliff 档,int8_tc + 极端剪枝,AP70≈0.53)。
2. **固定 N 条路测场景 × 固定 seed**(用天然可复现 route,关 ambient traffic,见 closedloop 坑),
   每配置跑同一组,测 **driving score / collision / route completion**。
3. **判读**:
   - 若 3 档 DS **单调可分**(超过 seed 噪声)→ **闭环是比开环 AP 更强的评价轴**,框架 AP 维改用
     闭环 DS(或 DS 与 AP 联合)。这直接解掉"AP 无信号"。
   - 若 3 档 DS **也平**(在噪声内)→ **坐实假设 B(对本任务真无损)**,且说明连闭环都不敏感 →
     该换更难载体/更难 route,或接受"此模型此任务无精度 trade-off"这一诚实结论。
4. **成本**:仅 3 配置 × N 场景,复用已跑通的 H800 torch2 闭环;比开环 finetune 网格便宜。可作为
   AP 最终验证的**第一步**(先确认闭环有无信号,再决定是否大规模铺)。

### 1.4 结论倾向(基于现有证据,待 §1.3 证实/推翻)
现有证据(cliff 无悬崖、参数冗余 68.9%、AP70 span 仅 0.101)最支持**假设 B(过参数化)**;
但**假设 A 的"int8 AP 是假的"**是未排除的硬伤,**假设 C 未被 zero-shot 曲线证伪过**,而**假设 D
(闭环)最可能直接解掉问题**(闭环对 AP 已知有信号,只差在真压缩模型上试)。
⇒ 下一步:**先跑 §1.3.D 最小闭环探针**(便宜、可能一步解决)+ **§1.3 判别实验 + 真 int8 AP**
(给开环定性 A/B/C)。两条并行,闭环有信号则 AP 维切闭环 DS;闭环也平则坐实 B。

## §2 问题二:跨模型框架效果 — 是否需要冷启动额外数据?

### 2.1 背景
框架要"输入任意网络 → 输出 Pareto"。跨模型时结构差异巨大(Pyramid conv-backbone / V2X-ViT
attention 92% / CoDriving 可分离)。已知:① auto_trace(AutoTraceAdapter)能自动扫描产 manifest
(Phase A0/A1 已复现 4 手写 adapter + 探通 F-Cooper/AttFuse);② 但 **cost model 是在 Pyramid
original60 上训的**,直接迁到新模型没有该模型的测量锚点 → 预测无依据。

### 2.2 用户提案(赞同):轻量全模型压缩探针作冷启动锚点
onboard 新模型时,先做一批**不分区(whole-model)的 P×Q 轻量探针**,measured lat/energy/AP,
并入 LUT 作为该模型的冷启动锚点,再让 cost model 微调/迁移。

**设计(可执行)**:
- **探针网格**:P 轴 = 全模型统一剪枝率 {0, 0.25, 0.5, 0.75}(不分 stage,4 档);Q 轴 = 全模型
  统一精度 {fp32, fp16, int8_tc}(3 档)→ **12 个 anchor**(远小于分区搜索空间)。
- **测量**:复用 measure_config 三精度接口(已 ready);AP 用 §1.3 的真口径(含真 int8)。
- **并入方式**:给训练表加 `model_class` one-hot + `is_coldstart_anchor` 标记;cost model 做
  **迁移/分层**(base = Pyramid 全量 + 目标模型 12 anchor 微调),或对目标模型只用其 anchor 训
  一个小残差头。
- **验证**:留出目标模型的若干分区配置作 test,比"零 anchor 直接迁"降 MAPE 多少 = 冷启动价值。

### 2.3 与现有资产的接口
- auto_trace 自动产 manifest → 决定探针网格的合法 width/precision(bridge 可建性)。
- 探针只需"模型构造器 + ckpt + 输入"(auto_scan 的薄胶水),不需源码 surgery。
- **注意**:whole-model 探针的"不分区"正好对应三臂里的 **S0/serial 基线**,可顺带为跨模型三臂
  提供 argmin-drift 载体(不同模型 fp16-最优 vs int8-最优 全局压缩率是否漂移)。

### 2.4 待定
- 12 anchor 是否够?可能需按模型瓶颈类型(conv/attention)自适应加密。
- attention 模型(V2X-ViT)瓶颈在 attention 非 conv,现有 rewrite(conv group→TC)对它无效 →
  跨模型不仅是 cost model 冷启动,还有**算子覆盖**问题(见 transformer 入框架计划)。

## §3 问题三(最后):跨硬件实现

- 现状:M2 的 f_lat 跨平台函数(4090↔Orin)已拟合 R²>0.995(旧结论);energy/throughput 跨硬件
  未系统化。
- 思路:硬件作为 LUT 的一个维度 / 或每硬件一套轻量锚点 + 跨硬件迁移函数(同 §2.2 冷启动思路,
  把"新模型"换成"新硬件")。Orin INT8 DLA 不可行(实测 0/12,Pyramid FP16-only)是硬约束。
- **优先级最低**:先把 §1(AP 轴)和 §2(跨模型冷启动)做实,跨硬件是把同一套冷启动/迁移方法
  复用到硬件维,方法学同构。
