## 3. 6_25 记录的核心空白

### 3.1 搜索空间构建空白

6_25 时的主要问题:

- P 轴不应固定为 `25%/50%/75%`，需要从真实结构、硬件对齐、AP anchor 和 latency LUT 可测点生成 width anchors。
- block/knob 不能只按粗 block 类型划分，需要有 stage/block/group 层级。
- Q 轴虽然当时证据信号弱，但必须作为正式软件候选成员进入搜索空间。
- dense-core/full-model 边界必须保留，不能把 dense-core 证据外推成 full-model claim。
- 当前要判断的是模型级 joint/serial/noS，而不是每个 knob 单独判断。

### 3.2 Cost Model 与证据构建空白

6_25 时的主要问题:

- 没有统一 `Stage2EvidenceRegistry`。
- latency LUT 生成流程没有产品化。
- AP anchors 生成流程没有产品化。
- Q evidence 的 backend、coverage、buildability 和 AP/latency 边界不清。
- energy LUT 还没有统一产物。
- AP x latency -> DS/closed-loop objective 只能作为带 scope 的 downstream LUT，不能无约束外推。
- LUT 数据规模、coverage、failed/proxy/measured cell 统计缺失。

### 3.3 AAAI 实验补充与验证空白

6_25 实验文档提出的 P0/P1 缺口包括:

- E1 主结果: end-to-end 或 dense-core 加速与 AP 保持。
- E2 joint vs serial/noS/single-axis 公平消融。
- E3 rank-flip / P(IC_BN)-hub 机制实验。
- E4 跨模型泛化。
- E5 搜索效率和测量成本。
- E6 cost model / LUT / AP anchor 质量。
- E7 跨硬件实验。
- E8 full-model coverage / Amdahl 分解。
- E9 energy / throughput / power。
- E12 外部 baseline 对比。

### 3.4 Stage1/Stage2 集成空白

6_25 时的主要问题:

- Stage1 manifest 只能定义结构、coverage 和硬件合法性，不能伪装成 latency/AP/energy 实测。
- Stage2Input/Stage2Output 契约、统一 CLI、classifier gate 和 evidence/search space/cost model 串联还不完整。
- 开源仓库路径需要能端到端复现，而不是只靠本地临时脚本和人工整理。



要求:

- 使用与 `fp32_latency_strict_direct_rows_v1.jsonl` 一致的 strict direct H800 TVM 口径。

- 不能用映射值、旧 smoke 或 FP16 latency 代替。

### 5.3 Energy 覆盖完整但可信度仍需审计

当前 energy:

```text
FP32 60/60
FP16 60/60
INT8 60/60
```

但 energy 对以下因素敏感:

- GPU 是否空闲。
- power telemetry window 是否对齐。
- schedule policy 是否一致。
- 后台任务和同机负载。

因此 energy 可进入总表，但使用时必须保留:

```text
energy_schedule_policy
energy_measurement_source
energy_evidence_scope
energy_claim_status
```

### 5.4 Evidence registry 仍未完全产品化

当前三精度总表已经承担了大量 registry 功能，但还不是 6_25 设计中的完整 `Stage2EvidenceRegistry`。

仍缺:

- 统一 registry 文件或 registry API。
- measured / historical / proxy / failed / no_claim 的全局 gate。
- 对 latency/AP/energy/DS 的 coverage 统计和版本冻结。
- runner 自动读取 registry，而不是人工指定 row/summary 路径。

### 5.5 AAAI 论文实验链路仍未完全收口

当前 original60 三精度表解决的是证据数据覆盖，不等于论文实验全部完成。

仍缺:

- joint vs serial/noS/P-only/Q-only/S-only/random 的统一公平消融表。
- rank-flip / P(IC_BN)-hub 机制图的自动化生成。
- CoDriving 阴性机制图。
- F-Cooper / AttFuse 等新增模型的 Stage2 latency LUT 与 AP anchors。
- 搜索成本表、measurement budget fairness 和 convergence curve。
- full-model / Amdahl 分解，避免 dense-core 结果被写成 full pipeline speedup。
- 外部 baseline 对比。

## 8. 固定规则

- Stage1 manifest 只定义结构、coverage 和硬件合法性，不伪装成 latency/AP/energy 实测。
- H800 TVM/Relax/MetaSchedule 是当前新增实测主后端。
- TRT 只能按 historical 或单独 backend scope 标注。
- dense-core / backbone-subnet evidence 不得外推为 full-model speedup。
- latency 单位统一 ms。
- no_claim 不能当作 0。
- smoke AP 不能当 full-val AP。
- 不允许跨 precision 复制 AP/latency/energy 补空白。
- 总表更新必须先有 row 文件，再有 merge 脚本或可审计合并记录。
- 每次总表更新必须记录覆盖数量、缺口数量、provenance 和不可信项。
