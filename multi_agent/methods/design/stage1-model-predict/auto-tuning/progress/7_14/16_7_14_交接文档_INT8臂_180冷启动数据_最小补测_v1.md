## 0. 本轮结论

本轮结论不是“INT8 不应该搜索”，也不是“回退使用旧 hand-rewrite 作为最终主结果”。更准确的结论是:

1. 现有 Phase1 自动搜索叙事应保留。
2. 旧 hand-rewrite/int8_tc 数据不能直接作为最终自动后端主结果。
3. hand-rewrite 里有价值的是 fused/full-engine 的后端思想，应上升为可自动选择、可自动重写、可实测回流的 backend/search arm。
4. 搜索空间需要从 `Q={fp32,fp16,int8}` 扩展为 `Q x S`，其中 `S` 是后端/调度路线。INT8 只有绑定到合适自动后端时才是有效加速臂。
5. INT8 某些点慢，不应写成硬规则，而应由性能模型和实测回流解释: padding、requant、materialization、fusion boundary、pack 开销会改变 INT8 相对 fp16 的收益。

最关键的审计发现: 旧 180 行 cold-start/training 表中，INT8 的 60 行全部是 `measured_int8_tc`。这属于历史 hand-rewrite/int8_tc 证据层，不是最终自动 INT8 TensorCore 后端的 gold measurement。如果直接把这 60 行当作最终自动后端训练数据，cost model 会学习到过度乐观的 INT8 性能。

## 4. 对旧矛盾的解释

之前看起来存在矛盾:

- Phase1/hand-rewrite-family 的一些点非常快，例如 `24x32x96` 旧 int8_tc prior 是 1.7785 ms。
- 后来的 Route B/auto 后端核验又发现 INT8 在某些点慢于 fp16，例如 `24x32x96` Route B INT8 是 3.5988 ms，慢于 Route B fp16 comparator 的 2.0156 ms。

这两个结论并不必然矛盾，因为它们不是同一个后端证据层:

- 旧 int8_tc 是 hand-rewrite/int8_tc 路线，代表一种人工写死的强后端实现。
- Route B INT8 是自动分解、自动暴露 int8 matmul、再 tensorize/tune 的自动后端路线。
- 论文和框架如果要保持“自动搜索”叙事，最终主结果必须来自可自动选择、可自动实测回流的路线，而不是人工替换成一个固定 hand-rewrite 结论。

因此，旧 hand-rewrite 的价值不是作为最终主结果，而是:

1. 证明 INT8 TensorCore 路线在硬件上有潜在收益。
2. 暴露出自动后端需要学习/搜索的结构: fused/full-engine、materialization 边界、padding 代价、requant 代价。
3. 作为 cold-start prior 或 backend design hint，但必须带 `source_class` 和 `trusted_for_final_frontier=false`。

## 5. 对 Phase1 搜索框架的最小调整建议

不要写硬规则，例如“INT8 总是赢”或“INT8 总是输”。建议做最小结构化调整:

1. 给每条样本增加元数据:
   - `precision`
   - `backend`
   - `schedule_route`
   - `source_class`
   - `trusted_for_final_frontier`
   - `can_use_as_cold_start_prior`
   - `measurement_timestamp`
2. 将搜索变量从 `Q` 扩展为 `Q x S`:
   - 示例: `(fp16, route_b_auto_tc)`
   - 示例: `(int8, route_b_auto_int8_tc)`
   - 示例: `(int8, native_direct)`
   - 示例: `(int8, historical_hand_rewrite_prior)` 只能作为 prior，不能进入最终 frontier gold。
3. cost model 训练时把 `source_class/backend/schedule_route` 作为特征或分层模型输入。
4. final frontier 筛选时只允许 `trusted_for_final_frontier=true` 的实测点进入主结论。
5. 对旧 180 数据不删除、不覆盖，而是 relabel/downweight:
   - fp32: baseline/reference
   - fp16: legacy/rewrite diagnostic prior，需 Route B 同口径补测
   - int8: historical hand-rewrite diagnostic prior，需 Route B/auto INT8 同口径补测
6. 采集策略增加 disagreement trigger:
   - 当旧 prior 与自动后端真测差异超过 1.5x，强制进入再测/高权重学习队列。
   - 当前已确认 `24x32x96` 是高差异样例: Route B INT8 / old int8_tc = 2.0235x。

  - `can_use_as_cold_start_prior=true`
  - `recommended_action=remeasure_routeb_int8_for_frontier_candidates`

  - `source_class=legacy_or_rewritten_fp16_diagnostic`

这样不会破坏自动搜索叙事，也不会浪费旧实验。旧数据进入模型时的身份是 prior/diagnostic，不是最终 gold。

## 7. 下一阶段实验重点

下一阶段不应再泛泛讨论“是否使用 hand-rewrite”，而应把问题变成可实验闭合的自动后端问题:

1. 选择 8 到 12 个关键点，至少覆盖:
   - `24x32x96`: 高差异、旧 prior 明显过度乐观
   - `32x32x128`: 自动 INT8 能赢 fp16 的边界样例
   - `64x32x96`: INT8/fp16 接近的边界样例
   - Phase1 Pareto 中小于 3 ms 的旧 int8_tc 点
2. 对每个点做同口径测量:
   - Route B fp16 auto TensorCore
   - Route B INT8 auto TensorCore
   - native direct INT8
   - old prior 只读不重写
3. 输出每点 rootcause:
   - tensorized block 数量
   - pack/requant/materialization 时间占比
   - padding ratio
   - fusion boundary 数量或可观测 proxy
4. 用测量结果更新 cost model 的数据入口，而不是在代码里写死 INT8/FP16 胜负规则。
