## §1 三线最终结果(全经主控独立核验)

### §1.1 计划一 — original60 满60点 AP80@e2 + 正式 Spearman(**闭合**)

产物 `results/plan1_original60_ap80e2/plan1_final_60_spearman.json`(主控 H800 重算三条腿,数值逐位一致):

| 指标 | 值 | 判读 |
|---|---|---|
| **AP80@e2** | n=**60**,spread=**0.1038**,stdev=**0.0234** | **~20× 噪声地板(0.005)→ 可排序** |
| AP90@e2 | mean **0.0064**,max 0.0099 | 噪声地板,排除 |
| Spearman AP80@e2 **vs 收敛AP70** | ρ=**0.343**,p=0.012(cov 53/60) | 弱正相关,与收敛序一致 |
| Spearman AP80@e2 **vs 参数量** | ρ=0.201,p=0.124 | **不显著** |
| Spearman AP80@e2 **vs 剪枝率** | ρ=**−0.201**,p=0.124 | **不显著** |

**★本轮关键订正(主控自测,plan1_ap80_signal_on_w0.png)**:AP80@e2 的可排序信号**不在标量剪枝率上,在 w0(第一段 backbone 宽度)轴上**:

| 相关对象 | Spearman ρ | p | 判读 |
|---|---|---|---|
| AP80@e2 **vs w0** | **+0.501** | **<1e-4** | **强显著 — 信号真源** |
| AP80@e2 vs w1 | ~+0.1 | n.s. | 弱 |
| AP80@e2 vs w2 | ~0 | n.s. | 无 |
| AP80@e2 vs 剪枝率(标量) | −0.201 | 0.124 | 不显著(w0 信号被平均抹掉) |

- **定论**:AP80@e2 spread≈0.10 是真信号(≈20× 噪声),度量**预算受限可恢复性**(固定 2ep 能恢复多少,**非收敛 AP**);但它由 **backbone 首层宽度 w0 主导**,标量剪枝率会把 w0 信号平均掉 → 表面"AP 对剪枝率全平"。机理 = **过参数化 + 可达区间无精度悬崖**。
- **剪枝轴另一半(latency,plan1_latency_vs_prunerate.png)**:latency vs 剪枝率 **ρ=−0.795 p<1e-4**,跨度 **9.8–54.4ms(5.2×)**,单调强获益。→ **剪枝轴 = AP 退化(平)+ latency 强获益 → Pareto 退化为"剪到底即最优"**;真正 AP↔速度 trade-off 不在剪枝轴,在量化轴(见 §1.2)。
- **剪枝率结构上限 62.2%**:只剪 backbone 三段宽 w0/w1/w2(grid 下界 [16,32,64],base [64,128,256]),固定模块(encoder_m1/backbone_m1/head/shrink_conv/deblocks)不缩放;w0 地板=16(grouped conv group=32 + HEAL ResNeXt 宽度公式在阈值下塌通道,见 [[project_heal_resnext_width_formula]])。**不建议延伸 80–90%**(backbone-only 已证无悬崖,延伸大概率只复现同结论)。

核验点:① `quant_scale_source = smoothquant_alpha_perlayer_real_calibration_percentile_p99.9_activation_per_tensor_weight_per_output_channel_migrated` — **真 SmoothQuant 逐通道迁移**(`s_ic=act_absmax^α/max(w_absmax^(1-α),1e-8)`,α∈{0.3,0.5,0.7} 逐层,**保 tensor-core dp4a/WMMA 归约结构**),**双标注不覆盖旧 PTQ 口径**;② n=300 四档统一;③ **fp16 桥接 sanity 4/4 PASS**(bridge fp16 vs 全量1789真PyTorch Δ<1%,证 TVM↔PyTorch 管线本身正确,排除 fake-quant);④ no-peek:校准 64 帧 train-pool、评测 val,overlap=0。

- **定论 — 量化难度 model-dependent(坐实)**:Pyramid base fp16→int8 AP50 **−0.13%** vs CoDriving base **−2.40%** = **~18× 量级差**。CoDriving 标准卷积 backbone 激活离群(layer1.0.conv1 max=40.7 vs p99.9=13.46)使 int8 有**实质但可控**代价(2–4% AP50/70,6–8% AP80),**非免费午餐**;而 Pyramid grouped-conv 近无损。**"真逐输入通道反量化会打断 tensor-core 归约"本身即量化粒度↔硬件张量化冲突的耦合陷阱侧写**。与"耦合强度 model-dependent"(Pyramid 耦合/CoDriving 可分离)同构,构成论文"何时该联合搜"叙事的量化轴证据。

## §2 四点最终决策(承 4_ §5 停止条件第四勾,带证据)

**① 框架 AP 轴口径 = `AP80@e2-budget-capped` + 必带宽度结构(w0),不能只喂标量剪枝率。**
证据:AP80@e2 spread 0.104(≈20×噪声)是真信号,但 vs 剪枝率 ρ=−0.20(n.s.)、**vs w0 ρ=+0.50(p<1e-4)**。可恢复性由"从哪儿剪(保 w0)"决定,不是"剪多少"。→ 接入搜索内环时 label 用 AP80@e2,特征必含首层宽度。

**② 剪枝轴定性 = Pareto 退化(AP 平 / latency 强获益 5.2× / 剪到底即最优)。**
证据:AP 对剪枝率近全平(过参数化无悬崖),latency vs 剪枝率 ρ=−0.795、5.2× 跨度。→ 真 AP↔速度 trade-off 载体是**量化轴**,不是剪枝率。

**③ CoDriving 真吃到 int8-TC,且量化难度 model-dependent(坐实)。**
证据:fp16-TC max_rel_err=0.0(WMMA 通);int8 真 AP 四档闭合,base AP50 −2.40% vs Pyramid −0.13%(~18×)。CoDriving int8 有实质代价、**非免费**,与 Pyramid 近无损形成对照。

**④ 冷启动在搜索闭环有价值(value 用途),rank 中等。**
证据:首轮粗筛省 58.3% 内环预算、recall 1.0;耦合分数预测器 6/6 一致;自适应预算已接入 SMBO 且 legacy 零回归。
