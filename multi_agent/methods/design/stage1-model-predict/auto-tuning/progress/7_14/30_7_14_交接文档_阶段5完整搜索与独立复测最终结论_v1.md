## 2. 搜索协议与论文口径

### 2.1 四个独立任务

阶段 5 没有把模型或后端作为搜索基因，而是运行四个互相独立的任务：

| 顺序 | 任务 ID | 固定目标模型 | 固定硬件 | 固定 capability profile |
|---:|---|---|---|---|
| 1 | `S5-PYR-TVM` | Pyramid | H800 | TVM 自动后端 profile |
| 2 | `S5-PYR-TRT` | Pyramid | H800 | TensorRT profile |
| 3 | `S5-COD-TVM` | CoDriving | H800 | TVM 自动后端 profile |
| 4 | `S5-COD-TRT` | CoDriving | H800 | TensorRT profile |

每次搜索固定一个 `target model + hardware + capability profile`，搜索基因只有：

```text
genome = (w0, w1, w2, q_mode)
q_mode in {fp16, int8}
```

因此，TVM 与 TensorRT 的结果是两个固定编译环境下的独立搜索结果，不能解释为搜索器在同一次搜索中“选择了后端”。

### 2.2 预算协议

四个任务使用相同预算：

| 参数 | 数值 | 含义 |
|---|---:|---|
| `M` | 686 | 每个目标模型的完整候选 genome 数量 |
| `B` | 4 | 每轮由 acquisition 自动选择并送入真实测量的配置数 |
| `T` | 16 | 每个独立任务的在线真实测量总预算 |
| 轮数 | 4 | `T/B=4` |

每轮均执行候选打分、批量选择、模型/ONNX 构建、后端真实性能测量、AP 测量、结果回流和下一轮重训练。候选不是由人工逐点指定。

### 2.3 冷启动边界

本轮正式搜索只使用冻结的 Gold176 作为 cold-start。经目标模型和固定 profile 过滤后：

| 任务 | cold-start 行数 | 在线新增行数 |
|---|---:|---:|
| `S5-PYR-TVM` | 42 | 16 |
| `S5-PYR-TRT` | 42 | 16 |
| `S5-COD-TVM` | 38 | 16 |
| `S5-COD-TRT` | 38 | 16 |

阶段 5 之前产生的其他 Pyramid、CoDriving 实测结果没有作为额外标签注入本轮搜索。它们只可用于事后对照，不能改变正式在线轨迹。

## 4. 各任务实验结论

### 4.1 Pyramid + TVM

1. 搜索使归一化 HV 从 `1.060796` 提升到 `1.151813`，四任务中提升最大。
2. 最终 5 个 Pareto 点全部为 INT8：
   `16x32x64`、`16x48x64`、`24x48x64`、`32x32x96`、`48x80x64`。
3. 其中 4 个点由在线搜索新增到最终前沿，说明有限预算反馈确实扩展了 cold-start 前沿。
4. 代表性点如下：

| 配置 | 来源 | latency (ms) | energy (J) | AP70 |
|---|---|---:|---:|---:|
| `16x32x64, INT8` | cold-start | 3.320522 | 0.680718 | 0.615977 |
| `16x48x64, INT8` | round 0 | 3.562675 | 0.638280 | 0.523549 |
| `24x48x64, INT8` | round 1 | 3.614378 | 0.651887 | 0.620452 |
| `32x32x96, INT8` | round 3 | 3.841642 | 0.722813 | 0.632916 |
| `48x80x64, INT8` | round 3 | 4.705518 | 0.872443 | 0.641434 |

**可支持的结论**：在 Pyramid、H800、当前 TVM 自动 INT8 路径和当前三目标定义下，INT8 并非必然被 FP16 支配，搜索能够找到一组真实 Pareto INT8 点。

**不能外推的结论**：不能由此宣称 TVM INT8 在所有模型、所有宽度或单一延迟指标上恒优于 FP16。

### 4.2 Pyramid + TensorRT

1. 58 行均成功完成，未出现 build 或数值 feasibility failure。
2. 最终前沿同时包含 FP16 和 INT8，说明即使 TensorRT 的 INT8 工程路径成熟，精度决策仍需与剪枝宽度联合搜索。
3. HV 提升为 `+0.26%`，表明 Gold176 已覆盖较强初始前沿，但在线搜索仍找到新的前沿点 `48x32x128, INT8`。
4. 同一宽度下可观察到不同的速度、能耗和精度交换：

| 配置 | latency (ms) | energy (J) | AP70 |
|---|---:|---:|---:|
| `16x32x64, FP16` | 0.456800 | 0.136594 | 0.621109 |
| `16x32x64, INT8` | 0.456288 | 0.135687 | 0.618838 |
| `16x64x128, FP16` | 0.456880 | 0.117679 | 0.561842 |
| `16x64x128, INT8` | 0.401344 | 0.092636 | 0.417491 |

**结论**：TensorRT INT8 能带来速度或能耗收益，但收益大小和 AP 损失随结构配置变化。框架保留 `q_mode` 搜索轴是必要的，不能把 TensorRT 下的 INT8 写成固定规则。

### 4.3 CoDriving + TVM

1. HV 从 `0.815884` 提升到 `0.840192`，增益 `+2.98%`。
2. 最终 15 个 Pareto 点同时包含 FP16 和 INT8；在线搜索向前沿加入了多种不同宽度的配置。
3. 54 行中有 1 行数值 feasibility failure，该状态被保留为搜索空间的真实不可行证据。
4. 该任务是四任务中唯一未完全通过独立复测一致性门槛的任务，问题集中在 `16x64x128, INT8` 的跨时段 latency/energy 基线漂移，而不是 AP 崩溃。

**结论**：当前证据不支持“CoDriving + TVM 的 INT8 恒慢、应删除 INT8 搜索臂”，也不支持“TVM INT8 已稳定优于 FP16”。正确口径是让模型依据 capability context、结构和在线反馈判断不同点的可行性与 Pareto 价值。

### 4.4 CoDriving + TensorRT

1. 54 行全部成功，无 build 或数值 feasibility failure。
2. HV 从 `1.037310` 提升到 `1.040351`，增益 `+0.29%`。
3. 在线搜索在 round 2 找到新的前沿点 `16x64x64, FP16`。
4. `16x32x64` 的对照说明 TensorRT INT8 可以在 AP 近似保持时改善速度与能耗：

| 配置 | latency (ms) | energy (J) | AP70 |
|---|---:|---:|---:|
| `16x32x64, FP16` | 0.277888 | 0.073971 | 0.357812 |
| `16x32x64, INT8` | 0.267968 | 0.067680 | 0.355274 |

**结论**：在该配置上，INT8 相比 FP16 延迟约降低 `3.57%`、能耗约降低 `8.50%`，AP70 仅下降约 `0.00254`；但最终前沿仍以多个 FP16 点为主，进一步证明精度模式不应被人工固定。

## 5. 阶段 5 对核心研究问题的回答

### 5.1 自动搜索是否真正以单个目标模型为中心

是。四个任务各自固定目标模型和 profile，从完整 686-genome 池中自主选点。Pyramid 与 CoDriving 之间没有在同一轮共同生成一组宽度，也没有人工要求每个宽度成组测四条精度/后端配置。

### 5.2 搜索是否发现了 cold-start 之外的新前沿

是。四任务 HV 均没有下降，并且都至少找到一个进入最终前沿的在线点。提升大小存在明显差异：TVM 两任务的新增收益高于 TensorRT 两任务，说明不同 profile 下 cold-start 覆盖度和剩余探索空间不同。

### 5.3 INT8 是否应该从 TVM 搜索空间删除

不应该。Pyramid + TVM 最终前沿全部为 INT8，CoDriving + TVM 最终前沿则为 FP16/INT8 混合。实验支持的叙事不是“TVM 默认使用或禁用 INT8”，而是：

> 同一硬件上的有效精度决策依赖目标模型、结构形状、编译后端实际能力和实测反馈；搜索器应保留 INT8，并学习何时选择或放弃它。

### 5.4 TensorRT 是否使搜索失去意义

不会。TensorRT 两任务中，INT8 的速度/能耗收益与 AP 损失仍随宽度变化，最终 Pareto 同时保留 FP16 和 INT8。后端优化更成熟不等于所有 genome 的最优精度模式相同。

### 5.5 当前预算是否有效

`B=4, T=16` 已经证明可以在四任务中发现新的 Pareto 点并提升 HV，因此该预算足以完成阶段 5 的方法 smoke 和有限预算搜索闭环。它尚不能单独证明前沿已全局收敛，论文中应称为“固定预算搜索结果”，不能称为穷举最优。

## 7. 实验实现中发现并修复的问题

### 7.1 INT8 quant contract 溯源错误

独立复测最初错误地回退到默认量化合同，导致 CoDriving TVM INT8 的数值 sanity/AP 异常。修复后，runner 从 Gold 性能产物中解析并绑定实际使用的 `percentile_99_99` quant contract，再重新执行 3 次性能测量和完整 AP。

修复后的 AP70 为 `0.319766`，与原值 `0.320088` 一致。由此得到的工程要求是：

> INT8 证据链必须同时绑定 checkpoint、ONNX、calibration/quant contract、编译产物和预测输出，不能只按模型宽度与 `q_mode` 恢复配置。

### 7.2 失败审计不能阻断收集

finalizer 已改为在某个配置不通过一致性门槛时仍生成完整失败审计，而不是中止整批汇总。这样可以区分“实验没有完成”和“实验完成但未通过门槛”。

### 7.3 本轮代码验证

与独立复测、quant source、finalizer 和 full-budget closure 相关的定向测试均已通过。这里的测试通过只证明流程实现符合合同，不替代上述 H800 真实测量结果。

## 8. 真实图特征回填与回放

### 8.1 已完成事实

64 个在线点均已从实际物化图中回填 graph features，覆盖 43 个结构组。历史请求和正式测量标签没有被修改。

### 8.2 surrogate 与 actual graph feature 差异

teacher-forced 单步回放结果为：

| 指标 | 结果 |
|---|---:|
| 可回放历史轮次 | 12 |
| 候选 batch 完全一致 | 2 |
| 候选选择发生差异 | 10 |
| 每批 4 点的平均重合数 | 1.833 |
| 预测相对变化均值 | 3.07% |
| 预测相对变化最大值 | 34.60% |

这说明 v2 正式轨迹中使用 surrogate graph features 不是无影响近似。真实图特征回流后，模型可能选择不同候选。

### 8.3 当前解释边界

该回放是 teacher-forced one-step replay。首次选择分歧后，反事实候选没有真实标签，因此无法重建完整反事实搜索轨迹。当前只能确认“图特征差异足以改变选择”，不能据此计算真实图特征版本最终会得到的完整 Pareto/HV。

按照此前约定，本文件记录问题但不替代后续专项决策。正式论文若要把阶段 5 描述成完整闭环自主搜索，需要采用实际物化图特征进入下一轮训练，或明确将本轮称为 surrogate-feature pilot。

## 9. 论文可用结论与禁止表述

### 9.1 当前可用结论

1. 已实现固定目标模型、固定硬件和固定 capability profile 下的结构压缩与精度联合搜索。
2. 四个独立任务均在 `T=16` 预算内完成 4 轮硬件在环反馈，共获得 64 个在线真实测量点。
3. 四任务 HV 均提升，证明在线反馈能在 Gold176 cold-start 之外发现新的 Pareto 候选。
4. FP16/INT8 的优劣不是跨模型、跨后端的固定规则；不同 profile 的最终前沿组成不同。
5. TVM 上保留 INT8 搜索臂有真实证据支持，但其结果必须按目标模型和 shape 条件解释。
6. TensorRT 下仍需联合搜索精度与剪枝宽度，不能默认全部 INT8。

### 9.2 当前禁止表述

1. 不得写“阶段 5 已获得全局最优前沿”；当前是固定预算结果。
2. 不得写“INT8 一定快于 FP16”或“TVM INT8 一定慢于 FP16”。
3. 不得把 TVM 与 TensorRT 描述成同一搜索任务中的可选 genome。
4. 不得宣称 16/16 独立配置全部通过；真实结果是 15/16。
5. 不得将当前 v2 轨迹直接描述为全程使用实际 graph features。
6. 不得用发生基线漂移的 CoDriving TVM INT8 点作为未经说明的论文最终数值。

## 13. 阶段 5 完整搜索流程与实测耗时

本节补充从输入目标模型到最终审计的完整流程。所有时间均来自 H800 结果目录中的 request、atomic feedback、terminal 和 audit 文件时间戳，不使用主观估计替代已记录时间。

### 13.1 端到端流程

```text
P0  固定任务合同
    target model + H800 + capability profile + genome + M/B/T
                         |
P1  冻结 Gold176 cold-start 和 capability profile
                         |
P2  构造完整 686-genome 候选注册表
                         |
P3  初始 cost model 拟合、全池预测、acquisition 选择 B=4
                         |
P4  物化四个选中 genome
    checkpoint/配置 -> ONNX -> quant contract -> backend build
                         |
P5  H800 性能测量
    latency + energy + feasibility
                         |
P6  数值 sanity 与 full AP
    AP30 + AP50 + AP70 或 numerical feasibility failure
                         |
P7  四行原子反馈
    证据 SHA 校验 -> 训练集回流 -> cost model 重训
                         |
P8  重复 P3-P7，直至 T=16（4 轮）
                         |
P9  任务级 Pareto/HV 与四任务 closure
                         |
P10 actual graph feature 回填、drift/replay
                         |
P11 16 配置独立复测与最终阶段门禁
```

P3 到 P8 是搜索器的自主闭环。人工固定的是任务合同、合法搜索空间、目标、预算和停止条件；每轮四个具体 genome 由 cost model 与 acquisition 决定。

Gold176 生成和 capability probe 属于阶段 3/阶段 2 的上游一次性成本，不计入本次阶段 5 搜索墙钟。阶段 5 内部从 Pyramid checkpoint inventory、686-genome source registry 到四任务首轮 request 的 CPU 准备约为 `5 s`（`09:26:26.588` 至 `09:26:31.392`）。

### 13.2 单轮内部阶段

每个任务的每一轮按照以下顺序执行：

| 顺序 | 阶段 | 输入 | 输出 |
|---:|---|---|---|
| 1 | 预测与 acquisition | cold-start + 历史反馈 | 4 行冻结 measurement request |
| 2 | source materialization | 选中 genome | checkpoint、配置、ONNX、校准源及 SHA |
| 3 | quant/backend preparation | ONNX 与 profile | TVM quant contract 或 TRT/TVM 编译产物 |
| 4 | performance measurement | 后端产物 | latency、energy、feasibility |
| 5 | numerical sanity | 后端输出 | 数值可行或 numerical failure |
| 6 | full AP | 数值可行输出 | AP30、AP50、AP70 |
| 7 | atomic feedback | 四行终态 | 下一轮训练视图或任务终态 |

相邻轮次从上一轮 atomic feedback 到下一轮 request 的 CPU 拟合、预测和选择约为 `3.1~3.4 s`。主要耗时来自模型物化/训练/导出和 full AP，而不是 acquisition 本身。

## 14. 真实图特征问题的最终实验讨论

### 14.1 要解决的不是所有候选预物化

actual-feature feedback 不要求先物化 686 个候选。正确合同是：

```text
未选择候选：使用 Gold176 训练的 surrogate graph features 参与 acquisition
本轮选中候选：保留选择时的 surrogate 快照和 SHA
选中候选物化后：从真实 ONNX 提取 actual graph features
当前轮测量：仍对应已冻结 request，不反向修改本轮选择
下一轮训练：使用已测点 actual features + 真实目标标签
```

因此，它不会把主动搜索退化为穷举，也不会引入 AP、latency 或 energy 标签泄漏。actual features 只描述已经物化的计算图。

### 14.2 已完成的具体实验

已完成三项图特征实验：

1. 对 64 个在线实测行提取 actual ONNX graph features，共覆盖 43 个唯一结构组；
2. 逐行计算 surrogate/actual drift，并按模型、后端和精度分组；
3. 在每个历史反馈前缀上执行 teacher-forced one-step acquisition replay。

分组 drift 结果为：

| 分组 | 行数 | 数值特征平均相对误差 | 最大相对误差 |
|---|---:|---:|---:|
| Pyramid | 32 | 5.91% | 188.28% |
| CoDriving | 32 | 3.84% | 81.68% |
| TVM | 32 | 5.24% | 188.28% |
| TensorRT | 32 | 4.51% | 114.06% |
| FP16 | 27 | 5.36% | 114.06% |
| INT8 | 37 | 4.52% | 188.28% |

这里的最大误差由个别基数较小或 surrogate 偏差较大的图统计量产生，不能只凭最大值判断搜索失效；真正决定是否可接受的是 acquisition 是否保持稳定。

### 14.3 acquisition 回放结果

| 指标 | 实测结果 | 解释 |
|---|---:|---|
| 历史总轮数 | 16 | 四任务各 4 轮 |
| round 0 不变 | 4 | 尚无在线反馈，按构造相同 |
| 可比较 actual-feedback 轮次 | 12 | round 1~3 |
| batch 完全一致 | 2/12 | 16.7% |
| batch 发生差异 | 10/12 | 83.3% |
| 每批平均重合数 | 1.833/4 | 45.8% |
| 预测相对变化均值 | 3.07% | 三目标综合统计 |
| 预测相对变化最大值 | 34.60% | 个别候选/目标 |

这个结果否定了“surrogate 与 actual 的差异足够小，可以把 v2 当正式轨迹”的假设。虽然平均预测变化只有约 3%，Pareto acquisition 对候选相对次序敏感，因此小的预测变化也能替换一半以上 batch。

### 14.4 为什么离线 replay 不能修补 v2

teacher-forced replay 只回答：在保持历史已测标签不变时，下一轮会不会选择不同候选。第一次发生分歧后，actual 路径新选候选没有真实标签，无法继续构造真实的反事实训练集。因此不能：

- 用 replay 候选替换历史 request；
- 用 cost model 预测值冒充这些候选的真实标签；
- 由 one-step replay 推断完整 v3 最终 Pareto/HV；
- 将 v2 的 64 个真实标签重新排序后宣称获得 actual-feedback 正式轨迹。

唯一可审计的解决方法是从相同 Gold176、相同 profile、相同 `M/B/T` 和相同 seed 启动新版本，并让每轮 actual features 真正进入下一轮训练。

### 14.5 actual-feature feedback 的成本判断

64 行 actual graph feature 的完整提取与审计约耗时 11 分钟，平均每行约 10 秒。相对 33 小时 28 分钟的搜索墙钟，占比约 `0.55%`。

因此，S2 类性能探针是否值得运行可以讨论，但已选点 actual graph extraction 没有成本争议：它消耗很小，却能修复训练输入证据链。选择继续使用 surrogate-only feedback 不能由资源成本支撑。

## 15. 两种口径的明确选择

### 15.1 口径 A：将 v2 直接作为正式搜索

不采用。原因是：

- 10/12 个可比较轮次发生选择分歧；
- 平均每批只有 1.833/4 个候选重合；
- v2 在线行虽然有真实目标，训练输入仍是 surrogate；
- 离线 replay 无法在首次分歧后恢复反事实真实标签。

如果仍把 v2 写成正式闭环，会造成“物化后真实结构上下文已回流”的论文表述与实现不符。

### 15.2 口径 B：v2 定位为 pilot，actual-feedback v3 作为正式轨迹

**采用该口径。**

v2 的作用保留为：

1. 验证四个独立任务的硬件在环控制器可以执行完整 `T=16` 预算；
2. 验证 latency、energy、AP 和 feasibility 可以原子回流；
3. 验证不同模型/profile 下 FP16 与 INT8 的 Pareto 组成不同；
4. 暴露 actual graph feature 回流缺口并为 v3 提供工程基线。

v2 的 64 个在线标签不能作为 v3 的 cold-start，也不能提前排除 v3 候选，否则会把 pilot 信息泄漏到正式轨迹。v3 仍只从冻结 Gold176 开始。

### 15.3 v3 正式轨迹必须满足的合同

1. round 0 使用与 v2 相同的 Gold176、profile、候选池、seed、`M=686`、`B=4`、`T=16`；
2. measurement request 保存选择时 surrogate feature 快照及 SHA，生成后不可修改；
3. source materialization 后从绑定 SHA 的真实 ONNX 提取 actual features；
4. feedback row 同时保存 `candidate_graph_features` 与 `graph_features=actual`；
5. 下一轮 cost model 对 cold-start 使用原 Gold actual features，对在线行使用物化 actual features；
6. actual extraction failure 必须阻断整批反馈，不允许静默回退 surrogate；
7. 每阶段记录 monotonic start/end，以得到可发表的搜索开销分解；
8. 四任务仍独立运行，后端不进入 genome；
9. 搜索结束后重新计算四任务 Pareto/HV，并重新抽取 16 个配置独立复测；
10. v2/v3 只做轨迹敏感性对照，论文主结果使用 v3。

### 15.4 v3 对照指标与停止条件

| 类别 | 必须输出的指标 |
|---|---|
| 轨迹 | 每轮 selected IDs、v2/v3 overlap、首次分歧轮次 |
| 模型 | 三目标预测、排序、不确定度与特征 provenance |
| 搜索 | 每轮 Pareto、HV、最终前沿组成、feasibility 状态 |
| 代价 | source、quant/build、performance、AP、feedback 各阶段耗时 |
| 复测 | 16 配置 × 3 次性能重复 + full AP |
| 证据 | request、ONNX、actual feature、编译、预测和 AP SHA |

正式停止条件：

```text
4/4 tasks budget_exhausted
16/16 rounds atomic feedback released
64/64 online rows carry extracted_actual graph features
0 silent surrogate fallback
four final Pareto/HV audits complete
independent validation passes the frozen consistency policy
```

按 v2 实测，v3 四任务搜索预计约 34 小时，独立复测约 4 小时，总计约 38 小时。actual extraction 本身不会成为主耗时。

## 16. 阶段 5 最终收口判断（2026-07-20）

本节取代第 10 节中的临时判定，作为当前最终状态。

| 层级 | 判定 | 说明 |
|---|---|---|
| v2 pilot 预算闭环 | **已收口** | 四任务、64 在线点、Pareto/HV、回填与复测均已执行 |
| 图特征问题诊断 | **已收口** | 已证明 surrogate-only feedback 会实质改变 acquisition |
| 正式搜索口径选择 | **已收口** | 明确选择 actual-feedback v3 |
| actual-feedback 正式轨迹 | **未执行完成** | 尚无 64 行 v3 在线真实反馈 |
| 论文级阶段 5 | **未收口** | 不能用 v2 替代 v3 正式轨迹 |
| 阶段 6 放行 | **否** | 等待 v3 搜索和独立复测通过 |

最终结论为：

> 当前阶段 5 不能正式收口。v2 是有效且必要的 pilot，但不是论文最终自主搜索轨迹。真实图特征实验已经给出足够强的反证，必须以 actual-feature feedback 重启同预算、同 seed、只使用 Gold176 冷启动的 v3 可审计轨迹；v3 满足第 15.4 节停止条件后，阶段 5 才能收口并进入阶段 6。
