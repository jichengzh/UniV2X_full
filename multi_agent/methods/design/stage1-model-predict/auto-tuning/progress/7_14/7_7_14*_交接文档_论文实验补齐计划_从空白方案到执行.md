## 2. ★统一口径主线:加速目标恒为"RSU 上部署的感知算法"

6_7_14 揭示的 Pyramid vs CoDriving 不可比,根子在**两模型的 latency 测量 scope/后端/设备/batch 不一致**。本轮所有搜索流程统一到一条 scope 定义,这也是跨模型可比的前提:

- **同一后端**:框架前进口径全 TVM(内层真调优);TRT/AutoTVM 只在 Phase 3 作 baseline,且每个 model-hardware pair 内部同口径。
- **每模型内部自洽 Pareto**:跨模型比较只比**speedup 比值 / Pareto 形状**,不并列绝对 ms(6_7_14 纪律)。

⇒ Phase 2 打通多模型时,第一件事就是把每个模型的"RSU 感知段"scope 对齐到统一定义,消除 6_7_14 的不可比。

### 3.1 框架实际运行模式(联合 P×Q×S,读 `run_pqs_ablation.py`/`search_three_arm.py` 扒出)

**Phase 1 生产搜索的决策变量 = 软件配置 $x=(p,q)$**;调度 $s$ 由**内层探针 tune 给出**(不是搜索维度):
- **p = 宽度**:W0∈{16,24,32,40,48,56,64}(7)× W1(7)× W2(7)= **343**。
- **q = 精度**:{fp32, fp16, int8_tc}(**3**,精度是联合基因,非外层循环)。
- ⇒ **联合软件空间 = 343 × 3 = 1029 个 (p,q) 点**。
- **s = 调度:每个 (p,q) 由内层调度器 tune 出唯一 tuned 实现**,不作搜索维度,不 ×2。生产 Pareto 上每点都是 tuned 口径。
- ⚠️ `SCHEDULES=(default, tuned)` 那个 **2 点离散化是消融器件(Phase 3 专用)**:构造 A-noS(不给调度反馈)/ A-serial(先锁 P/Q 再调度)臂时,需要 "default/未调优" 点作对照。**Phase 1 不涉及,别把它当搜索轴。**
- **int8 可建性约束**(结构耦合,`qlut.can_build_int8(w)`):NCHWc dp4a 需 in_per_g%4==0;**s0=48(in_per_g=3)→ int8 结构不可建**,feasibility_gate 剪掉这些 (w, int8) 对。**这正是 joint>serial 的机理**(serial 在 fp16-default 先锁的 misaligned s0=48 宽度是 int8-不可建,够不到 int8-P_g 区)。

**冷启动**(已完成):180-LUT 训 cost model(输出 μ±σ);lat spearman 0.991 / energy 0.955。

**搜索循环(surrogate-assisted NSGA-II + 真测反馈)**:
1. **NSGA-II 在 surrogate 上搜联合 (w,s,q)**:cost model 预测 (AP, lat, energy),多目标非支配排序,pop 迭代到 budget 次评估。(cost 评估廉价,全在 surrogate。)
2. **inner 调度器 + 目标硬件真测**:对预测前沿邻域候选,TVM **fresh workdir + 逐宽度独立进程**真调优 + 实测 lat/energy(防假 ratio,[[feedback-tvm-tune-apply-fresh-workdir]]);int8 走真 int8_tc(im2col+MMA,非 fake);前沿候选补真 AP(DAIR val n=1789,收敛 finetune,AP70 主 + w0 特征)。
3. **回流**:pred vs actual → 重训 cost model → 推进实测 Pareto。
4. 迭代至预算耗尽/空间穷尽。

**终止**:实测 Pareto = 全实测点(180 冷启动 + 真测新点)非支配集,取 AP max / lat min / energy min 三极值点。

- **CoDriving/F-Cooper/AttFuse**:**不假设统一 7³**。真实可搜轴数(k)+ 每轴档数由 2.1 spacecard 逐模型落定,空间 = ∏档数 × 3 精度,可建性掩码剪。CoDriving 冷启动 12-anchor 用的是**全局剪枝标尺 {base,p25,p50,p75}(1 维)× 3 精度**,是探针参数化,**不等于生产搜索的 k 维宽度空间**——两者别混。
- **2.1 验收动作**:每个验收模型跑 `autoscan` + `bridge`,把该模型 **真实可搜轴数 k / 每轴 width_grid / 空间大小 ∏×3 / separable** 打印落盘 `results/phase2_<model>_spacecard.json`,**用户查这张 spacecard 即可确认 AutoScan 生效 + 空间到底多大(不再是我拍的数)**。

### 4.2 【2.1 续】冷启动数据集补点方案(★补多少、怎么分布)

**方法论**(§3.3.4):不穷尽,只给 cost model 初始硬件信号 + 让它学到该模型 **latency/AP 随剪枝×量化的趋势**;跨模型冷启动预测器已证 **12 anchor 即把 AP70 MAPE 从 53.9%→5.2%**(LOO)。

**已有基线**:
- Pyramid-LiDAR:180-LUT(60 宽度 × 3 精度),充分。
- **CoDriving:12-anchor 已建**(`results/codriving_12anchor_pxq.json`),分布 = 剪枝 {base, p25, p50, p75}(4)× 精度 {fp32, fp16, int8}(3)= **4×3 干净 P×Q 网格**,MAPE 5.2%。

**每个新模型(camera-Pyramid / F-Cooper / AttFuse)补点方案** —— 复刻 CoDriving 已验证的 12 点最小集:

### 4.3 【2.2】int8 / fp16 TVM 真加速打通(每模型)

> **旧错误**:本节把 **TensorRT 当"外部基线 vs 厂商编译器"**、并设"我们前沿**支配** TRT / speedup vs TRT"列。这是**层次错配**:TRT/TVM/AutoTVM 都是**后端(可互换黑盒),不是同层对手**。拿"我们前沿(TVM 后端)"去"支配 TRT"会**把选择贡献与后端性能混淆**(朴素配置跑在快后端上可能反超我们好配置跑在慢后端上)。
> **正确设计(见 13_7_14)**:核心命题 = **软硬件协同 + 多目标搜索有效**,分两实验:**实验一(协同有效性,双后端 TVM&TRT)** = 9 臂(原始 / pruning-only / quant-only / prune+quant无S / 仅调度 / 串行compress→tune / 串行tune→compress / FLOPs驱动 / **ours 协同+多目标**),证 ours 前沿跨两后端支配所有非协同/串行臂(串行两序都劣 = 贪心陷局部最优);**实验二(组件消融,单后端)** = surrogate / 闭环反馈 / NSGA-II vs 固定权重 + 超参(预算/轮次)。TVM+TRT 是**两台秤做跨后端泛化非对手**;搜索空间只用描述表(~1029)不做实验。TVM-逼近-TRT(`12_7_14` 组合税)= 独立"开放后端"线不承担主结论。**13_7_14 附两张待填空白结果表。**
> 下面 5.1–5.3 的三臂消融机(joint/serial/noS)与执行命令仍有效,但**对比阵列的后端定位以 13_7_14 为准**。

### 5.1 对比阵列(一张主表统管 baseline + 消融)

在**同 RSU-感知 scope + 同硬件(H800 空闲卡)+ 同 batch + 同 AP 口径**下,每条取其最优点:

| 类别 | 方法 | 定义 | 隔离出的价值 |
|---|---|---|---|
| 外部基线 | **Default** | TVM 默认 dlight,不搜 | 未优化地板 |
| 后端(非对手) | **TensorRT** | 一台"秤"(封闭后端);用于 🅱 跨后端泛化,**不作被支配的对手**(见 13_7_14) | 证优势跨后端成立,非后端伪影 |
| 外部基线 | **AutoTVM** | 固定软件配置(base 宽/fp16)只调度 | vs 标准自动调优(无 P×Q 协同) |
| **消融臂** | **compression-only**(=A-noS) | 搜 P×Q,S 恒 default 不给调度反馈 | **调度协同 S 的价值** |
| **消融臂** | **serial**(=A-serial) | 先 fp16/default 锁宽度,再在锁定宽度上调 schedule×quant | **联合 vs 串行的价值** |
| **本文** | **SHCoSearch**(=A-joint) | P×Q×S + 实测反馈联合 | 完整方法 |

- **公平红线**:所有条目最终 AP/lat/energy 同口径真测;跨模型只比 speedup + HV,不比绝对 ms(§2)。
- **AutoTVM 与 compression-only 的区别**(勿混):AutoTVM = 在 **base 模型**上只调 schedule(不动 P/Q);compression-only = 搜 **P×Q** 但用 default schedule(不搜 S)。前者隔离"协同 vs 纯调优",后者隔离"S 轴价值"。

### 5.2 执行计划(每模型)

1. **建 AutoTVM 基线**:对 base 软件配置(未剪/fp16)跑 AutoTVM 标准调优,取其最优 latency;同一 base 也测 TRT + Default。→ 三个外部基线点。
2. **跑三臂**:`python -m framework.run_pqs_ablation --seeds 12 --budget 60 --pop 8 --manifest <model>`(喂该模型 Phase 2 的 spacecard/LUT),产 joint/serial/noS 三臂各 12 seed 的前沿。
3. **取最优点 + 统计**:每方法 iso-AP 下 min-latency(或 HV);三臂间 Wilcoxon signed-rank(已在 `run_b4_ablation` 实现)出 p 值。
4. **对齐真测**:各方法最优点的 AP/lat/energy 用 §2 口径复测确认(不用 surrogate 值报最终结果)。

## 9. 纪律(贯穿)

1. **RSU 感知 scope 统一**:所有模型优化对象 = RSU 端感知主干,同后端/同卡/同 batch;跨模型只比 speedup(6_7_14 纪律)。
2. **最终 Pareto 真测**:AP/lat/energy 目标硬件真测(§3.4);surrogate/proxy 只进搜索内环不进正文坐标。
3. **fresh-tune 纪律**:内层 TVM 真调优必 fresh workdir + 逐宽度独立进程,验收看 ratio<1。
4. **TVM 非 TRT**:TRT/AutoTVM 仅 Phase 3 baseline,明确标注 deployment/schedule-only baseline。
5. **AP 轴按定论**:收敛→AP70 主;固定预算→AP80@budget-capped(标 recoverability);闭环用 collision rate + curated 路由 + N≥30。
6. **实测独占卡**:lat/energy 用 util0%/mem≤50MiB 空闲卡;AP finetune 可共卡避高负载卡([[feedback-gpu-sharing-ap-vs-latency]])。
7. **核验纪律**:agent 自报必主控复跑/读文件核验;交付物必落共享 fs + 独立 stat 核([[feedback-agent-bash-sandbox-overlay]]);单编排不越权起/杀 worker。
