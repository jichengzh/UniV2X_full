## §0 核心立场(接手先读)

1. **贡献层 = 硬件反馈引导的 P×Q(×S)联合选择 + 多目标(NSGA-II)选点**;交付 = 选出的配置。
2. **后端(TVM/TRT/AutoTVM)= 可互换黑盒"秤",不是对手**。"TVM vs TRT 谁快"非本文命题;拿"我们前沿(某后端)去支配 TRT"= 把选择贡献与后端性能混淆,禁止。
3. **实验一在 TVM 与 TRT 两个后端各跑一遍**——不是让两后端互比,而是证"**无论用哪个后端,协同+多目标都优于各种非协同/串行/单轴方案**",即协同有效性跨后端成立。
4. **实验二只需单一后端**——证框架内部各组件(surrogate / 闭环反馈 / NSGA-II)必要。
5. **AP 走 gold 协议**(finetune 真测,不跨 PTQ-vs-finetune 栏),AP 轴用 **AP70**([[project-ap-axis-final-verdict]])。
6. **口径铁律**:同 {device, scope, shape, batch, precision}。**backbone-only 0.907ms(H800)≠ collab2-body 1.269ms(4090)**——scope+device 双重不同,严禁混比(见 `12_7_14` §9)。

## §1 实验一:软硬件协同 + 多目标搜索有效性(双后端 TVM & TRT)

### §1.1 臂设计(6 臂,聚焦"协同" —— 已删单轴 Pruning-only/Quant-only 与 FLOPs 驱动臂,见 §1.5)

| # | 方法(Arm) | P(剪枝) | Q(量化) | S(调度) | 隔离证明 |
|---|---|:-:|:-:|:-:|---|
| 1 | **原始模型** default prec + default schedule | ✗ | ✗ | default | 上界锚 |
| 2 | **软件压缩-only**(Prune+Quant)+ default backend | ✓ | ✓ | default | 软件压缩全开但**无调度协同**(=A-noS) |
| 3 | **硬件调度-only** 原始模型 + compiler tuning | ✗ | ✗ | ✓tune | 只调度不压缩 |
| 4 | **串行:先 compress 再 tune** | ✓ | ✓ | 后调 | 串行贪心 → 局部最优(=A-serial) |
| 5 | **串行:先 tune 再 compress** | 后压 | 后压 | 先调 | 另一串行序,证**序无关都劣于联合** |
| ★6 | **ours 协同联合 + 多目标** P×Q×S 联合搜 + NSGA-II | ✓ | ✓ | ✓联合 | 本文 |

- **臂 4/5 是"串行会因贪心陷局部最优"的核心证据**:先压后调 / 先调后压两个序都应劣于联合(joint),证明**必须联合搜、不能分步贪心**。
- **臂 2(压缩-only,无 S)vs 臂 3(仅调度)vs ours**:证协同 = 压缩与调度必须一起搜,单开任一维都不够。

### §1.2 判据
- **ours 前沿在 (AP70, latency) 与 (AP70, energy) 上支配臂 1–5 的最优点**(支配数 + HV + iso-AP@{1,2,5%} 的 lat/energy speedup + Wilcoxon p)。
- **协同跨后端成立**:在 TVM 与 TRT 两个后端上,ours > 各非协同/串行臂**都成立**(证协同有效性非某后端伪影)。

### §1.6 对比臂实验设计(★框架一致,2026-07-06 重写)

#### A. 之前"三臂消融"到底怎么做的(机制真相)

旧三臂消融 = `framework/search_three_arm.py`(≠ 框架 SMBO)。三臂都是 NSGA-II,但:
- **joint (A-joint)** = NSGA-II over (width × schedule × quant),decode(g)=(width_grid[g0], SCHEDULES[g1], QUANT[g2])。
- **serial (A-serial, compress→tune)** = **两阶段** NSGA-II:stage1 只搜 width(在 **default 调度 + fp16** 下,budget×0.5)→ 锁定 stage1 的 Pareto 宽度集;stage2 在**锁定宽度上**才搜 schedule×quant。
- **noS (A-noS, 压缩-only)** = NSGA-II over (width × quant),schedule **固定 default**(不调优)。

**用的空间 = `candidate_widths_pqs` 只有 9 个粗宽**:`[(16,32,64),(32,64,128),(48,64,256),(48,96,192),(48,128,128),(64,64,256),(64,96,192),(64,128,128),(64,128,256)]`。**用的 LUT = `results/latency_lut_pyramid.json`(gap1_grid,1000-trial 深度调优,且对齐/错位宽来自不同预算的混合来源)**。

#### B. 为什么它不能直接进本表(两处不一致)

1. **空间不一致**:9 宽粗格 **不含框架前沿的非对角点**(`[24,32,96]` 等根本不在里面)→ 消融的 joint 也到不了我们真前沿,serial/joint 都被困在粗格里比。
2. **regime 不一致**:消融 LUT 是 **1000-trial 深调优**(p75 tuned 0.484ms,比 TRT 还快=可疑;48-错位宽 21ms 来自混合来源);而**框架真前沿是轻调优**(measure_config 复用 original60 DB,p75=1.625ms)。**两个 regime 混用 → 3.827× 陷阱是 regime 假象,不是框架结论。**

⇒ **旧三臂消融的 HV(100/85.3/56.7)、Wilcoxon p=4.88e-4、3.827× 陷阱,都不能作为本表(实验一)的证据。** 必须在框架 regime 重跑。

#### C. 每个对比臂的框架一致实验设计(统一:1029 空间 + 轻调优 corpus LUT + 同 SMBO/NSGA-II 内核 + 同 iso-AP 度量)

| 臂 | 搜索脚本/约束 | 空间 | 调度(S) | 量化(Q) | 预期结果 |
|---|---|---|---|---|---|
| **原始** | 无搜索,单点 | base [64,128,256] | default(未调优) | fp16 | 56.2ms@0.631(慢锚) |
| **调度-only** | 无搜索,单点 | base 固定 | **auto-tune** | fp16 | 6.52ms@0.631 |
| **压缩-only(no S)** | SMBO NSGA-II,**S 锁 default** | 1029 全 | default | 搜 int8/fp16 | 前沿远慢于 ours(int8 在未调优下无 tensorize 收益)→ 被 ours 支配 |
| **串行 compress→tune** | 两阶段:stage1 SMBO 搜 width(AP-proxy/default+fp16)→锁;stage2 在锁定宽搜 tune×quant | 1029 全 | stage2 tune | stage2 int8 | **关键验证点**:stage1 不看真实 tuned+int8 延迟,大概率锁到非 [24,32,96] 的宽(如对角/AP-proxy 优先宽)→ 错过平衡点,iso-AP 下慢于 ours |

| **★ours(joint)** | 框架 SMBO joint NSGA-II | 1029 全 | joint tune | joint int8 | **[24,32,96] 1.779ms@0.594**(已真测,前沿在册) |

**执行步骤(可复跑)**:
1. **建轻调优 LUT**:用 original60 corpus + 本轮 fresh 测量(全 [128,256] 轻调优)组一张 `latency_lut_pyramid_lighttune.json`(default_us + tuned_us + int8 可建性/比率,per 1029 宽)。缺的宽用 `measure_config` 补测(独占空闲卡,~70s/点)。
2. **同内核跑,★需重搜的臂共 3 个搜索臂**:改 `search_three_arm.py` 的 `width_grid=1029`、LUT=轻调优版,复用现有 `run_*_pqs` 跑:**① 压缩-only(P×Q,S=default)=`run_noS_pqs`;② 串行 compress→tune=`run_serial_pqs`;③ 串行 tune→compress=serial 反序(需加 stage1=tune-base、stage2=width×quant 的变体)**。joint 已有真前沿(可复用/复跑校验);"调度-only/原始"为单点无需搜。同 budget、同 seed×多 seed。
3. **iso-AP 度量**:各臂前沿在 AP70∈{0.55,0.59,0.63} 处取 min-lat,算 ours/臂 的 speedup;支配数;HV;ours-vs-serial 多 seed Wilcoxon。
4. **闭合 off-diagonal AP**:对 ours 前沿的非对角点([24,32,96] 等)做 gold finetune(DAIR val 1789,AP70),把外推 AP 换成真测,确认平衡点。
5. **保证性检查(回答"框架一定到达该点")**:joint 已证到达 [24,32,96];serial 跑完后核验其 stage1 锁定宽是否含 [24,32,*],若不含即证明 serial 结构性错过 → ours 严格更优的直接证据。

- **核心**:ours 在 4 个模型(Pyramid grouped / CoDriving 标准 / F-Cooper / AttFuse)上**都**取得协同优势 → 证方法**跨 ResNet 家族普适**(标准 conv ↔ 分组 conv)。
