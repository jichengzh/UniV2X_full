## 0. 定位:Phase 2 要干什么

Phase 1 已证:方法正确(联合 NSGA-II 可 scale)、真前沿=对角线、baseline=**random-search** 背书(HV nsga2>random 100%)。
**但 random-search 是"内部弱 baseline"**。要让审稿人信服,必须拿**工业级/SOTA 框架(TensorRT、AutoTVM)当外部强 baseline**,证明我们的 co-design 搜索产出的 Pareto 打得过"把模型直接丢给现成优化器"。这就是 Phase 2.A。

---

## 1. ★TRT 纪律澄清(必读,否则会与项目铁律冲突)

项目铁律"**框架 = TVM 非 TRT**"针对的是 **用 TRT 作优化后端 / 作前进方向**(legacy TRT 数据只作历史)。
**本 Phase 用 TRT 作对比 baseline(要打败的对手),是证明方法有效的正道,不违背铁律**:
- 我们方法的**后端仍是 TVM**(dp4a/WMMA 张量化);
- TensorRT / AutoTVM 是**被比较对象**,不是我们采用的后端;
- 结论若"our-TVM co-design ≥ TRT",正好坐实 TVM 路线 + co-design 的价值。

---

## 2. 要证明什么(叙事骨架)

**贡献** = joint co-design **SEARCH**(width × precision,AP/lat/energy 三目标 Pareto,surrogate-assisted,TVM 后端)。
**有效性 = 两个层级都要赢/不输:**

| 层级 | 命题 | 为什么必须做 |
|------|------|------|
| **L-A 后端质量(iso-config)** | 固定架构下 our-TVM-tuned 与 TRT / AutoTVM **同量级**(不显著慢) | 否则"我们赢"可能只是因为后端弱,不成立 |
| **L-B co-design 价值(主结果)** | our Pareto front **支配** off-the-shelf 单点(TRT-auto / AutoTVM-base) | 这才是方法贡献:搜 width×precision 能到现成优化器够不到的 lat/energy |
| **内部消融(必要性)** | 联合 P×Q×S **> 串行 > 无 S**(§4.D) | 证明联合设计不可拆:串行/缺轴会系统性错过最优 |

> **完整有效性 = 三块**: L-A(后端不弱)+ L-B(打得过现成框架)+ 消融(联合设计必要)。缺一块论证都有洞。

**关键洞察(叙事核心)**: TRT / AutoTVM 优化的是**固定架构的 schedule/精度**,**不搜 width**。我们靠 co-design 缩 width(Pyramid 过参数化下近无损 AP)能降到它们**物理够不到**的 lat/energy 区间 —— 这是 co-design 相对 off-the-shelf 的结构性优势。

## 3. 对比框架清单(baseline 矩阵)

| 框架 | 优化层级 | 是否搜 width | 精度策略 | 角色 |
|------|---------|-------------|---------|------|
| **TensorRT** (FP16 / INT8-PTQ) | 后端 + 逐层 auto 精度 + 融合 | ❌ | TRT 自选(延迟驱动) | 工业标准 off-the-shelf baseline |
| **AutoTVM / Ansor** | 后端 schedule autotune | ❌ | 固定(给定 fp16/int8) | TVM 系 SOTA autotuner(同后端,对照**搜索策略**) |
| **TVM-default(untuned)** | 无 tune | ❌ | 固定 | 下界参照 |
| **PyTorch-eager / ONNX Runtime**(可选) | 无/图优化 | ❌ | 固定 | 更多 off-the-shelf 对照 |
| **our co-design(joint NSGA-II + TVM tune)** | **搜索 width×precision + 后端 tune** | ✅ | **AP/lat/energy 三目标** | 我们 |

> ⚠️ **AutoTVM 的定位要说清**: AutoTVM/Ansor 是 **schedule(s 轴)autotuner,与我们同后端(TVM)**。所以"our vs AutoTVM"**不是搜索策略对搜索策略**(AutoTVM 不搜 width),而是:①在 iso-config 下比后端 tune 质量(L-A);②AutoTVM 本可作为我们内层 s 轴 tuner 的一种(未来可换)。真正对照我们**搜索策略**的是 random-search / 单轴 / TRT-auto。

## 4. 实验设计(Phase 2.A,Pyramid-LiDAR,全 H800 真测)

### 4.A L-A — 后端质量(iso-config,证后端不弱)
- 固定 **base Pyramid width**,精度 fp16 & int8(int8_tc),**同 input shape / 同 H800 空闲卡 / 同 warmup+iters**。
- 测 latency(p50):`our-TVM-tuned` vs `TRT` vs `AutoTVM/Ansor` vs `TVM-default`。
- **判据**: our-TVM 与 TRT **同量级**(比如 ±15% 内),证明胜不是靠后端弱。

### 4.B L-B — co-design 价值(主结果)
- **our Pareto front**(Phase 1 canonical:对角 int8_tc/fp16)vs:
  - `TRT-auto` 单点(base width,TRT 自选精度 + INT8-PTQ)
  - `AutoTVM-base` 单点(base width,fp16 与 int8 各一)
- **判据(量化)**:
  1. **iso-AP latency/energy speedup**: 同 AP 下 our 最优 lat/energy vs baseline(期望 our 更低,因 width shrink)。
  2. **支配关系**: baseline 单点是否落在 our front 的被支配区。
  3. **hypervolume**: HV(our front) vs HV(baseline 单点集)。
  4. **可达区间**: our front 有 baseline 物理够不到的低 lat/energy 点(width<base)。

### 4.C 口径统一(强制,否则对比无效)
- 同 GPU(H800 空闲卡 util0%/mem≤50MiB)、同 input shape、同 warmup/iters、同 timing 方法。
- **AP 公平**: TRT-INT8 = PTQ(无 finetune),our-INT8 = 有 finetune → AP 不可直接比。方案:**要么两边都 PTQ、要么两边都 finetune**,或明确分栏标注(PTQ-AP vs finetune-AP)。gold 协议 eval 双方。
- 全真测,逐点标源(TRT python API 10.13 / AutoTVM / Ansor / our measure_config)。

### 4.D 内部消融实验(两个 — 之前遗漏,与外部对比互补)

外部对比(L-A/L-B vs TRT/AutoTVM/Ansor)证明"**我们打得过现成框架**";
内部消融证明"**我们的联合设计(P×Q×S 联合搜索)是必要的**"——串行/缺轴优化器会系统性错过最优。两个消融(均对照 full **A-joint-PQS**):

| 消融臂 | 定义 | 证明的价值 | 已有 proxy 结果 |
|--------|------|-----------|----------------|
| **compression-only**(=A-noS) | 搜 P×Q,**S 恒 default,不给调度反馈** | **调度协同 S 的价值**(有 S vs 无 S) | HV **56.7%** |
| **serial**(=A-serial) | 先 fp16/default **锁宽度**,再在锁定宽度上调 schedule×quant | **联合 vs 串行的价值**(串行锁死 int8-不可建 misaligned width,够不到 aligned P_g 的 int8 路径) | HV **85.3%** |

- 已有 proxy 结果: `framework/run_pqs_ablation.py`,A-joint **100%** / A-serial 85.3% / A-noS 56.7%,Wilcoxon **p=4.88e-4**([[project-three-arm-ablation-results]] / [[project-codesign-nextstage-v3]])。
- **Phase 2 要做的**: 把这两个消融从 proxy-LUT(`UNIFORM_INT8_SPEEDUP=1.449` 代理)**升级到 2.A 真测口径**(H800 真 lat/energy + 真 int8_tc),让内部消融与外部对比同口径。
- 位置: 与 L-A/L-B **并列作 2.A 第三块结果(内部必要性)**;三块合起来 = 完整有效性论证(打得过现成 + 联合设计必要)。

### 4.E ★公平性保证(专章 — 用户要求)

对比可信度全靠口径公平。本章列明**核心张力处理 + 不变量 + 已知陷阱**。

#### E.1 核心张力:我们的前沿点没有穷尽 TVM 搜索(用户指出)
- **事实**: Phase 1 前沿点用 `measure_config`(复用 original60 tuned DB,~70s/点),**不是**对每点穷尽 AutoTVM/Ansor 全量 tune → **our-TVM 的 latency 是上界(tune 更久可能更快)**。
- **对 L-A(后端质量)**: 声称"our-TVM ≈ TRT"必须 **tuning 预算对等**:
  1. base-width ONNX 上,**our-TVM 与 AutoTVM/Ansor 用同一 tuning 预算**(同 trial 数 / 同 wall-clock),显式记录。
  2. TRT 用其**默认 builder 优化**(实践者拿到的即此;TRT 内部 tactic 选择 ≈ 一次有界 auto-tune),标 "TRT-default builder"。
  3. 每个数标 **tuning 预算来源**,绝不拿"轻调 TVM"比"全调对手"或反之。
- **对 L-B(co-design 主结果)**: our 前沿用标准 measure_config 预算;**若仍支配 baseline = 保守结论**(更久 tune 只会让我们更好)→ 图注显式写明"under-tuned 只低估我们不高估"。
- **可选加强**: 对 3 个极值前沿点补一次**全量 Ansor tune**,证明"even 全调后相对关系不变",堵死"欠调导致胜负"质疑。

#### E.2 不变量(所有框架、所有点强制一致)
| 维度 | 统一规定 | 防的历史陷阱 |
|------|---------|-------------|
| **input shape** | 全框架统一 = **[128,256]**(与 Phase 1 前沿口径一致) | fp16@256² vs int8@128² 双重不公([[project-precision-axis-double-unfairness]]) |
| **device** | H800 同一张**空闲卡**(util0%/mem≤50MiB **独占**) | GPU 共卡污染 lat/energy([[feedback-gpu-sharing-ap-vs-latency]]) |
| **batch** | 全框架同 batch | batch1 vs batch2 口径错配([[project-latency-caliber-crossmodel-noncomparable]]) |
| **scope(计时边界)** | 全框架同一子图(backbone-subnet,声明并锁定;不混 e2e) | 未优化 TVM(subnet)vs 优化 TRT(body)=100× 测量假象([[project-latency-caliber-crossmodel-noncomparable]]) |
| **int8 张量化** | 两边都上 tensor core:TRT int8 用 tensor core;ours 用 **int8_tc**(WMMA/dp4a)**非 native SIMT** | SIMT int8 比 WMMA fp16 慢 2× → 颠倒 fp16/int8 序 |
| **timing 方法** | 同 warmup + iters + CUDA event(TVM/TRT 同一 harness 逻辑) | timing 口径漂移 |
| **energy** | 同 NVML 采样口径(J/frame) | 能耗口径不一 |
| **tune workdir** | fresh workdir per width per process | 单进程复用撞名残缺 db → 假 ratio≈1.0([[feedback-tvm-tune-apply-fresh-workdir]]) |

#### E.3 AP 公平(分栏,已定)
- TRT-INT8=PTQ → **PTQ-AP 栏**;ours-INT8=finetune → **finetune-AP 栏**;**不跨栏比大小**。
- 两边 AP 都走 **gold 协议 eval**(DAIR val1789,PyTorch inference.py,**非 buggy subnet 管线** [[feedback_verify_ap_via_eval_yaml]])。
- 主结果看 (lat,energy) 支配;AP 作约束/分栏参考。

#### E.4 核验纪律
- 所有"已 build/已测"自报必**复跑/读文件/stat 核验**(防 sandbox overlay [[feedback-agent-bash-sandbox-overlay]]);数值必真读不从报告推断。
- 交付落共享 fs + 独立 stat + 数值真读。

## 5. 风险与前置(必须先解决)

| 风险 | 说明 | 应对 |
|------|------|------|
| **TRT 环境** | 对比须与我们 TVM 同硬件(H800)才公平;H800 是否有可用 TRT(10.x)未知 | 先探 H800 有无 TRT;无则搭(setup 成本)或明确改在有 TRT 的 4090 + 标硬件差 caveat |

| **口径漂移** | 三框架各自 timing | 统一 harness + input + warmup |
| **过参数化** | Pyramid AP 轴弱,L-B 的"iso-AP"区分度低 | 主打 (lat,energy) 支配 + width-shrink 可达性;AP 作约束轴 |

## 10. ★决策已拍板(2026-07-05 用户确认)

1. **对比框架集 = {TensorRT(FP16/INT8-PTQ), AutoTVM, Ansor, TVM-default, ours}**。加 Ansor(TVM auto-scheduler,比 AutoTVM 更新)作更强 TVM 系对照。

4. **gold-AP cost model 增强(§6)= 不阻塞 2.A**(默认并行/留 2.B;AP 轴弱不影响 L-A/L-B 的 lat/energy 主结果)。
