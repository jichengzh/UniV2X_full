## 1. 本文边界

本文只回答两个问题：

1. Gold176 相对 Gold144 是否改善了 cost model 所需的数据充分性、排序、迁移、Pareto 选择和不确定性质量。
2. 当前 cold-start 数据能否锁定并进入阶段 4 的 cost-model/loss 选择。

本文不通过更换模型或放宽阈值来制造“改善”。Gold144 与 Gold176 首先采用同一诊断协议比较新增数据的边际作用；执行后发现原 locked holdout 已参与补点决策，因此该集合只能保留为历史诊断集，不能继续充当最终无偏收口集。

## 2. Gold144 的实测问题

Gold144 包含 144 行、36 个完整四臂组，其中 30 组训练、6 组 locked holdout。其最后一次严格评估结论为 `targeted_supplement_required`。旧报告中只有 learning plateau 和 `global+K` 优于 global-only 两项通过，其余关键门禁未通过。后续复核发现旧 `26 -> 30` plateau 的 4 个新增组全部来自 Pyramid，因此它只能说明 Pyramid 扩展未继续改善，不能解释为两模型共同的全局平台期。

| 门禁 | Gold144 v4 | 固定阈值 | 结果 |
|---|---:|---:|---|
| learning plateau | 三个目标末段 MAE 改善均不超过 5% | 全部 `<= 5%` | 通过 |
| grouped ranking | AP70 `rho=0.875/top-k=0.500`；latency `0.929/0.708`；energy `0.818/0.819` | 每头 `rho>=0.90` 且 `top-k>=0.75` | 失败 |
| `global+K` 优于 global-only | 24/24 | 24/24 | 通过 |
| `global+K` 优于 local-only | 3/24 | 至少 16/24 | 失败 |
| measured Pareto recall | mean `0.809`，p10 `0.367` | p10 `>=0.80` | 失败 |
| HV regret | mean `0.0627`，p90 `0.2979` | p90 `<=0.10` | 失败 |
| 90% prediction interval | 最低逐行 coverage `0.833`；最低整组 coverage `0.333` | 两者均 `>=0.80` | 失败 |

因此，Gold144 的主要问题不是“行数没有达到某个整数”，而是：

1. AP70 和 energy 的组间排序不稳定，latency 的 top-k 也未过线。
2. 全局趋势虽然能修复 global-only 的跨模型尺度偏差，但尚未稳定优于目标模型 local-only。
3. Pareto 尾部召回和 HV 尾部损失较差，说明失败集中在少数边界区域，而不是平均误差。
4. 预测区间能覆盖多数单行，但不能同时覆盖一个 width 的完整四臂组。

## 3. 为什么从 Gold144 补到 Gold176

新增数据不是均匀随机扩容，而是在读取 Gold144 sufficiency 报告后、测量前冻结的 8 个 failure-boundary 组。每组完整测量 `(TVM FP16, TVM INT8, TRT FP16, TRT INT8)`，共 32 行。

| 模型 | width | 冻结时的补点原因 |
|---|---|---|
| Pyramid | `24x32x64` | 小宽度 TRT/Pareto 排序边界 |
| Pyramid | `40x96x192` | 中大宽度 latency/energy 区间边界 |
| Pyramid | `56x128x256` | 大宽度 TVM 外推边界 |
| Pyramid | `64x128x224` | stage-2 AP/latency 边界 |
| CoDriving | `48x64x192` | 中宽到大宽 Pareto bridge |
| CoDriving | `48x96x128` | 跨 shape 模型分歧区域 |
| CoDriving | `48x32x128` | 小宽度 TRT-INT8 Pareto bridge |
| CoDriving | `64x64x192` | 大宽度 TVM latency/energy bridge |

新增数据的预期作用是补齐高分歧、高不确定度和 Pareto 边界，而不是增加跨模型完全相同的 width。Gold176 仍只有两个模型，因此本轮最多证明双向迁移 pilot 和当前搜索空间内的数据充分性，不能宣称普适跨模型泛化。

## 5. 同协议有效性验证

### 5.1 冻结项

以下内容必须与 Gold144 v4 保持一致：

1. 原 6 个 holdout 组及其四臂证据不得改变；本轮只用于 Gold144/Gold176 历史同口径诊断，不再作为最终独立 holdout。
2. capability profiles、相对目标定义、模型类型和特征口径不变。
3. `K=2/4/6/8` 双向 few-shot transfer 协议不变。
4. 比较 `raw absolute target` 与 `relative/residual target`，主合同仍为 `relative + ExtraTrees + global_plus_k_residual`。
5. Pareto、HV 和 regret 先在模型内计算。
6. feasibility failure 不填零，不进入 value-head 回归。

### 5.2 新增项

1. 为全部 44 个 group 重新生成 graph features，禁止沿用缺少 8 个新增组的 Gold144 特征表。
2. learning curve 使用 `6/12/18/24/28/30/32/34/38` 个训练组。`32 -> 34` 是每个模型各增加一组的平衡增量；`34 -> 38` 单独标记为 Pyramid extension，不再伪装成全局增量。
3. 输出 Gold144 v4 与 Gold176 的逐门禁差值，不能只给 Gold176 单点结果。
4. 保留相同随机种子、重复次数和 bootstrap 次数，避免把随机波动当成补点收益。

### 5.3 固定收口门槛

Gold176 仍使用 Gold144 的严格门槛：

```text
learning plateau:
  三个目标的 balanced 32 -> 34 MAE 改善均 <= 5%
  三个目标的 Pyramid extension 34 -> 38 MAE 改善均 <= 5%

ranking:
  每个目标 Spearman >= 0.90 且 top-k recall >= 0.75

few-shot transfer:
  global+K 优于 global-only = 24/24
  global+K 优于 local-only >= 16/24

selection:
  Pareto recall p10 >= 0.80
  HV regret p90 <= 0.10

uncertainty:
  90% interval 最低逐行 coverage >= 0.80
  90% interval 最低整组 coverage >= 0.80

measurement:
  inherited evidence repeat audit qualified
  Gold176 新增边界点 repeat audit qualified

evaluation independence:
  最终 holdout 未参与候选选择、acquisition、模型选择或阈值调整
```

只有全部门禁通过，才能输出 `lock_gold176_for_stage4`。

## 6. 结果解释与后续分支

### 6.1 全部门禁通过

阶段 3.5 收口：冻结 Gold 数据、manifest、graph features、capability profiles、验证脚本和结果 SHA；阶段 4 可以开始 cost-model/loss 选择。除数值门禁外，必须已有未被 acquisition 使用的独立 holdout，且新增边界点具有 repeat audit。此结论仅适用于 Pyramid、CoDriving、H800 及当前 TVM/TRT capability contexts。

### 6.2 learning curve 未平台化

说明有效组数仍不足。下一批只补高不确定度和模型分歧最大的完整四臂组，禁止均匀扩容；补点数量由末段学习曲线决定。

### 6.3 ranking 或 Pareto/HV 未通过

先区分数据稀疏与特征不足：

1. 若新增 8 组在失败 slice 上明显改善，则沿相邻 Pareto 边界补完整组。
2. 若训练规模增加但指标不改善，审查 graph descriptors、AP-sensitive shape 特征和 pairwise/ranking objective；此时不能继续盲目加同类数据。

### 6.4 `global+K` 仍不优于 local-only

说明两模型的可迁移共享趋势不足，或 residual calibrator 没有利用全局先验。优先增加跨模型共同 width 或第三模型，并把 local-only 作为强基线；不得仅因优于 global-only 就宣称迁移成立。

### 6.5 prediction interval 未通过

若点预测已经稳定而区间失败，优先修复 group-aware/conformal calibration，并补跨时段重复锚点估计异方差；不把区间问题误判为必须继续扩大 value-head 数据。

## 10. 验证有效性反思

### 10.1 原 holdout 已发生 adaptive reuse

Gold176 candidate plan 明确绑定 Gold144 sufficiency report 的 SHA，并且多个 `failure_boundary` 直接引用原 holdout width：`24x32x96`、`40x80x160`、`64x128x256`。这意味着补点 acquisition 使用过原 holdout 的失败信息。

结论：

1. 当前 6 组没有发生行级 train/test 混入，但统计意义上的独立性已经失效。
2. 本轮 Gold144/Gold176 对照仍可用于诊断新增数据是否改善旧失败 slice。
3. 不能再用同一 6 组完成最终阶段 lock 或论文级泛化声明。

### 10.2 repeat audit 只覆盖继承证据

当前 `inherited_repeat_audit_qualified=true` 只说明旧 Gold128/Gold144 锚点的重复测量合格。Gold176 新增 8 组没有独立跨时段 repeat，因此报告将其记为：

```text
gold176_supplement_repeat_audit_qualified = null
```

在新增边界点 repeat audit 完成前，验证器不能输出 `lock_gold176_for_stage4`。

### 10.3 `global+K` 失败不是纯数据量结论

`global+K` 已稳定优于 global-only，但只在 4/24 个任务上优于 local-only。该门禁同时受数据覆盖、relative target、residual calibrator 和模型容量影响，不能靠继续堆同类点解决。下一轮需要把“共享趋势证据不足”和“当前 calibrator 设计不足”分开验证。

## 11. 阶段结论与解决方案

### 11.1 是否解决 Gold144 问题

部分解决，但未完全解决：

1. AP70 和 energy 排序已单头过线。
2. Pareto/HV 尾部与区间覆盖显著改善，但仍未过严格阈值。
3. latency top-k、Pyramid latency plateau 和 `global+K` 对 local-only 仍是主要缺口。
4. 原 holdout adaptive reuse 与新增点无 repeat 使当前结果不具备最终 lock 资格。

### 11.2 阶段 3.5 是否收口

**不收口。** 该决定同时由数值门禁失败和证据独立性不足支持，不是只因为某一个阈值略低。

### 11.3 下一步解决路径

P0：先修正评估设计，不立即盲目补点。

1. 将原 6 组重标为 `adaptive_validation_v1`，只保留历史诊断用途。
2. 对当前 44 组运行 nested grouped CV，内部评估 learning、ranking、Pareto/HV 和 interval，候选选择只能读取 inner validation。
3. 在任何新测量前，按静态结构分层冻结新的独立 holdout；其选择不能读取 latency/AP/energy、模型误差或 acquisition score。

P1：训练补点只针对已定位缺口。

1. latency：在 inner-CV 的 latency top-k 分歧和 Pyramid 大宽度边界补完整四臂组，直到平衡增量与模型内增量均 `<=5%`。
2. transfer：优先增加 Pyramid/CoDriving 共同 width 或静态特征近邻 pair，检验 global shared trend，而不是继续补彼此不重合的单模型边界。
3. Pareto/HV：只补 inner-CV 中反复出现的 frontier miss/high-regret 区域，不再读取旧 holdout 选点。

P2：区间与重复性单独解决。

1. 使用 group-aware/conformal calibration 解决“单行覆盖高、整组覆盖低”。
2. 至少选择新增边界中的 latency、Pareto、alignment、large-width 四类锚点跨时段复测。
3. interval 失败不能自动触发 value-head 均匀扩容。

P3：最终收口顺序。

```text
nested grouped CV 证明训练数据进入平台
-> 冻结 cost-model/loss/calibrator 候选
-> 完成新增边界 repeat audit
-> 一次性运行新的独立 holdout
-> 全部门禁通过后锁定阶段 3.5
```

## 12. 时间预算与阶段 4 并行推进决策

### 12.1 cold-start 的实际目的

Gold176 不需要在闭环开始前成为高精度最终预测器。当前 cold-start 的职责是：

1. 给第一轮候选提供方向正确的 latency、energy、AP 排序。
2. 识别明显不可行点和高不确定度区域。
3. 支持 acquisition 在真实搜索空间中启动，而不是替代后续实测。

之后 cost model 会通过 `candidate -> real measurement -> feedback -> retrain` 循环自主改进。因此不应为了让首轮离线门禁全部变绿而无限补点，特别是不能让数据构建长期阻塞阶段 4 的模型和 loss 选择。

### 12.2 当前推进结论

```text
Gold176:
  作为 initial cold-start pool v1 冻结并进入阶段 4

严格数据充分性：
  仍为开放审查项，不写成跨模型泛化已证明

补点：
  后台运行，完成后作为 measured feedback batch 增量接入

Stage4：
  立即开始 raw/log/relative target、tree regressor、ranker、quantile/ensemble 对照
```

该安排不降低证据要求，而是把问题放回正确阶段：Stage3 负责提供可启动的真实 cold-start；Stage4 选择 cost-model/loss；Stage5 的实测回流负责让 predictor 在搜索过程中变准。

### 12.3 后台补点预算

首轮后台补点采用小预算，不再预设大规模 Gold 扩容：

1. 优先冻结 `4` 个完整四臂 train groups，即 `16` 行；只有 source/build 预检全通过才扩到 `8` 组。
2. 至少覆盖一组 Pyramid latency 大宽度邻域、一组 TVM/TRT latency 排序分歧点，以及一对跨模型共同或静态近邻 width。
3. 点位只能由当前 train/nested-CV 证据选择，不读取原 adaptive validation 的标签。
4. 后台补点不得修改 Gold176 baseline、Stage4 split 或当前结果目录；统一进入独立 feedback batch。
5. 停止条件是 `16` 行完整终态或出现两次相同 pipeline failure；不要求本轮立即重新跑完整 Gold sufficiency 审计。

### 12.4 阶段 4 准入边界

阶段 4 可以立即开始，但必须遵守：

1. 所有行按 `(model,width)` 分组，四臂不可拆分。
2. 使用 nested grouped CV 做模型/loss 比较，禁止继续把原 6 组称为独立 locked holdout。
3. 首轮模型选择只比较低容量候选；复杂 head 必须证明改善 ranking、Pareto/HV 或 uncertainty 才保留。
4. 后台反馈进入训练表时必须带 batch/source/hash，确保论文能区分 initial cold-start 与 online feedback。

### 14.2 独立 ranker 判定：不保留

| model | value-head top-10% recall | LGBMRanker top-10% recall | ranker delta |
|---|---:|---:|---:|
| CoDriving | `0.625` | `0.500` | `-0.125` |
| Pyramid | `0.444` | `0.333` | `-0.111` |

平均 delta 为 `-0.118`，低于“至少提高 `0.05` 才启用”的门槛。第一版 canonical cost model 不增加独立 rank head；value regressors 继续提供 Pareto 坐标和候选排序。

### 14.3 value OOF 的 Pareto/HV 结果

| model | Pareto recall | Pareto precision | HV regret |
|---|---:|---:|---:|
| CoDriving | `0.500` | `0.455` | `0.0435` |
| Pyramid | `0.333` | `0.600` | `0.0060` |
| 平均 | `0.417` | `0.527` | `0.0247` |

HV regret 较低但 frontier recall 较低，表示当前预测前沿保留了主要支配体积，却漏掉多条次级真实前沿成员。该结果足以启动反馈循环，不足以宣称 cold-start 已可靠恢复完整 Pareto。

### 14.4 uncertainty coverage 判定：quantile 暂留，仍需在线校准

原实现每个 outer fold、每个模型只使用一个 calibration group，整组 coverage 不稳定。本轮修正为按模型抽取约 `20%` outer-train groups 做 group-aware conformal calibration，5 折累计使用 39 个 calibration-group instances。

| 方法 | AP70 整组 coverage | energy 整组 coverage | latency 整组 coverage | 结论 |
|---|---:|---:|---:|---|
| ExtraTrees ensemble | `0.786` | `0.857` | `0.738` | 区间较窄，但 latency 未过 `0.80` |
| LGBM quantile + conformal | `0.810` | `0.833` | `0.881` | 三头均过 `0.80`，暂选 |

LGBM quantile 的平均整组 coverage 为 `0.841`，但平均相对区间宽度为 `0.620`，明显宽于 ExtraTrees 的 `0.199`。因此只能写为“满足首轮保守 coverage 门禁”，不能写成区间已经精确；后续 measured feedback 必须继续收窄区间。

上述 coverage 是“每个 target 分别要求四臂整组覆盖”。更严格的“三个 target 与四臂同时覆盖”诊断中，ExtraTrees 为 `0.476`，LGBM quantile 为 `0.595`；本轮不把 target-wise `0.80` 解释为联合 `90%` 置信保证。

### 14.5 offline replay 反思与结果

首版 replay 错误地把 Pyramid 与 CoDriving 合并成全局 HV，导致两种策略在初始 6 组即达到 95% oracle HV；该口径违反“Pareto/HV 先在模型内计算”的约束，结果已废弃。修正版执行：

1. 每个模型独立归一化和计算 HV，再平均 oracle fraction；
2. 初始组对模型分层；
3. 每轮只用已测完整组标签训练低容量 ExtraTrees ensemble；
4. 未测候选只暴露 width、graph、q_mode 和 capability 数值特征；
5. 按预测 Pareto 候选与 ensemble uncertainty 选择下一完整四臂组；
6. 回归测试确认任意修改全部未测候选标签，不改变下一步选择。

5 个 seed 的 samples-to-95%-model-internal-HV 结果：

| policy | 每 seed 所需完整组 | 中位组数 | 中位实测行数 |
|---|---|---:|---:|
| Pareto + uncertainty | `13, 8, 11, 12, 23` | `12` | `48` |
| random group | `9, 10, 19, 11, 10` | `10` | `40` |

当前 acquisition 比 random 多用 2 个完整组/8 行，未证明样本效率收益。该负结果不能通过改阈值隐藏：现有 acquisition score 不进入最终方法，下一轮应比较 expected HV improvement、frontier diversity 和 uncertainty-only，并保持相同初始组与 seed。
