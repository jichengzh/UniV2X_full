## 0. 本轮一句话结论

INT8 搜索臂应保留，但不能继续用单一 `q=int8_tc` 表示。旧 Phase1 的 hand-rewrite/int8_tc 数字在多个关键点上明显偏乐观；本轮 8 个 Route B INT8 自动后端 keypoints 均 correctness exact、均有 49 个 Conv tensorized，但性能排序依赖 backend/schedule。因此 Phase1 后续应使用 `Q x S`，并把 `backend/source/trusted_for_final_frontier` 写入数据入口。

汇总判断:

- 8/8 correctness exact。
- 8/8 至少 49 个 Conv 被 INT8 TensorCore tensorize。

## 4. 对 INT8 臂的解释

本轮更清楚地说明了三个事实:

1. **INT8 TensorCore 机制可用**: 8 个点都 exact，且 49 个 Conv tensorized。
2. **旧 hand-rewrite prior 不能当最终主结果**: `16x32x64` 和 `24x32x96` 上，Route B 自动 INT8 分别是旧 prior 的 2.47x 和 2.02x。
3. **INT8 是否优于其他路线由 backend 决定**:
   - 小宽度中 Route B INT8 可能慢于 native direct 或旧 prior。
   - 高宽度中 Route B INT8 开始优于 native direct，例如 `64x96x192` 和 `64x128x256`。
   - 这不是“INT8 必输/必赢”，而是 `Q x S` 与 shape/padding/fusion 的交互。

底层机制仍与 16 号文档一致:

```text
T_layer ~= max(F_ops / P_eff, Bytes / BW_eff) + T_launch + T_sync
```

当前 Route B INT8 auto-decomp v1 的主要损耗来自:

- padded int32 accumulator materialization。
- 独立 pack/requant kernel，稳定占约 18-22%。
- per-block `call_tir` 造成较多 fusion boundary。
- 小通道/小 per-group N 触发较高 padding 放大。

## 6. Phase1 搜索变量改造

代码定位:

- `scripts/stage2_smbo_joint_nsga2_v1.py`
  - 当前 `PRECS=["fp32","fp16","int8_tc"]`
  - 当前 genome 是 `(w0,w1,w2,q)`
  - 当前 `feat(w,q)` 只加入 `Q_ORD[q]`
  - 当前 `measure_real(w,q)` 只调用 `framework/measure_config.py --precision q`
- `framework/measure_config.py`
  - `--precision int8` = native direct INT8
  - `--precision int8_tc` = historical hand-rewrite/int8_tc route
  - 当前没有把 Route B INT8 auto-decomp 作为 `measure_config` 的正式 precision/backend arm

因此主搜索器的问题不是没有 joint P x Q，而是 `q` 粒度太粗。`q=int8_tc` 同时混入了:

- historical hand-rewrite prior
- native direct INT8 comparator
- Route B automatic INT8 TensorCore candidate

本轮生成了非侵入式 QxS manifest:

```text
${V2X_ROOT}/results/phase1_qxs_search_space_manifest_20260707.{json,csv}
```

建议的 5 个 arm:

| search_arm_id | Q | S/backend | final frontier |
|---|---|---|---|
| `fp32__baseline_reference` | fp32 | H800 TVM fp32 baseline | 条件允许 |
| `fp16__route_b_auto_tc` | fp16 | Route B auto-tune split-fix | 允许，但需泛化 runner |
| `int8__route_b_auto_int8_tc` | int8 | Route B auto-decomp INT8 TensorCore | 允许 |
| `int8__native_direct` | int8 | native direct full-ONNX | 诊断/条件允许 |
| `int8__historical_hand_rewrite_prior` | int8 | historical im2col+MMA | 不允许进入 final gold |

本轮没有直接修改 `stage2_smbo_joint_nsga2_v1.py` 的原因:

- Route B INT8 有可泛化 CLI；本轮已用于 4 个新 H800 点。
- Route B fp16 目前仍主要是 base artifact/quick remeasure，尚未整理为同等泛化的 per-width runner。
- 如果现在把主搜索器强行改为 QxS real-mode，会出现 `(fp16,route_b_auto_tc)` 无正式 measurement entry 的不完整状态。

正确下一步是先把 `measure_config` 或新 measurement registry 扩展为 `search_arm_id -> measurement_entry`，再让 NSGA-II genome 从 `(w,q)` 变为 `(w,search_arm_id)`。

## 7. 对论文叙事的影响

对论文有利的表述应是:

- 我们不是写死 INT8/FP16 胜负，而是让自动搜索框架学习 `P x Q x S` 的耦合。
- INT8 不是被否定，而是从单一 precision arm 被提升为 backend-aware arm。
- 旧 hand-rewrite 结果保留为诊断先验，说明 fused/full-engine INT8 有潜力；但最终主结果必须来自自动后端实测。
- 当前 auto-decomp v1 的失败/变慢点有可解释机制: padding、requant/materialization、fusion boundary。
- cost model 的改造不是硬编码规则，而是加入 `backend/source/trust/confidence`，让实测回流自动修正。

## 8. 下一步最小执行建议

1. 将 Route B fp16 泛化为 per-width runner，使其与 `stage2_route_b_int8_auto_decomp.py` 形成同等级 measurement entry。
2. 修改或新建搜索器入口:
   - input: `phase1_qxs_search_space_manifest_20260707.json`
   - training table: `original60_training_table_backend_relabel_20260707.json`
   - genome: `(w0,w1,w2,search_arm_id)`
   - features: widths + q_axis one-hot + backend one-hot + source confidence
3. final Pareto 过滤:
   - 只允许 `trusted_for_final_frontier=true/conditional` 且当前 pipeline 匹配的实测点进入主结果。
   - `historical_hand_rewrite_prior` 只能做 warm-start，不做 final gold。
4. acquisition 加 disagreement trigger:
   - 当 `RouteB_auto / historical_prior > 1.5x` 时，将邻域宽度加入补测队列。
   - 当前高差异中心: `16x32x64`、`24x32x96`。
