## 0. 本轮最终决策

### 0.1 只保留四条在线搜索消融

本轮只执行：

1. `w/o surrogate`：去掉代理模型，改为合法候选池内均匀随机采样；

### 0.3 Full 方法按真实实现定义

本轮 Full 方法不是 NSGA-II。真实实现冻结为：

```text
candidate universe:
  每个 SearchTask 预先枚举 686 个合法 genome

online budget:
  B = 4 candidates / round
  4 rounds
  T = 16 measured candidates / task

acquisition:
  predicted_frontier_diversity
  = latency/AP exploitation anchors
    + feature/objective maximin diversity
    + predicted-frontier / uncertainty diagnostics

feedback:
  measured latency + energy + full AP + terminal feasibility
  + materialized actual graph features
  atomic feedback before next-round refit
```

当前实现位置：

- `${V2X_ROOT}/framework/stage5/single_target_search_v2.py`
- `${V2X_ROOT}/scripts/stage5_advance_task_round_v2.py`

论文中应将其称为：

> surrogate-assisted finite-pool multi-objective acquisition with Pareto-aware ranking and maximin diversity

不得称为 NSGA-II，也不得写成“每轮由 NSGA-II 生成 600+ 个新候选”。正确表述是：每轮对冻结候选池中尚未测量的合法候选进行代理预测，再选择 4 个候选真实测量。

#### 0.3.1 当前实现尚无候选级 capability scan

实现复核确认：

```text

  验证 task 与 capability profile/hardware 是否匹配
```

```text
  latency
  energy
```

scanner 只能使用预注册的算子/精度支持、量化合同、shape/alignment 和 backend buildability 规则。规则必须在读取 Stage5/6 的成功/失败 terminal 标签前完成冻结并生成 `scanner_rule_manifest.sha256`；冻结后才允许用已有终态做独立审计。不得为了拟合历史赢家、失败点或某种 precision 的结果而加入规则。若审计后修改任何规则，必须：

```text
bump scanner version

废弃此前全部 scan decisions
```

```text

known successful configurations are not silently rejected
```

## 3. 公平预算与重复

### 3.1 统一预算

Full 和四条消融统一使用：

```text
M_pre_scan = 686 candidates for S7-PYR-TVM
M_scan_pass = scanner 冻结后报告，Full/A1/A2/A3 共用
B       = 4 selected candidates/round
rounds  = 4
T       = 16 selected candidates for S7-PYR-TVM
seeds   = {20260718, 20260719, 20260720}
```

A4 使用冻结 686 点 pre-scan pool，但仍保持 `B=4, T=16`。真实 capability/build/numerical failure 消耗一个测量名额；基础设施故障不消耗名额。

逻辑运行数量：

```text
5 variants × 1 SearchTask × 3 seeds = 15 logical trajectories
15 × 16 = 240 selected-candidate events
```

其中 Full GEAR-S7 是参考轨迹；历史 `S5-PYR-TVM` v3 默认只进入 measurement cache。完整轨迹复用还必须通过第 4.4 节定义的 `trajectory_reuse_audit.json`，且不得绕过新 scanner 的 scan-pass pool。

### 3.2 不允许用更多预算补偿失败

以下统一执行：

- build/numerical feasibility failure：消耗预算；
- source/checkpoint/ONNX 不存在：属于 evidence failure，任务阻塞；
- GPU 被占用、SSH 中断、临时文件系统错误：基础设施失败，同 request SHA 恢复，不消耗预算；
- 某臂效果差：不得增加 T；
- 某臂效果好：不得提前停止；
- 不允许为随机臂挑选“表现较好的 seed”。

### 3.3 复用缓存但隐藏标签

为减少重复测量，采用“冻结可信缓存 + 选中后揭示 + cache miss 真测”：

1. 启动前建立只读 measurement cache；
2. cache 只允许包含 Stage5/6 `paper_ready`、SHA 完整且测量合同一致的数据；
3. 候选选择前，搜索器只能看到 candidate identity/features，不能看到 cache 中的 latency、energy、AP 或 terminal status；
4. 搜索器也不能看到 cache membership、预计 hit/miss、cache source 或该候选是否曾被历史轨迹测量；
5. 某臂选中一个候选后，才按完整 key 查询 cache；
6. 完整 key 必须至少包含：

```text
model
profile
hardware
scope
input
batch
genome
q_mode
source/checkpoint/ONNX SHA
build/tuning contract
measurement protocol
AP protocol
```

7. key 完全一致则释放缓存真值；
8. cache miss 必须按正式合同真实物化、build、测量和 AP；
9. 不允许近似匹配、跨 profile 复用、跨 seed 偷看或用 surrogate 值补空；
10. 每条轨迹报告 cache hit、cache miss、新增实测数和实际 GPU-hours；
11. 在释放标签前，用空 cache 和完整 cache 各做一次 selection-only dry-run，selected IDs 必须逐字节相同，并保存 `cache_membership_invariance_audit.json`。

纯 replay-only 结果不能作为论文主表，因为现有缓存由 Full 方法自适应产生，可能系统性偏向 Full。

### 3.4 GPU 使用规则与快速版墙钟

GPU 调度合同：

- 动态检查 H800 GPU `0--7`，只租用真实空闲卡，不停止或抢占其他正式实验；
- 每张 GPU 同时最多运行一个正式 GPU job；
- 每条轨迹每轮有 4 个候选，允许这 4 点并行；
- 8 张 GPU 全空闲时，最多同时运行两个已经冻结的四候选批次；
- 每条轨迹必须等待本轮 4 点全部获得终态并完成原子反馈后，才能产生下一轮；
- 不同 variant/seed 可以并行，但状态、标签和 cache visibility 必须隔离；
- 同 width source 使用文件锁，禁止重复恢复训练或相互覆盖；
- latency/energy 测量窗口必须独占 GPU；检测到外部进程、频率/功耗异常或显存争用时，保持 request SHA 重试；
- 保存 `gpu_lease_audit.json` 和逐测量窗口 `gpu_occupancy_snapshots.jsonl`，至少记录 GPU UUID、租约、进程、显存占用和异常重试；
- GPU 进入 CPU build、文件等待或任务结束后，可从已冻结队列补位，但不得改变 selected IDs、seed 或预算；
- 不得通过跨轮提前选择、重复测量或放宽标签隔离来制造 GPU 利用率。

历史 `S5-PYR-TVM` 一条 T16 轨迹墙钟约 `4:54:47`。快速版共有 15 条轨迹：

```text
单轨迹历史耗时 × 15 ≈ 73.7 GPU-lane hours
8 GPU 理想情况下可并行两个四点批次
```

预计：

| 阶段 | 预计墙钟 |
|---|---:|
| runner/scanner、TDD、dry-run | 0.5--1.5 天 |
| 15 条正式轨迹 | 1--2 天（取决于 cache/source 命中） |
| 汇总与审计 | 2--6 小时 |
| **正常总墙钟** | **约 2--4 天** |
| 外部争用或 cache 命中很低 | **约 5--7 天** |

该估计不是硬停止时间。运行 24 小时后必须根据已完成终态数、cache 命中率和有效并行度更新 ETA；不得为了满足 ETA 修改实验合同。

## 4. 五行方法定义与单变量隔离

| Variant | Candidate pool | Surrogate | Online labels回流 | Capability features | Capability scan | Acquisition |
|---|---|---|---|---|---|---|
| Full GEAR-S7 | scan-pass subset | on | on | on | on | `predicted_frontier_diversity` |
| A1 w/o surrogate | scan-pass subset | **off** | 只记录、不用于选点 | 不用于选点 | on | uniform random |
| A2 w/o measured feedback | scan-pass subset | on，round 0 后冻结 | **off** | on | on | 与 Full 相同 |
| A3 backend-blind | scan-pass subset | on | on | **off** | on | 与 Full 相同 |
| A4 w/o capability scan | pre-scan 686 | on | on | on | **off** | 与 Full 相同 |

除表中加粗项外，其余合同必须与 Full 完全一致。

### 4.1 A1：`w/o surrogate`

定义：

```text
每轮从尚未选择的 scan-pass 候选中
按冻结 seed 均匀无放回采样 4 个独立 genome
```

约束：

- 不训练或调用 value heads；
- 不调用 uncertainty；
- 不调用 predicted frontier；
- 不使用在线标签调整采样概率；
- q_mode 不设配额，不强制 FP16/INT8 配对；
- 每轮仍执行相同物化、backend tuning、latency、energy、full AP 和数值门禁；
- 记录反馈，但反馈只进入结果表，不进入后续采样。

该实验回答“代理引导是否提升同预算样本效率”，不是比较随机搜索是否最终能穷举整个空间。

### 4.2 A2：`w/o measured feedback`

定义：

```text
round 0:
  仅用冻结 Gold176 训练一次 canonical bundle

round 1-3:
  value heads / uncertainty / anchors / calibration 全部冻结
  不把新 latency、energy、AP、terminal status 或 actual graph features
  写入训练视图
```

允许：

- 记录已经选择过的 candidate ID，防止重复；
- 使用选择时已有的 surrogate candidate features 做 batch diversity；
- 使用冻结模型重新预测剩余候选。

禁止：

- 用实测标签重训；
- 用失败状态过滤相邻候选；
- 用 materialized actual graph features 更新模型；
- 修改 AP anchor；
- 因已知某种 q_mode 失败而人工改变候选池。

该实验隔离“真实测量回流”的价值。它不是把整条测量链删除；所有 16 个候选仍需真实终态。

### 4.3 A3：`backend-blind features`

该臂保留 task 的 backend 路由，因为候选仍必须在指定 `tvm_auto` profile 上真实执行；删除的是**代理模型可见的 capability context**。

模型输入中必须删除：

```text
capability_* numeric features
backend/profile one-hot features
dispatch_key
backend name
capability_profile_id-derived features
```

模型输入中保留：

```text
model/config features
widths
q_mode
graph features
FLOPs / params / operator statistics
```

为了防止隐式泄漏，启动前输出：

```text
full_feature_schema.json
blind_feature_schema.json
removed_feature_names.json
feature_leakage_audit.json
```

泄漏审计必须证明 blind schema 中不能由列名或确定性编码直接恢复 backend/profile 身份。

#### A3 可辨识性门禁

Gold176 同时包含多个 capability profiles，因此理论上 A3 可产生不同预测；但仍必须实测审计：

```text
capability feature count > 0 in Full
removed feature count > 0 in blind
Full/blind encoded matrix SHA differs
至少报告逐 seed prediction delta 和 selected-ID overlap
```

若某个任务/seed 的 16 个 selected IDs 与 Full 完全相同，则直接复用完全相同的真测结果，标记：

```text
trajectory_identical_after_feature_ablation
```

不得为制造差异而换 seed、改 tie-break 或增加预算。

如果 3 seeds 的全部轨迹与 Full 完全相同，则该臂仍算实验完成，但论文结论只能写成：

> capability features were not identifiable under the current finite-pool/search-budget setting

不能声称 capability context 已被证明有效。

### 4.4 A4：`w/o capability scan`

A4 保留 capability features，唯一变化是候选进入搜索前不执行新通过 admission 的候选级 scan gate。历史 Stage5 actual-v3 默认只能作为选中后揭示的 measurement cache，不能直接作为 Full GEAR-S7 轨迹。只有生成并通过 `trajectory_reuse_audit.json`，同时证明以下内容逐字段相同，才允许复用一条完整轨迹：

```text
seed and per-round seed derivation
pre-scan/scan-pass pool and pool SHA
feature schema and encoder SHA
surrogate/acquisition implementation SHA
tie-break
round-by-round selected IDs
feedback visibility and bundle SHA
measurement contract
```

由于历史 Stage5 没有候选级 scanner，历史轨迹原则上不能通过 Full GEAR-S7 的 scan-pass pool 审计；不得仅因 selected IDs 恰好都在 scan-pass 子集中就事后宣称为同一 Full 轨迹。

真实失败分类：

```text
backend_build_failure
unsupported_operator_or_precision
quantization_contract_failure
numerical_feasibility_failure
runtime_failure caused by candidate capability incompatibility
```

这些候选：

- 消耗 T=16 中的一个名额；
- 不伪造 `AP=0`、`latency=inf` 或 energy；
- 保存 build log、numerical report、terminal status 和 SHA；
- 在 HV 中不作为有效点；
- 计入 invalid/failure rate 和 valid measurement yield。

以下不计为 capability failure：

```text
GPU unavailable
temporary OOM caused by unrelated process
SSH/network failure
missing source artifact
permission failure
runner bug
```

这些属于基础设施或证据错误，必须修复后用同 request SHA 重试。

如果 A4 在全部 3 条 seed 轨迹中没有选到任何 scanner-reject 候选，则实验结论是“在 T=16 的当前采集轨迹中未观察到 scan 对失败率的影响”；不得根据未被选择的候选推断一个虚假 failure-rate 改善。

## 5. 结果指标

### 5.1 主指标

Gold176 初始前沿较强，直接报告总 HV 容易掩盖 16 点在线搜索的增量。因此主指标冻结为：

```text
DeltaHV@16
= HV(Gold176 ∪ online_1:16) - HV(Gold176)

DeltaHV-AUC
= 在 budget = {0,4,8,12,16} 上的增量 HV 曲线面积
```

`DeltaHV-AUC` 为主统计终点，`DeltaHV@16` 为次要终点。

HV 必须：

- 在每个 model/profile 内独立计算；
- 使用 latency、energy 最小化和 AP70 最大化；
- reference point 在首条实验结果产生前由冻结 Gold176 合同确定；
- 所有 variant 使用相同 task-specific reference；
- failure 不伪造目标值，不进入有效 Pareto 集。

### 5.2 其他必须指标

每条轨迹必须报告：

```text
frontier recall@16
valid measurement yield
build failure rate
numerical failure rate
total capability-related invalid rate
selected FP16/INT8 count
selected-ID overlap vs Full
cache hit / miss
new real measurements
logical measurement budget
wall-clock
GPU-hours
backend tuning time/trials
full AP time
infrastructure wait/retry time
```

`frontier recall@16` 的参考前沿定义为：

```text
本轮全部 variants/seeds 实际获得的、合同一致的成功测量点
在同一 model/profile 内组成的 pooled measured attainable frontier
```

它不是完整 686 点的 oracle frontier，因此只能标记为 secondary/post-hoc。主表中保留时应加 `†`，表注必须解释该定义；不得将其用于主显著性声明。

在 `DeltaAP70 <= 0.10` 下另报告：

```text
best valid latency
best valid energy
latency ratio vs Full
energy ratio vs Full
```

ratio 必须先在同一 task/seed 内计算。跨 profile 不比较绝对 latency。

### 5.3 `samples-to-95%-HV`

完整 686 候选没有全部真测，因此不存在无偏的全空间 oracle HV。允许报告：

```text
S95-pooled
= 达到本轮所有 variant 已真实测得的 pooled attainable DeltaHV 的 95%
```

但必须明确标记为 secondary/post-hoc，不得将其写成达到全候选空间理论最优的 95%。

## 6. 统计合同

统计单位：

```text
seed within the fixed S7-PYR-TVM task
```

总计只有 `1 task × 3 seeds = 3` 个与 Full 配对的统计单位。不得把每条轨迹的 16 个候选当成 16 个独立样本。

快速版采用描述性统计：

- 逐 seed 报告原始值；
- 报告 `mean ± std`、median 和 range；
- 每条消融相对 Full 报告逐 seed paired delta；
- 报告 paired delta 的 mean/median；
- 报告改善方向一致性，例如 `3/3 seeds improved`；
- 主要描述性终点为 `DeltaHV-AUC`；
- `DeltaHV@16`、failure rate、frontier recall 为次要终点。

只有 3 个配对样本时，exact two-sided Wilcoxon 的最小可能 p 值也不足以支持四项多重比较后的显著性声明。因此本轮：

```text
不计算或展示显著性星号
不使用 Holm-corrected p-value
不把 bootstrap CI 写成稳定总体区间
不声称 statistically significant
```

如果某条消融未闭合全部 3 个 seed：

- 标记 `incomplete`；
- 不汇报只基于成功 seed 的均值；
- 不用不成对样本替代；
- 不删掉失败 seed。

该快速版可以提供机制趋势和效应方向，但若论文最终必须作显著性检验，需要后续增加 seed 或恢复多任务矩阵。

## 16. 2026-07-25 版本澄清：actual-feedback v3 才是正式执行底座

### 16.1 核心结论

本项目已经更新并实际运行了 **Stage5 actual-feedback v3**。但仓库采用的是“模块、数据合同和实验目录分别版本化”，不是整套框架统一使用一个全局版本号。因此，正式 v3 闭环内部继续调用文件名带 `v1` 或 `v2` 的稳定模块并不矛盾。
