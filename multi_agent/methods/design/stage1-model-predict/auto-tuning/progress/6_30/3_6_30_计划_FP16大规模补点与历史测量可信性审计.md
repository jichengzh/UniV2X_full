## 2. 固定口径和不可再犯的问题

1. latency 统一使用 `ms`。
2. speed 口径必须是 `H800 + TVM compiled backbone/subnet full-engine`, 输入为 `spatial_features`, 输出为 multiscale feature。
3. 不能把完整 perception pipeline latency、backbone/subnet latency、PyTorch eval wall time 混写。
4. FP16 speed row 必须包含:
   - `input_shape`;
   - `source_cast_fp16`;
   - `tensorcore_gate`;
   - `wmma`;
   - `tvm_mma_sync`;
   - `scheduled_counts`;
   - `replace_records`;
   - `artifact_path`;
   - `raw_dir`;
   - `gpu_model`;
   - `gpu_compute_cap`;
   - `schedule_route`;
   - `full_network_claim=false`。
5. AP row 必须区分:
   - smoke;
   - full-val;
   - `processed_samples`;
   - `requested_num_samples`;
   - `ap_measured`;
   - `pred_nonempty_count`;
   - `pred_total_count`。

   - power sampling method;
   - warmup/reps;
   - same engine artifact;
   - same schedule route;
   - GPU model;
   - idle/baseline handling;
   - raw power trace。

## 3. 历史数据可信性审计规则

历史 FP16 数据不能默认可信。先做 audit matrix。

### 3.1 latency 可信条件

一个 FP16 latency row 只有满足全部条件才可复用:

```text
1. H800/sm90。
2. TVM compiled backbone/subnet full-engine。
3. route identity 明确: default / rewritten_tensorcore / cast_fp16_source。
4. input_shape 与 AP/runtime config 对齐。
5. TensorCore gate 明确:
   - 若 claim 是 TensorCore, 必须 wmma/tvm_mma_sync > 0。
   - 若 wmma=0, 只能写 default FP16/cast FP16 latency, 不能写 TensorCore latency。
6. raw_dir 中有 report、TIR、.so、stdout/stderr 或 runner_command。
7. schedule route 可复现。
```

不满足任意一条:

```text
latency_status=invalidated_needs_remeasure
```

### 3.2 energy 可信条件

一个 FP16 energy row 只有满足全部条件才可复用:

```text
1. energy 对应的 engine artifact 与 latency row 是同一个 .so 或同一个 build manifest。
2. power sampling 方法与 INT8/FP32 当前统一方法一致。
3. 有 raw power trace 或至少有 power sampling report。
4. energy 单位是 J, latency 单位是 ms。
5. 没有 FP16 energy 明显系统性高/低但缺少解释的异常。
```

若历史 FP16 energy 与 FP32/INT8 不是同方法、同 GPU 类型、同 engine artifact:

```text
energy_status=invalidated_needs_remeasure
```

### 3.3 AP 可信条件

一个 FP16 AP row 只有满足全部条件才可复用:

```text
1. full-val: processed_samples >= 1789 或配置对应完整验证集样本数。
2. requested_num_samples=null。
3. ap_measured=true。
4. pred_nonempty_count > 0。
5. AP30/AP50/AP70 有合理非零趋势。
6. report 中有 prediction_distribution 且 samples=processed_samples。
7. postprocess_distribution 包含 pred_score/pred_box_tensor/gt_box_tensor 全量 aggregate。
8. output_error_summary 或等价数值对照存在。
```

若只有 1-sample smoke:

```text
ap_status=smoke_only_not_fullval
```

## 5. 并行执行建议

可使用 GPU 分工:

```text
GPU0/GPU1: latency + TVM build/rewrite 队列。
GPU2/GPU3: energy 重测队列。
GPU4/GPU5/GPU6/GPU7: AP full-val 队列。
```

调度规则:

```text
1. 同一 label 必须先有 latency/rewrite `.so`, 再跑 energy/AP。
2. AP 和 energy 不能各自 rebuild 不同 `.so` 后再合并。
3. 每个 job 写独立 raw_dir, 禁止覆盖。
4. 每 30 分钟刷新 job manifest。
5. 失败 job 不删除 raw, 写 blocker 并进入 retry/root-cause 队列。
```
