## 1. 论文核心命题

最终实验应共同支持三个命题：

| 命题 | 必须提供的证据 |
|---|---|
| C1 软硬件变量存在条件耦合 | FLOPs/位宽不能稳定预测真实延迟；joint 优于 compression-only 和 serial |
| C2 自动搜索框架有效 | 相同预算下获得更高 HV、更少测量、更可靠的最终 Pareto |
| C3 方法具有迁移能力 | 在 Pyramid、CoDriving 以及至少两个硬件 profile 上仍成立 |

INT8 不需要被强行证明恒快。只要完整证明“何时快、何时慢、为什么，以及框架能否自动学会选择”，就是论文级结论。

## 2. 阶段 0：冻结论文证据契约

首先统一所有后续实验的数据行：

```text
model / dataset / checkpoint
width vector
q_mode / optional mixed_policy_id
capability_profile_id
realization_origin / source-build artifact digests
ONNX / calibration / compiler SHA
scope / input shape / batch
tuning budget / seed
latency p50/p90
energy
AP30/AP50/AP70

trusted_for_final_frontier
```

规则：

1. backend 名称不进入 genome，只记录 capability scan 的数值特征。
2. evidence trust 只负责训练集和主前沿过滤，不进入模型特征。
3. build/numerical 失败点进入 feasibility classifier，不能伪造 `AP=0` 训练 AP 回归器。
4. latency、energy、AP 必须共享 pipeline fingerprint。
5. gold 自动实现 provenance 同时支持 TVM `source_ir_automatic` 和 TRT `compiler_engine_automatic`，但二者都必须绑定 source/build artifact digest；不能用 TVM 专属门禁排除 TRT，也不能让 engine build 绕过 provenance。

交付：唯一的 `measurement_row_v3`、artifact registry 和 final-frontier validator。

## 3. 阶段 1：闭合 INT8 开放问题

执行 21 号文档第 13 章的新计划：

1. NumPy/CPU INT8 数学 oracle。
2. `2 x 2 x 2` 八点精度矩阵。
3. S0--S5 性能逐级剥离。
4. TRT 同 shape layer profile/engine inspector 对照。
5. 最多两个通过门禁的 full AP 点。

最终必须落入以下分支之一：

| 结果 | 框架处理 | 论文结论 |
|---|---|---|
| INT8 core 和 full region 都快，精度可恢复 | 注册为有效 realization | 自动 mixed INT8 可产生收益 |
| core 快、full region 慢 | 继续定位 materialization/fusion | 后端实现成本抵消理论收益 |
| core 本身不快 | capability profile 标记无净收益 | INT8 并非该 shape/profile 的有效臂 |
| 部分层精度敏感 | mixed policy 学习覆盖范围 | 全 INT8 不一定优于 mixed/FP16 |
| 当前 TVM INT8 全部失败 | 保留为真实负样本 | 框架自动避免无收益 INT8，而非人工禁用 |

产出论文表 **T0：INT8 mechanism table**，主文可放精简版，完整 waterfall 放附录。

### 3.1 阶段 1 收口结论（2026-07-11）

阶段 1 已按停止条件收口：TVM/H800 上 INT8 core 对部分大 Conv 可加速，但完整 persistent-INT8 region 仍慢于 FP16；TRT/H800 在同一 CoDriving backbone 上实现了 `1.431x` INT8 加速和约 `46%` energy 降低。结论是 INT8 收益取决于编译后端的全图精度传播、融合与 tactic 能力，不能由硬件或量化名称单独决定。

TVM/H800 的 INT8 搜索臂**不删除、也不人工禁用**，其负结果作为真实冷启动/回流证据，由模型学习是否选择；mixed INT8 的历史证据保留，但在通过第 4 章联合准入门前不进入 active manifest。“不考虑软件后端、默认使用 INT8”的对照用于证明软硬件分离优化可能导致实际减速。TVM 路径未通过速度门，因此该诊断 realization 的进一步 full AP 按门禁不启动。

详细实验与原因见 [21 号文档第 13 章](progress/7_14/21_7_14_交接文档_RouteB_INT8_AP修复与速度复测计划_v1.md#13-p0--p3-实现反思与下一轮双问题归因计划) 和 [22 号最终决策文档](progress/7_14/22_7_14_交接文档_持续INT8区域最终决策冲刺_v1.md)；机器可读结论见 [`final_backend_decision.json`](${V2X_ROOT}/results/codriving_source_conv_auto_20260711/final_backend_decision.json)。

## 4. 阶段 2：重构 canonical 自动搜索框架

### 4.0 重构必要性复审

阶段 2 **仍有必要，但重构理由和范围需要收缩**。必要性不再来自“mixed policy 已证明可以超过 FP16”，而来自以下已闭合事实：同一 H800 上，TVM 当前实测倾向 FP16，而 TRT 的 INT8 可实现 `1.431x` 加速；框架必须通过 capability scan、冷启动数据、cost model 和实测回流自行学习该后端条件差异，不能统一默认 INT8，也不能人工删除 TVM INT8 臂。

`mixed_policy_id` 当前没有形成同时通过 latency、numerical 和 AP 门禁的有效 Pareto 证据，因此**不再作为第一版 canonical genome 的必选主轴**。当前 active genome 收敛为：

```text
([p1,p2,p3], q_mode)

q_mode = fp16 | int8
```

`mixed_policy_id` 保留为可选扩展字段，默认 `none`；只有某个 compiler profile 下出现同 pipeline、正式校准、numerical/AP 通过且相对 FP16/pure INT8 非支配的 mixed 实测点后，才由 active manifest 激活 `topK/region` 候选。未激活不等于人工判定 mixed 理论无效，而是避免让尚无 gold 证据的维度扩大冷启动和搜索成本。

相关结论演变如下：

| 文档 | 当时结论 | 当前审计与错误原因 |
|---|---|---|
| [18 号 INT8 慢因与 G4 实验](progress/7_14/18*_7_14_交接文档_INT8慢因验证_后三组对照实验设计_v1.md) | `mixed_top25_flops` 曾在 4/8 点快于 FP16，因而提出 `Q x S` | 这些是 diagnosis-only latency，使用旧量化语义/无有效 scale，且前后 graph boundary 不一致；只能证明 policy 会改变执行成本，不能证明有效 AP 下存在 mixed 加速。 |
| [19 号 QxS 改造 v1](progress/7_14/19_7_14_交接文档_QxS搜索框架改造计划_v1.md) | 将 backend、schedule、mixed policy 绑定为 `search_arm_id` | 过早把诊断 realization 提升为搜索动作，并可能把人工后端知识编码进 genome；该方案已被后续能力扫描优先设计替代。 |
| [20 号能力扫描优先 v2](progress/7_14/20_7_14_交接文档_QxS搜索框架改造计划_v2_硬件后端能力扫描优先.md) | backend 改为 compiler context，但仍默认激活多种 topK mixed policy | backend 位置修正正确；问题是 mixed 仍在 gold 联合收益成立前被预设为主搜索轴。当前保留其条件激活机制，不默认展开 top10--top75。 |
| [21 号 AP 修复与速度复测](progress/7_14/21_7_14_交接文档_RouteB_INT8_AP修复与速度复测计划_v1.md) | 修复 scale 后 AP 可非崩溃，但 scale-aware mixed latency 显著慢于 FP16；另一些 top25 fused 路径 numerical fail | 说明问题并非简单的“mixed 必然 AP 崩溃”，而是早期速度与正确 AP 不属于同一有效 pipeline；目前不存在速度、精度同时成立的 TVM mixed gold 点。 |
| [22 号最终决策](progress/7_14/22_7_14_交接文档_持续INT8区域最终决策冲刺_v1.md) | persistent INT8 已成立，但 TVM top-2 region 仍慢 29.25%；TRT INT8 快 1.431x | 阶段 2 应优先学习 backend-conditioned `fp16/int8` 选择；mixed 只作为未来经证据准入的扩展，不再承担当前框架重构的必要性证明。 |

因此阶段 2 的保留范围是：统一 measurement contract、capability scanner、backend realizer、cost model、多目标搜索与真实回流；删除“必须依赖 mixed policy 才能证明框架价值”的前提。

框架拆成六个稳定组件：

| 组件 | 职责 |
|---|---|
| Capability scanner | 扫描硬件和编译器支持的 dtype、scale 粒度、region、fusion 和 schedule 能力 |
| Genome decoder | 将逻辑 `fp16/int8` 策略转换为稳定 selection manifest；仅展开 active manifest 已准入的 mixed 扩展 |
| Backend realizer | 自动生成 FP16、pure INT8 实现，并在证据准入后生成 mixed-region 实现 |
| Cost-model layer | 从 cold-start 与实测回流训练 feasibility、AP、latency、energy 和 uncertainty/rank heads，为候选提供预测坐标与采集信号 |
| Multi-objective search | surrogate-assisted NSGA-II 生成候选 |
| Measurement feedback | latency/energy/AP 真测、校准 surrogate、更新 Pareto |

### 4.1 Cost model 在 canonical framework 中的位置

Cost model 不是后续附加模块，而是连接 cold-start、候选生成和实测回流的核心接口：

```text
Gold Cold-start / measured feedback
-> feature encoder
-> feasibility + multi-objective cost-model heads
-> predicted AP/latency/energy + uncertainty/disagreement
-> NSGA-II Pareto ranking and acquisition
-> selected candidates enter real measurement
-> measured rows update cost model
```

阶段 2 需要先固定以下接口，阶段 4 再通过实验决定每个 head 的具体损失函数和模型形式：

```text
fit(training_rows, feature_schema) -> fitted_model_bundle
predict(candidate_batch) -> AP/latency/energy predictions
predict_feasibility(candidate_batch) -> build/numerical feasibility probability
predict_uncertainty(candidate_batch) -> interval/disagreement
update(new_measured_rows) -> calibrated_model_bundle
save/load(model_bundle, schema_hash, training_data_hash)
```

### 4.2 Cost-model 输入特征契约

输入只能来自 genome、自动 capability scan 和编译/图分析结果：

```text
widths / pruning ratios
q_mode one-hot
optional active mixed_policy_id one-hot
FLOPs / parameters / activation bytes
selected Conv/MAC ratio
region count and Q/DQ count
padding/materialization estimates
fusion-break count
hardware/compiler capability measurements
```

以下字段禁止作为预测特征：

```text
backend name string
具体模型专用 Conv ID
evidence trust label
final-frontier membership
人工 INT8/FP16 优先规则
```

其中 evidence trust 只在训练数据装配阶段过滤样本，不能让模型通过 trust 标签间接获知答案。

### 4.3 Cost-model 多头结构

canonical framework 预留以下 heads：

| head | 目标 | 使用位置 |
|---|---|---|
| feasibility head | build、numerical 和 pipeline 可行性 | 候选 repair/filter |
| AP value head | 预测候选 AP 或相对 gold anchor 的变化 | Pareto AP 坐标 |
| latency value head | 预测条件化 realization 的端到端延迟 | Pareto latency 坐标 |
| energy value head | 预测单次推理能耗 | Pareto energy 坐标 |
| uncertainty head | 预测区间或 ensemble disagreement | acquisition 与补测触发 |
| optional rank head | 学习候选相对次序 | 仅在阶段 4 证明提高 frontier recall/HV 后启用 |

阶段 2 不预先宣布 rank loss、AP residual 或某种回归树一定最优，只定义这些 head 的接口和证据要求。阶段 4 的职责是通过 locked holdout 和搜索 replay 选择实际启用的模型组合。

### 4.4 Cost-model 更新与搜索闭环

每轮搜索必须执行：

```text
train/retrain on trusted cold-start + measured feedback
-> predict unmeasured feasible candidates
-> NSGA-II generates predicted Pareto neighborhood
-> acquisition combines Pareto rank and uncertainty/disagreement
-> real measurement
-> prediction-vs-actual calibration report
-> append trusted rows and retrain
```

必须记录：训练数据 SHA、feature schema SHA、模型超参数、随机种子、held-out 指标、每轮 prediction-vs-actual error 和 frontier advance。没有发生模型更新的对照臂才可标记为 `w/o feedback`。

必须修复 Method 中当前不真实的实现描述：

1. 不再把 `q` 只写成 bit-width。
2. 若 active manifest 激活 mixed 扩展，区分 logical mixed policy 与 physical INT8 region；未准入时不把 mixed 描述为主搜索轴。
3. 未实现 pairwise rank loss 前，不在方法中声称已使用。
4. 未实现 AP residual 主路径前，按直接 AP surrogate + gold validation 描述。
5. 每个 compiler profile 内固定唯一 canonical realization/tuning pipeline；TVM 与 TRT 可以是不同 profile，但同一 profile 内不能混写 AutoTVM、DLight、MetaSchedule 和 hand-rewrite。

阶段 2 的交付包括：统一 feature encoder、model bundle schema、训练/预测/增量更新入口、feasibility gate、NSGA-II acquisition 接口和逐轮 calibration report。阶段 4 在这些接口上完成 cost-model/loss 的选择实验，而不是到阶段 4 才开始设计 cost model。

### 4.5 阶段 2 接口工程收口（2026-07-11）

阶段 2 已按“接口与真实回流 smoke”口径收口，默认 capability 冻结为：

```text
S0 static hardware/toolchain
+ S1 model-independent build-only structural probes
S2 performance probes = disabled by default, conditional extension only
```

收口证据位于：

- `results/s1_neutral_probes_v3_20260711/`：H800 TVM/TRT 六类 S1 build-only 结构探针；
- `results/canonical_stage2_interface_smoke_v3_20260711/closure/stage2_closure_report_v3.json`：canonical 真实回流接口 smoke；
- `results/canonical_stage2_interface_smoke_v3_20260711/closure/measurement_rows_v3.json`：两条重新构建、重新真测、同源 provenance 的 TRT FP16/INT8 metric-specific gold 行。

真实 smoke 使用 H800、Pyramid `32x64x128` backbone 和 TRT `<PRIVATE_HOST>`，INT8 使用 123 个 DAIR calibration-only activation 样本。每条 measurement JSON 均绑定同次 build 的 source ONNX、serialized engine、build config 和 engine inspector SHA；INT8 额外绑定 calibration manifest/cache SHA。输出 finite check、1500 次 CUDA-event latency 和 NVML energy。

本轮真测：

| q_mode | latency p50 | latency p90 | energy |
|---|---:|---:|---:|
| FP16 | `0.856944 ms` | `0.859872 ms` | `0.245942 J` |
| INT8 | `0.860000 ms` | `0.863264 ms` | `0.250649 J` |

两行均通过 `measurement_row_v3`，进入 metric-specific `gold_training`；因 AP 尚未测量且 `trusted_for_final_frontier=false`，均不进入 final frontier。闭环已真实执行：

```text
S0+S1 capability profile
-> canonical candidates
-> initial fit
-> latency/energy acquisition replay emits backend dispatch request
-> measured INT8 feedback
-> training rows 1 -> 2
-> updated predictions
-> measured latency-energy Pareto view
```

阶段 2 收口的严格含义：

1. measurement contract、capability context、model bundle、metric-specific acquisition、dispatch request、feedback update 和 Pareto view 已能通过真实 measured rows 串联；
2. backend 名称仍只用于 dispatch，不进入 genome 或 predictor 数值特征；
3. S2 默认关闭，后续只有阶段 3/4 locked validation 证明 S1 不足时才按门槛激活；
4. acquisition 本轮是对已存在 measured INT8 行的 wiring replay，不宣称 acquisition 因果地产生了该测量；
5. `stage2_interface_smoke_closed=true`，但 `stage2_method_validated=false`。

本收口不代表：Gold Cold-start 96 已完成、AP head 已验收、cost model/loss 已选定、跨 profile 泛化已证明或 final Pareto 已产生。这些分别属于阶段 3、4 和后续实验。

### 4.6 首轮接口 smoke 反思与补充收口要求

1. **S1 覆盖偏量化。** 已完成的 S1-Q 主要观察 INT8 propagation 和 Q/DQ folding，尚未系统覆盖剪枝造成的通道不对齐、padding、小通道、group packing 和 off-diagonal stage boundary；阶段 2 需要补充 S1-P shape/build 探针。
2. **固定 `32x64x128` 的两行 smoke 只是 wiring。** 它证明 contract、fit、request 和 update 能连接，但没有验证候选生成、组级 acquisition、预测误差下降或 Pareto advance，不能单独代表完整搜索轮次。
3. **正式反馈单位不是单行。** canonical 96 中最小不可拆分单位是一个 `(model,width)` 的 TVM/TRT × FP16/INT8 完整配对组；正式循环应按组选择、按组测量、整组回流。预测 Pareto 用于选择 batch，不是“一条 Pareto 一条 Pareto”更新。
4. **Cost model 第一版应简化。** 主预测器只固定 latency、energy、AP 三个目标；feasibility 先作为规则/失败 gate，uncertainty 从 ensemble/quantile 导出，独立 rank head 默认关闭，后续由阶段 4 消融决定是否启用。

因此，阶段 2 在 4.5 的接口 smoke 之外，还需完成：S1-P build-only 扫描，以及一次多 width、完整配对组的 acquisition → feedback → Pareto 更新循环，之后才能标记搜索行为收口。

### 4.7 S1-P 与整组搜索循环收口（2026-07-11）

S1-P 使用 6 类不从 Pyramid/CoDriving 或历史结果取 shape 的合成探针，每类各含 FP16 和显式 INT8 Q/DQ，共 12 个 ONNX。H800 build-only 结果如下：

| S1-P 类型 | TVM build | TVM INT8 传播 | TRT build | TRT INT8 传播 | 本轮结论 |
|---|---:|---:|---:|---:|---|
| aligned channels | 2/2 | 0/1 | 2/2 | 1/1 | build 可行 |
| misaligned channels | 2/2 | 0/1 | 2/2 | 1/1 | 未在 build-only 指标上与 aligned 拉开差异 |
| small channels | 2/2 | 0/1 | 2/2 | 1/1 | build 可行，性能影响待阶段 3 实测 |
| group packed | 2/2 | 0/1 | 2/2 | 0/1 | TRT Q/DQ 不折叠，reformat=3 |
| group unpacked | 2/2 | 0/1 | 2/2 | 0/1 | TRT Q/DQ 不折叠，reformat=2 |
| off-diagonal two-stage | 2/2 | 0/2 | 2/2 | 2/2 | TRT 两个 Conv 均传播，4 对 Q/DQ 折叠 3 对 |

TVM 的 Relax 结构解析器本轮对所有 INT8 均返回传播 0，因此该列只能证明当前解析入口没有观察到传播，不能单独判定 TVM 未执行 INT8。TRT 列是 engine inspector 的结构证据，不是延迟证据。本轮已证实 `group/per-group shape` 会改变 TRT 的 INT8 可实现性；未证实通道对齐必然影响延迟。原始记录见 [S1-P H800 records](../../../../../results/s1_pruning_shape_probes_v3_20260711/runs_v3/)。

整组循环以 CoDriving 已有真实 latency/energy 数据做 locked replay：初始 3 个完整组（12 行），acquisition 一次选择 2 个完整组（8 行），训练表一次性从 12 更新到 20 行；4 个 locked holdout 组（16 行）未参与 acquisition。更新后 latency MAPE 从 `1.6633` 降至 `1.5151`，energy MAPE 从 `0.9959` 降至 `0.7159`，精度选择准确率保持 `1.0`，并重算了 measured latency-energy Pareto。详见 [grouped replay report](../../../../../results/stage2_grouped_search_round_smoke_v3_20260711/report.json)。

阶段 2 最终状态：

- `stage2_interface_smoke_closed=true`；
- `stage2_grouped_search_behavior_closed=true`；
- `stage2_method_validated=false`。

即：能力上下文、完整组 acquisition、整组回流和 Pareto 重算的工程链路已收口；replay 并非因果调度，误差仍高，不代表 cost model 或论文方法已验证。后者由阶段 3 Gold Cold-start 与阶段 4 locked validation 负责。

## 5. 阶段 3：构建 Gold Cold-start 96

### 5.1 修订后的 96 点设计

保持总规模 96，但不再用 6 种 mixed policy 凑满。修订为：

```text
2 models x 12 width configurations x 2 q_mode x 2 compiler profiles = 96

models            = Pyramid | CoDriving
q_mode            = fp16 | int8
compiler profiles = H800-TVM-auto | H800-TRT
```

backend/compiler profile 是 capability scan 产生的测量上下文，不进入 genome；搜索动作仍只有剪枝向量和 `q_mode`。每个 `(model, width)` 形成四条严格配对行：

```text
TVM FP16
TVM INT8
TRT FP16
TRT INT8
```

每个模型的 12 个 width 应覆盖：

```text
4 个 diagonal/base/AP anchors
4 个 alignment/padding/disagreement traps
4 个 off-diagonal AP-sensitive points
```

`mixed_policy_id` 默认 `none`，不占用这 96 个 gold 配额。未来 mixed 通过第 4 章的联合准入门后，先作为独立 pilot/feedback batch 增量加入，不要求重建基础 cold-start。

### 5.2 为什么仍采用 96 点

96 不是理论最优常数，而是当前实验预算下的最小平衡设计：

1. 两个模型、两种精度和两个编译后端完全配对，能够直接学习和检验 `shape x q_mode x compiler capability` 的条件效应。
2. 12 个 width/model 比原先 8 个更充分覆盖对角锚、off-diagonal AP 敏感点和 TensorCore alignment/padding 陷阱。
3. 每个 `(model, width)` 是 4 行不可拆分分组；24 个 width-model 组初步可按 20 组训练和 4 组 holdout 评估，即 `80 train + 16 holdout`，且不会把同 width 的不同精度/后端泄漏到两侧。该比例仍须通过 5.7 审查后才能锁定。
4. 96 条仍处于可以完成统一 latency、energy、AP 和 provenance 审计的规模，不需要为尚未证明有效的 topK mixed 额外支付大规模 full AP 成本。

旧 96 设计及其门禁来源见 [20 号能力扫描优先设计](progress/7_14/20_7_14_交接文档_QxS搜索框架改造计划_v2_硬件后端能力扫描优先.md) 和 [21 号文档的 96 点数据审计](progress/7_14/21_7_14_交接文档_RouteB_INT8_AP修复与速度复测计划_v1.md#6-当前-96-点数据集状态)。旧实现实际采用 `12 widths x 8 compiler/precision combinations`；其中 36 条 TVM INT8/mixed 因无有效 AP 或 pipeline 不同源而失效。新设计保留“12 width 覆盖”和“96 点可控预算”，删除未经 gold 证明的 mixed 组合，并把配额转给两个模型、两个有效 q_mode 和 TVM/TRT 配对。

### 5.3 Gold 数据要求

数据要求：

1. latency、energy 全部 H800 真测。
2. numerical pass 的点全部执行统一 gold AP。
3. numerical/build failure 单独记录 feasibility，不进入 AP 回归。
4. 按 width family 分组切分，禁止相邻配置泄漏。
5. `80 train + 16 locked holdout` 仅作为 20/4 完整组的初始候选；同一 `(model, width)` 的四条 backend/precision 配对行必须位于同一侧。最终 split 和目标模型 calibration/test 比例须通过 5.7 的 grouped learning-curve 与迁移审查后锁定，locked test 在模型选择前不可见。
6. FP32 只作为论文 baseline 单独测量，不占 active `fp16/int8` cold-start 配额。
7. mixed policy pilot 不得与基础 96 混写；只有通过正式联合门禁后才作为 measured feedback 增量追加。

### 5.4 旧 180 点数据的重要性复审

旧 180 点的重要性在主搜索轴收缩后**部分恢复**。它覆盖 Pyramid 的 60 个 width 和三种历史精度，仍是当前最密集的宽度结构观测，适合：

1. 学习或审计 width、FLOPs、activation bytes 与 AP/可行性的结构趋势；
2. 从 60 个 width 中选择新 96 设计所需的 12 个 Pyramid 锚点；
3. 识别 old-prior 与自动后端差异最大的 alignment/padding/disagreement 补测点；
4. 作为论文中的 `historical prior vs gold-only` 冷启动消融。

但其证据身份没有恢复为 gold：60 条旧 INT8 来自 historical hand-rewrite `int8_tc`，60 条 FP16 也缺少当前 compiler profile/provenance，不能直接训练最终 backend-conditioned latency/energy head，也不能进入 final frontier。处理方式不是模糊“降权”，而是按任务显式路由：

| 用途 | 旧 180 是否使用 |
|---|---|
| width/AP 结构 prior 与候选选择 | 使用，保留 source class |
| feasibility/disagreement 触发 | 使用 |
| 最终 TVM/TRT latency/energy cost-model gold | 不使用，必须由新 96 同口径实测替换 |
| final Pareto/frontier | 不使用 |
| historical-prior 消融 | 使用，单独报告 |

详细逐行审计和 hand-rewrite 偏差见 [16 号 180 点审计文档](progress/7_14/16_7_14_交接文档_INT8臂_180冷启动数据_最小补测_v1.md)。原始 180 文件保持只读，不覆盖、不伪装成新自动后端测量。

### 5.5 阶段 3 状态更正（2026-07-13）

阶段 3 **尚未收口**。当前 provisional 表有 70 行完整 `latency + energy + AP30/AP50/AP70` Gold 和 2 行 Pyramid TVM-FP16 shape feasibility failure；其余 24 行 TVM-INT8 的直接原因是缺少同源静态输入/输出量化参数合同，应标记为 `blocked_missing_quant_contract`，不能作为最终 numerical feasibility failure。21 号文档已证明 scale-aware TVM INT8 在代表点可获得有限非零 AP，因此该缺口必须修复，不能通过接受 AP 为空来收口。

### 5.6 阶段 3 最终收口（2026-07-13）

24 行 TVM-INT8 已完成静态量化合同修复和完整 AP 重测。最终 Gold96 为 `94 measured + 2 confirmed TVM-FP16 shape failure + 0 pending`，24/24 组完整终态；阶段 3 正式收口。最终表位于 `results/stage3_gold96_final_v3_20260713_int8_repaired/`，详细证据与公共入口修复见 [24 号交接文档](progress/7_14/24_7_14_交接文档_Gold_Coldstart96_v3最终收口_v1.md)。该 JSONL 是阶段 4 的候选 seed Gold，必须先通过 5.7 的数据充分性审查，不能因行数达到 96 就直接锁定。

provisional 数据位于 [`results/stage3_gold96_final_v3_20260713/`](${V2X_ROOT}/results/stage3_gold96_final_v3_20260713/)，仅用于缺口审计，禁止直接作为阶段 4 最终训练输入。详细更正和补测停止条件见 [24 号文档](progress/7_14/24_7_14_交接文档_Gold_Coldstart96_v3最终收口_v1.md)。

### 5.7 阶段 4 前的数据充分性与跨模型校准反思

Gold96 的有效独立单元是 24 个 `(model,width)` 完整组，而不是 96 个独立样本；每个模型只有 12 组，且 Pyramid/CoDriving 仅共享 2 个 width。两模型 AP、latency、energy 的绝对基线明显不同，直接合并 absolute targets 会混淆 model effect 与剪枝/量化趋势。

阶段 4 前采用以下修订设计：

1. 当前 Gold96 定位为学习结构、量化和 capability 条件趋势的 **global seed/base pool**，不直接宣称数据充分或跨模型泛化。
2. global model 优先学习 `Delta AP`、log latency/energy ratio、组内 speedup/ranking；每个模型固定 reference baseline，避免混合绝对尺度。
3. 历史跨模型迁移审查使用少量完整四臂组作为 calibration/locked transfer 单位；该设计用于数据充分性分析，不再规定阶段 5 的在线 acquisition。阶段 5 v2 的目标尺度校准由首批单 genome 反馈在任务内部完成。
4. 用 `K=2/4/6/8` 完整组学习曲线选择最小校准预算，并比较 global-only、local-only K-shot、global+K-shot，检查 negative transfer。
5. cold-start split、bootstrap 和阶段 4 历史 replay 以 `(model,width)` 整组进行，避免配对行泄漏；阶段 5 v2 在线 acquisition 改为固定 profile 下的单 genome。两种单位必须分别报告，不能混称。
6. 在正式 Stage4 前完成 grouped learning curve、双向 few-shot transfer、共同 width 补点需求、重复测量噪声和 failure-boundary 审查；若误差、排序、Pareto recall 或 uncertainty 尚未稳定，先按信息增益扩充 cold-start。

因此在 Gold96 节点，阶段 3 的测量闭环已经收口，但阶段 4 数据集当时尚未锁定。该历史状态已由 5.8 的 Gold176 准入和第 6 章的 Stage4 P1-P3 收口结果更新；完整风险、解决方案和门禁见 [24 号文档第 12 节](progress/7_14/24_7_14_交接文档_Gold_Coldstart96_v3最终收口_v1.md#12-阶段-4-前的-gold96-数据集反思)。

### 5.8 Gold176 更新与阶段 4 准入（2026-07-16）

Gold96 经 Gold128、Gold144 和两轮 failure-boundary targeted supplement 扩展为 Gold176。最终数据包含 `176` 行、`44` 个完整四臂组，其中 `174` 行为完整 `latency + energy + AP` 真测，`2` 行为确认的 TVM-FP16 shape feasibility failure；全部 `348` 个性能/AP 证据文件已通过 SHA256 审计。最终表见 `results/stage35_gold144_targeted_supplement_v2_20260714/final_gold176_v1/`。

Gold144 -> Gold176 的严格诊断显示新增数据具有明确价值：AP70 top-k recall 从 `0.500` 提高到 `0.917`，energy Spearman 从 `0.818` 提高到 `0.910`，Pareto recall p10 从 `0.367` 提高到 `0.667`，HV regret p90 从 `0.298` 降到 `0.122`，整组 prediction-interval coverage 从 `0.333` 提高到 `0.667`。但 latency top-k、`global+K` 对 local-only、Pareto/HV 尾部和整组区间覆盖仍未全部达到严格锁定门槛。

同时确认两项证据边界：

1. Gold176 补点选择读取过 Gold144 holdout 的 sufficiency report，因此原 6 组只保留为 `adaptive_validation_v1`，不能继续承担最终独立 holdout。
2. 继承的 repeat audit 只覆盖旧 Gold128/Gold144 锚点，尚未覆盖 Gold176 新增 8 组。

阶段决策调整为：

1. **阶段 3 数据生产收口**：Gold176 冻结为阶段 4 的 `initial cold-start pool v1`，其规模和趋势质量已经足以启动回归树、target encoding、ranking loss 与 uncertainty head 的比较。
2. **严格泛化审查不阻塞阶段 4**：cold-start cost model 的作用是为第一轮 acquisition 提供可用排序和不确定度，不要求在闭环开始前达到最终预测精度；后续真实测量回流负责持续校准。
3. **后台补点与阶段 4 并行**：新增完整四臂组只针对 latency 分歧、跨模型共同/近邻 width 和区间校准锚点；后台结果作为 measured feedback batch 追加，不回溯改变当前 Stage4 baseline。
4. **阶段 4 采用 nested grouped CV**：原 adaptive validation 不参与最终论文级 lock；模型/loss 候选先在当前 44 组内部完成 grouped/nested 比较，新的独立 holdout 必须在读取任何标签前冻结，并在方法选择完成后一次性使用。

因此可以进入阶段 4，但论文中不得写成“Gold176 已证明跨模型泛化充分”。完整数值、验证器修正、时间预算取舍和后台补点原则见 [25 号交接文档](progress/7_14/25_7_14_交接文档_Gold176有效性验证与阶段3.5收口_v1.md)。

## 6. 阶段 4：回归树与损失函数选择

阶段 4 已于 2026-07-16 完成 P1-P3 工程收口。完整实验、失败反思、Feedback16 增量协议和逐项门禁见 [26 号交接文档](progress/7_14/26_7_14_交接文档_Feedback16_AP收口与阶段4问题反思_v1.md)。本章只保留论文路线需要的冻结结果、优势、不足和阶段 5 准入边界。

### 6.1 已完成的模型与策略选择

阶段 4 没有预设“树模型、rank loss 或 uncertainty 越复杂越好”，而是在 Gold176 基线上比较 raw/log/residual regression、独立 ranker、quantile/ensemble uncertainty 和多种 acquisition。最终冻结结果为：

| 组件 | 冻结结果 | 主要证据 |
|---|---|---|
| latency value head | `extra_trees_log` | nested grouped CV 中 `5/5` outer folds 选择该候选 |
| energy value head | `extra_trees_log` | nested grouped CV 中 `4/5` outer folds选择该候选 |
| AP70 value head | `lgbm_huber_residual` | nested grouped CV 中 `3/5` outer folds选择该候选 |
| 独立 ranker | reject | 相对 value head 的 top-10% recall 平均下降 `0.118` |
| uncertainty | `LGBM quantile + group conformal` | target-wise group coverage 达到准入门槛，且可确定性复现 |
| acquisition | `predicted_frontier_diversity` | 两套固定 replay 均优于 random |

这意味着阶段 4 的最终方法不是一个统一损失强行预测三个目标，而是低容量、多头、按目标选择：value heads 预测 Pareto 坐标，quantile/conformal 给出区间，acquisition 使用预测前沿和结构多样性。独立 ranker 不进入阶段 5 主方法。

这里的 acquisition 选择只在**组级 offline replay**上冻结；它尚未通过阶段 5 v2 的单 genome compatibility 门禁，不能表述为在线单 genome 方法已经验证。

### 6.2 Acquisition 与 Feedback16 的关键结果

所有 acquisition 使用相同初始完整组、seed、预算和候选可见性；未测候选的 latency、energy、AP 标签不可见。达到 95% model-internal oracle HV 所需的中位完整组数为：

| policy | Gold176 | Gold176 random | Gold176+Feedback16 | 对应 random | 决策 |
|---|---:|---:|---:|---:|---|
| uncertainty-only | `22` | `10` | `17` | `13` | reject |
| EHVI | `11` | `10` | `10` | `13` | reject，基线弱于 random |
| 旧 Pareto + uncertainty | `12` | `10` | `15` | `13` | reject |
| predicted-frontier diversity | `8` | `10` | `10` | `13` | **select** |
| EHVI + uncertainty + diversity | `8` | `10` | `13` | `13` | eligible，保留为消融 |

Feedback16 保持为独立 `online_feedback` 批次。合并视图为 `192` 行、`48` 组，其中 `176` 行属于 `initial_coldstart`、`16` 行属于 `online_feedback`，两批 group overlap 为 `0`。严格 leave-one-feedback-group-out 对照表明：

| target | 回流前 | 回流后 | 结论 |
|---|---:|---:|---|
| latency MAE | `1.3531 ms` | `1.4698 ms` | 变差 `8.62%`，拒绝该 target 的更新增益声明 |
| energy MAE | `0.1991 J` | `0.2077 J` | 变差 `4.29%`，但 Spearman 从 `0.871` 升至 `0.924` |
| AP70 MAE | `0.0390` | `0.0291` | 改善 `25.44%` |
| AP70 Spearman | `0.844` | `0.894` | 改善 |
| AP70 interval width | `0.4871` | `0.4682` | 收窄 `3.89%` |

因此，在线回流机制已经跑通，但不能写成“少量反馈必然改善所有目标”。阶段 5 必须为 latency、energy、AP 分别执行更新验收；只有该目标的误差、区间和 coverage 门禁通过，才替换对应 head。

### 6.3 当前优势

1. **保持自动搜索叙事。** q-mode 和剪枝宽度仍由搜索器决定；TVM/TRT 是 capability scan 产生的测量上下文，不作为人工规则写入 genome。TVM-INT8 不被人工删除，模型可以依据真实证据判断其是否值得测量。
2. **冷启动统计单位保持一致。** split、训练和阶段 4 replay 均按 `(model,width)` 完整四臂组执行，避免同一 width 的 TVM/TRT、FP16/INT8 行跨侧泄漏；该规则只约束离线证据，不再强制阶段 5 在线采样成组。
3. **模型容量受证据约束。** 独立 ranker 和纯 uncertainty acquisition 因真实消融失败而被删除，没有为了方法复杂度继续叠加预测头。
4. **组级 acquisition 已超过随机基线。** `predicted_frontier_diversity` 在 Gold176 和 Feedback 增量视图中分别节省 `2` 和 `3` 个完整组，证明策略概念可用；由于阶段 5 v2 改为单 genome，首轮 H800 前仍须完成一次单 genome compatibility replay，不能直接外推组级优势。
5. **反馈不是回溯改写冷启动。** Gold176 保持冻结，Feedback16 只作为 `online_feedback` 增量加入，可以在论文中清楚区分初始先验、在线测量和更新后的模型。
6. **实现采用 fail-closed 审计。** graph/capability 特征拒绝 latency、energy、AP 和状态标签；收口器反查 training source、split、record ID、holdout manifest 和 SHA。Gold176 baseline、Feedback cost model、增量校准以及 ranking/uncertainty/Pareto/replay 均完成逐字节复现。

### 6.4 当前不足与论文风险

1. **尚未证明跨模型普适泛化。** 当前只有 Pyramid 和 CoDriving，OOF 主要是各模型内部的 grouped interpolation。Stage 3.5 的 universal cross-model generalization 仍为 open，不能把阶段 4 结果表述为对任意协同感知网络均有效。
2. **Feedback 收益具有 target specificity。** 本轮只有 AP70 同时满足 MAE 改善、区间不变宽和 coverage 不下降；latency/energy 没有通过相同收益门。阶段 5 需要 target-wise accept/reject，不能整包替换模型。
3. **Pareto 恢复仍不稳定。** Feedback 后 Pareto recall 从 `0.417` 提高到 `0.472`，但平均 HV regret 从 `0.0247` 增加到 `0.0537`。这说明找回了更多前沿成员，却没有同步改善支配体积误差。
4. **Uncertainty 仍偏保守。** Gold176 grouped OOF 的三目标同时覆盖约为 `0.595`；严格 Feedback 留一对照为 `0.75`，但区间仍较宽。当前 uncertainty 适合保护采集，不足以支撑高精度置信区间声明。
5. **Acquisition 证据仍是 offline replay。** 它证明在冻结 measurement pool 上不弱于 random，但尚未证明真实 H800 hardware-in-the-loop 搜索中的 wall-clock、失败恢复和在线收敛优势。
6. **新独立 holdout 尚未测量。** 已在读取标签前冻结 Pyramid/CoDriving 各 2 组，但 source/checkpoint、四臂性能和 AP 尚待阶段 5 物化。它当前只证明评估身份冻结，不构成独立测试结果。
7. **存在两个已确认 feasibility failure 组。** 阶段 4 只在 `42/44` 个 Gold176 完整数值组上评价 value/uncertainty；失败组必须在阶段 5 由 feasibility head/状态机处理，不能静默丢弃或伪造 AP。

### 6.5 论文可声明边界

阶段 4 当前可以支持以下表述：

```text
在两个目标模型和冻结的 H800 TVM/TRT 测量池上，
按 capability 条件化的低容量多头 cost model 可以驱动组级离线采集；
预测前沿多样性在固定离线 replay 中以更少测量达到 95% oracle HV，
且真实 Feedback16 能够对 AP head 产生可复现的增量校准收益。
```

当前不能支持以下表述：

```text
1. cost model 已对未见模型普适泛化；
2. online feedback 会同时改善 latency、energy 和 AP；
3. offline replay 的测量节省等价于真实 H800 搜索节省；
4. 已获得 Pyramid/CoDriving 的最终论文级 Pareto 前沿。
```

### 6.6 阶段 4 收口与阶段 5 准入

阶段 4 的组级离线工程门禁已通过：canonical heads、ranker 决策、组级 acquisition、可复现 Feedback 更新、target-scoped gain、training-source 合同、独立 holdout 身份冻结和 uncertainty calibrator 均已锁定。独立 holdout 标签评估与单 genome acquisition compatibility 仍是阶段 5 v2 前置门禁。状态为：

```text
Stage 4 P1-P3: closed
Stage 5 single-target/single-profile search v2: contract correction required before main search
Stage 3.5 universal cross-model generalization: still open
```

阶段 5 必须继承以下合同：

1. 使用同一搜索入口、genome、候选生成器和预算合同，分别运行 Pyramid/TVM、Pyramid/TRT、CoDriving/TVM、CoDriving/TRT 四个独立 SearchTask。
2. 初始训练视图固定为 `Gold176(initial_coldstart)` 共 176 行；Feedback16 只作为阶段 4 增量机制证据，不进入阶段 5 round-0，27 号 `pre_stage5_smoke`、专项补点和其他历史实测标签同样不可见。
3. value heads、uncertainty 和 acquisition 使用本章冻结配置，除非新的 target-wise feedback 门禁明确通过。
4. 冷启动数据继续按完整配对组防止泄漏；在线搜索以固定 target model、hardware、capability profile 下的单个 `(w0,w1,w2,q_mode)` genome 为 acquisition、测量、反馈和预算单位。
5. 主结果只能包含具有真实 latency、energy、AP 和证据 SHA 的 trusted frontier 点。
6. 将新冻结的 4 组独立 holdout 物化并一次性评估，不允许依据其标签继续选择模型或 acquisition。
7. 在首批 H800 v2 搜索前，用冻结 measurement pool 验证 `predicted_frontier_diversity` 从组级候选迁移到单 genome 候选后不弱于 random，并确认 q_mode 进入实际排序。

阶段 4 对应论文表 **T1：Cost-model and cold-start ablation**。当前已具备 value/ranker/uncertainty/acquisition/Feedback 消融数据；T1 的独立 holdout 行须在阶段 5 物化后补齐，不能提前填写。

## 7. 阶段 5：单目标模型、单 Profile 自主搜索

> 2026-07-18 修正：27 号 P0/P1 将“双模型同步配额”和“width 四臂完整组”误当成正式 acquisition 协议。其 8 行 H800 测量和证据合同仍有效，但只能标记为 `pre_stage5_smoke`，不计入阶段 5 v2 主搜索预算或轨迹。完整反思与实施合同见 [28 号交接文档](progress/7_14/28_7_14_交接文档_阶段5单目标模型单Profile自主搜索反思与预算协议_v1.md)。

### 7.1 单次搜索任务边界

一次搜索任务固定：

```text
SearchTask = (
    target_model,
    hardware_id,
    capability_profile_id,
    coldstart_version,
    search_space_version,
    objective_contract,
    budget_contract,
    seed
)
```

约束如下：

1. 单次任务只面向一个目标模型，例如 Pyramid。
2. 单次任务只在一个硬件设备和一个 capability profile 下运行。
3. TVM 与 TRT 分别启动独立任务，backend/profile 不是 genome 中的可选基因。
4. capability scan 只描述并验证部署上下文，不根据历史性能替用户选择 TVM/TRT；部署栈由 SearchTask 固定，框架在该上下文内自主优化 genome。
5. 四个论文主任务为 `Pyramid×TVM`、`Pyramid×TRT`、`CoDriving×TVM`、`CoDriving×TRT`。
6. 四个任务使用同一入口、schema、搜索空间、预算、batch size、cost-model 配置和停止口径，但在线状态与 Pareto 彼此隔离。
7. 四个任务的初始 cold-start 快照必须在第一项启动前统一冻结，禁止前序任务的新反馈改变后序任务起点。

### 7.2 为什么同时研究 TRT 与 TVM

TRT 与 TVM 不是同一次搜索中的竞争 gene，而是两类独立部署上下文：

1. **部署覆盖**：TensorRT 官方定位为 NVIDIA GPU 推理 SDK；TVM 通过可编程 target 抽象面向更广的编译目标。协同感知可能部署到车端、路侧及异构边缘设备，不能把框架贡献限定为 NVIDIA + TRT。
2. **研究可观测性与可扩展性**：TVM 暴露 Relax/TensorIR、schedule、MetaSchedule、fusion、target lowering 和 BYOC，能够诊断 shape、tensorization、Q/DQ、requant 和 materialization 边界，并扩展新硬件路径。
3. **验证 capability-conditioned 命题**：分别运行同一算法可以验证 capability context 改变后，结构与精度 Pareto 是否改变，以及固定“全局采用 INT8”的软件策略为何不能跨后端成立。
4. **强工业参照**：TRT 提供 H800/NVIDIA 环境中的成熟性能参照；论文不要求 TVM 普遍超过 TRT，而要求搜索器在每个固定 profile 内自主找到合适配置。
5. **engine 部署边界**：TRT engine 默认受设备、平台和兼容配置约束，进一步说明单个 H800/TRT 最快点不能替代 capability scan 和独立部署搜索。

产品支持边界以官方 [TensorRT 文档](https://docs.nvidia.com/deeplearning/tensorrt/latest/index.html)、[TensorRT Support Matrix](https://docs.nvidia.com/deeplearning/tensorrt/latest/getting-started/support-matrix.html)、[TVM Target API](https://tvm.apache.org/docs/reference/api/python/target.html) 和 [TVM Architecture](https://tvm.apache.org/docs/arch/index.html) 为准。

论文叙事固定为：本文不声称 TVM 在 NVIDIA GPU 上普遍超过 TensorRT；TensorRT 代表 NVIDIA 专用高性能路径，TVM 用于验证开放、可观测、可迁移的自动编译路径。贡献是让同一搜索方法在固定 capability context 下自主形成不同结构与精度决策。

### 7.3 Genome 与在线候选单位

主 genome 为：

```text
g = (w0, w1, w2, q_mode)
q_mode in {fp16, int8}
```

按当前离散空间，每个 SearchTask 有 `7×7×7×2=686` 个候选。`target_model`、hardware、capability profile、backend 和 schedule route 均不进入 genome。

在线 acquisition 的最小单位是一个单 genome：

```text
(target_model, hardware, profile, w0, w1, w2, q_mode)
-> latency, energy, AP30/AP50/AP70 or feasibility terminal state
```

选中一个 width 后不得自动补测另一种精度或另一个 backend。相同 width 的 FP16/INT8 只有被 acquisition 分别选中时才会同时测量。冷启动阶段的四臂完整组只保留为趋势学习、反事实比较和 grouped split 单位，不再约束在线采样。

### 7.4 完全自主搜索边界

人工在任务启动前只提供 target model、hardware、capability profile、搜索空间版本、预算、batch size 和 seed。启动后由框架完成：

```text
candidate generation
-> prediction/uncertainty
-> batch acquisition
-> measurement
-> atomic feedback
-> target-wise model update
-> measured Pareto/HV
-> next batch
-> budget exhaustion
-> final validation
```

禁止人工指定下一 width、q_mode、精度配额、跨 backend 配对或邻域补点；禁止因为看到结果临时修改模型、acquisition 或预算。

阶段 4 的 acquisition 优势来自 width 组级 replay。首批真实测量前必须补做单目标、单 profile、单 genome compatibility replay，确认 `predicted_frontier_diversity` 不弱于 random 且确实对 q_mode 排序。该检查是决策单位迁移门禁，不是重新无限期优化阶段 4。

### 7.5 固定搜索预算

阶段 5 v2 的论文主预算为：

```text
N_search = 16 个新 genome / SearchTask
batch_size = 4
round_count = 4
SearchTask 数量 = 4
总在线搜索预算 = 64 个新 genome
```

预算按达到真实终态的 genome 计数，不按 width 组或四臂行计数。每个成功 genome 必须具备 latency、energy、full AP 和证据 SHA；真实 build/shape/numerical feasibility failure 也消耗预算。GPU、SSH、磁盘或公共 runner 错误不消耗候选预算，最多重试两次，仍失败则暂停任务修复并以原 request 恢复。

同时审计 unique-width source materialization、checkpoint/ONNX/calibration、backend build/tune、full AP 和总 wall-clock。同一 width 的不同 q_mode 可以复用模型 source，但仍分别消耗一个 genome 预算；论文必须同时报告 sample budget 与实际计算成本。

为保证四个任务及阶段 6 对比公平，论文主搜索固定执行 16 点，不使用结果驱动的提前停止。HV 增益与 frontier stability 只作为收敛曲线报告。

### 7.6 批量采样协议

每轮以同一个冻结快照预测全部未测 genome，由 `predicted_frontier_diversity` 一次选择 4 点。批内：

- 不规定 FP16/INT8 比例；
- 不要求 width 不重复；
- 不要求精度成对；
- 不要求 TVM/TRT 选择相同结构；
- 可以并行测量，但 4 点全部获得可信终态前不得使用部分结果更新模型；
- batch 结束后原子追加反馈，每轮只更新一次 cost model 和一次 Pareto/HV；同一批的相同 width 可复用模型 source，但仍保持独立 genome 身份和预算。

每轮必须保存训练快照 SHA、模型 SHA、候选预测、acquisition 分解、4 条 request、测量/AP 证据、预算计数、target-wise head accept/reject、Pareto/HV 和可恢复状态。

### 7.7 Cold-start 与目标任务校准

四个任务统一从冻结的 `Gold176 initial_coldstart` 训练视图启动。`Feedback16` 只保留为阶段 4 增量机制证据，与 27 号 `pre_stage5_smoke`、专项补点和其他历史实测标签一样，不进入阶段 5 round-0 训练、候选过滤或排序。Gold176 用于训练 global trend model，而不是把两个模型绑定在同一次搜索中；首批正式反馈只在当前 SearchTask 内完成目标尺度校准，不允许人工指定 calibration width。

四个任务的完整搜索空间均固定为 `M=686`。Gold176 中同一目标任务且落在规范 343-width 网格内的合法已知行进入初始 observed set，不重复消耗在线预算；Pyramid 每个 profile 已知 42 行、round-0 未观测 644 行，CoDriving 每个 profile 已知 38 行、round-0 未观测 648 行。Gold176 的网格外点可参与 global trend 训练，但不从规范候选全集扣除。checkpoint/ONNX 是否已存在不能缩小搜索空间，只能在候选被选中后影响 lazy materialization 成本。候选池错误、历史证据泄漏、启动前回放风险及旧 round-0 隔离规则见 [28 号交接文档第 15 节](progress/7_14/28_7_14_交接文档_阶段5单目标模型单Profile自主搜索反思与预算协议_v1.md#15-2026-07-18-候选池与历史证据泄漏反思)。

27 号的 8 行真实 smoke 统一冻结为 `pre_stage5_smoke` 诊断数据，不进入 v2 初始训练、不计入任何任务的 16 点预算，也不能充当 v2 搜索轨迹。

### 7.8 独立最终验证预算

每个 SearchTask 在 16 点搜索结束后最多选择 4 个可信 Pareto 配置做独立验证：latency/energy 进行 3 次独立重复并报告均值、标准差和 CV；AP 对冻结 artifact 做一次 full evaluation 与 SHA 审计。验证结果不回流模型，`N_verify<=4` 单独报告，不与搜索预算混排。

### 7.9 执行顺序与收口

先完成 v2 合同测试和四任务确定性 dry-run，再执行 Pyramid/H800/TVM 的第一个 4 点真实 batch。这里的执行顺序不等于人工选点；4 个 genome 必须全部由 acquisition 产生。

随后按冻结顺序完成四个独立任务。此前基于错误 `M0=100/640` 完成的 Pyramid/TVM round-0 降级为 `invalidated_stage5_pilot`，保留 runner 证据但不计入正式预算。阶段 5 只有在修正后的四个任务各完成 16 个新 genome、生成四份真实 Pareto/四条 HV 曲线、完成预算审计、泄漏审计和独立验证后才收口。

阶段 5 工程收口后即可进入阶段 6；“优于 random/旧策略/六臂基线”不是阶段 5 的先验门槛，而是阶段 6 需要在相同 `M/B/T` 下回答的有效性问题。若阶段 5 存在历史标签泄漏、预算未耗尽、跨任务反馈或证据缺失，则不得进入阶段 6。

## 8. 阶段 6：方法有效性六臂对照

在 TVM 上执行完整六臂：

```text
1 original/default
2 compression-only
3 schedule-only
4 compress -> tune
5 tune -> compress
6 joint SHCoSearch
```

公平性要求：

1. TVM 六臂主表统一使用同一份 TVM-only 初始证据视图；TRT-derived prior 不进入该主表。跨 profile transfer 另列消融，不得只让本文方法获得额外 TRT 信息。
2. `16 genome、batch_size=4` 只直接适用于在同一 `(w0,w1,w2,q_mode)` 空间中执行采集的搜索型方法，不能机械套给 `original/default` 或内部 schedule trial。
3. `original/default` 作为固定参考点，只报告一次标准构建和独立重复测量，不伪造 16 次搜索预算。
4. `schedule-only` 固定结构与精度，其公平预算按 backend tuning trials/GPU 时间定义；`compression-only`、两个 serial 方法和 joint 方法的 action space、q_mode 权限、候选测量数及 tuning trials 必须在 Stage6 arm manifest 中逐项冻结。
5. 搜索型可比臂使用相同真实 candidate-measurement 上限、batch 协议和 AP 验证预算；不同内部动作还必须报告 backend tuning trials、GPU-hours 与 wall-clock，不能只比较样本数。
6. Stage6 在 arm-specific action/budget manifest 审查通过前不得启动。该 manifest 必须解释无搜索固定臂、结构搜索臂、schedule 搜索臂和 joint 搜索臂的预算如何对应。
7. 禁止旧 9-width LUT、legacy `343 widths x 3 precisions = 1029` 空间与当前 active `343 widths x {fp16,int8}` 空间混用。

TRT 不应强行复制六臂，因为 TRT 没有严格的“untuned”模式，原始臂与 schedule-only 会退化成同一项。TRT 更适合作为 backend generalization：

```text
size/FLOPs-driven compression
serial compression then TRT build
hardware-feedback joint search
```
