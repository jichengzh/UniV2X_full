## 〇、这篇论文一句话

> **给定任意待加速网络 + 一档目标硬件 + 一份部署 SLA，框架自动产出该硬件上的多目标 Pareto 前沿（精度 × 延迟 × 吞吐 × 能耗 × 体积），并给出满足 SLA 的最优部署方案。**

- 不是"主模型在多硬件上调优"，而是"**框架在 N 网络 × M 硬件上的自适应能力**"。网络与硬件 capability YAML 是**对称的输入参数**，不是叙事主角。
- 硬核差异化 = **剪枝 × 量化 × 硬件部署(D) 联合搜索 + 事前规避耦合陷阱（kernel-cliff, ISS-014）**，对位 QuantV2X（量化 only、事后才知崩）。

## A.4 数据引用纪律 ★（本项目签名级规矩，写进每条实验句）

来源：`background/00_研究目标与实验档案_v1.md` §三「通用引用纪律」。**违反即 reporting failure。**

1. **每个数字标来源分级**：真测 / 估算 / 预测（LGB/KNN/rule-based）。表格里 latency 必须能追到 CUDA-Event / trtexec / 预测器。
2. **subnet ≠ e2e**：body subnet latency 还要叠 voxelize/NMS ~6–10ms，不可当 e2e 报。
3. **未 finetune 的剪枝/改结构子网 AP 一律不作有效数据**（`stage_b_ap_real` ap50≈0.055 是反例；金标准只有 `stage_a_ap_real`）。
4. **禁跨模型拼曲线**：`baseline_4090`/`unified_bench` 是多模型混表，必须先按 `model_class` 拆。
5. **"某方案无价值/无收益"结论，延迟轴 + AP 轴都有数据才能下**；只测延迟时精度轴必须明写"AP 未测，价值未定"。
6. **预测值永标"预测"**，不与真测混列。

## B.1 Introduction（明确"加速对象"，不许只写 efficient）

收敛到一个具体矛盾，6 拍：
1. **真实任务**：V2X 协同感知要在边缘 SoC（Orin）与数据中心 GPU（4090）上满足**双硬实时约束**（延迟 ≤ 控制截止 且 吞吐 ≥ 输入帧率）+ 能耗预算。
2. **现有方法的不现实假设**：单维优化（只量化 / 只剪枝）、硬件当 latency LUT 黑盒、量化"事后才知崩"。
3. **导致的失败模式/成本瓶颈**：局部最优组装出整体次优；耦合陷阱（剪枝×量化×硬件互相抵消收益）；V2X-ViT INT8 崩（AP50 49.5→11.0）。
4. **本文新视角**：把 B1/B2/D 纳入**同一搜索器联合求解**，硬件以**可读 capability YAML** 进入流程，预测器 + 约束传播**事前**规避崩溃。
5. **方法直觉**：5 指标预测器 + regime 条件多目标 selector + D↔B2 双向约束传播。
6. **贡献（3 条，可验证）**：即 Method 三个技术点——①硬件 YAML + 一次前向搜索（类 UAPQ，部分为 future work）；②B1×B2×D 联合搜索空间构建 + 耦合陷阱事前规避；③5 指标预测器 + regime 条件 Pareto selector（见 B.4）。
> 明确加速对象 = 推理延迟 / 吞吐 / 能耗 / 显存（**不是训练时间**，别被 `.md` 调研的"训练加速"框架带偏）。

## B.2 Related Work（按问题类别，每段末句点差异）

五类 + 各自差异（对位本文的真实对手，不是调研里那批）：
1. **边缘 AV 上的剪枝+量化协同（最接近的对手）**：UPAQ（[arXiv:2501.04213](https://arxiv.org/abs/2501.04213)，pattern 剪枝 + 混精量化做 3D OD 于 Orin Nano，标量 efficiency score）→ 本文 **加硬件部署维度 D（DLA 路由/tactic/对齐）联合 + 多目标 Pareto + 跨硬件 capability YAML + V2X 协同感知**（UPAQ 是单车单平台、标量打分、无 D 维）。
2. **V2X 协同感知量化部署**：QuantV2X（量化 only、2.2×、事后报崩）→ 本文 **B1×B2×D 联合 + 事前规避**。
3. **硬件感知 NAS / 量化**：APQ、HAQ（硬件作 LUT 黑盒）→ 本文硬件以 **capability YAML** 进入。
4. **硬件感知剪枝**：HALP、LightPrune（单维 + latency LUT）→ 本文**多维联合 + D↔B2 双向传播**。
5. **官方 BEV 部署**：CUDA-BEVFusion / DL4AGX uniad-trt（手工调参最优部署）→ 本文**自动化 Pareto 搜索**（手工调参作 baseline 而非对手）。

## B.3 Problem Formulation（AAAI 评审对设定漏洞敏感）

写清：
1. **输入/输出/目标**：输入 = (待加速网络的 module 字典, 硬件 capability YAML, SLA)；输出 = Pareto 前沿 + 满足 SLA 的最优 DeployPlan。
2. **5 个一级指标（Pareto 轴）**：AP（主用 AP70）↑、latency ↓、throughput ↑、energy(J/frame) ↓、model_size ↓。**AP 是常驻纯目标轴，不作约束**（用户拍板 v2，ISS-018 部分撤销）。
3. **资源预算 / SLA 约束**：throughput ≥ FPS 下限、model_size ≤ 显存预算。
4. **regime 条件**：默认主前沿 (AP, latency, energy) 3D；**RSU / 吞吐-binding regime 把 throughput 切为目标轴**。
5. **搜索空间**：B1（剪枝率×对象×准则）× B2（位宽×粒度×对象×校准器）× D（设备路由×tactic×对齐×调度）× batch。**量级须统一口径并标注**（背景档存在 10^15/10^14/~432 多口径，正文要统一，标"待确认"已知）。
6. **与已有设定的差异**：throughput 在非流水线场景 ≈1/latency（实测相关 0.9996），**唯有加 batch 轴/异构流水才解耦**——这是把 throughput 立为独立目标的合法性论证。

## B.4 Method（总览图 + 三个技术点 = 框架完整流程）

Method 按**优化框架的流程顺序**组织成三个技术点，一张总览图贯穿（硬件 YAML + 网络 → 一次前向搜索定可行域 → 联合搜索空间 → 预测器 + Pareto selector → DeployPlan）。

> 关于旧 C1–C4 framing：原"C2 双向传播 / C3 联合搜索"拆成两个 contribution 是人为的——传播只是**联合空间内部把硬件维度耦合到量化维度的约束机制**，和"在该空间上搜索"是同一件事。本结构把它们合并进技术点 2，更顺。

### 技术点 1 · 硬件 capability YAML + 一次前向搜索（**待开发，诚实标 future/部分实现**）

- **硬件 capability YAML**：把硬件抽象为 (IP 列表, 精度集合, 对齐约束, 算子白名单, 工具链)；这是"通用/可移植"的载体，驱动动态约束（如 Orin 通道对齐由 hard 降 soft，解放 ~30% 空间）。
- **网络的一次前向搜索**：对待加速网络做**一次前向遍历**，结合 capability YAML 自动标定每个 module/layer 的**可行优化档位**（可否 INT8、可否路由 DLA、对齐是否满足、敏感度），一次性圈定**合法可行域**，避免逐配置试错。
- **与 UPAQ 的关系（对位 + 差异）**：UPAQ（[arXiv:2501.04213](https://arxiv.org/abs/2501.04213), 2025）是最接近的已发表工作——半结构化 pattern 剪枝 + 混精量化做 3D 目标检测（PointPillar/SMOKE）于 Jetson Orin Nano，用一个标量 **efficiency score（精度/延迟/能耗加权）**迭代选 pattern。但 UPAQ：①剪枝+量化档由 ES 迭代/随机 pattern 决定，**不是硬件感知的一次前向可行域标定**；②硬件不是显式可读描述（无 capability YAML）；③单平台、单车 3D OD，**非 V2X 协同感知**；④标量 ES 而**非多目标 Pareto**。本技术点的"capability YAML + 一次前向圈可行域"正是要在 UPAQ 之上补 hardware-aware 与可移植性。
- **诚实定位**：此功能**目前尚未开发**。论文里要么标为 future work，要么写"当前以离线 capability 标定 + 约束过滤近似实现，一次前向搜索为下阶段工程"。**不可声称已 demonstrated。**

### 技术点 2 · 联合维度搜索空间的构建（B1×B2×D 一体，**本文硬核**）

这一节合并讲清"我们的优化方法 = 如何建出一个剪枝×量化×硬件联合可搜的空间"：

1. **维度建设**：统一配置契约 `Config`（module 粒度承载 B1/B2/D 全部旋钮，不可变）；module 字典解耦"模型"与"维度"，搜索器代码对 UniV2X 5 模块 / Pyramid 单模块都不改。
2. **剪枝 B1 怎么实现**：DepGraph 全网结构化剪枝（剪枝率 × 对象 channel/head/2:4 × 准则 L1/FPGM/Taylor/Wanda）；**剪后必 finetune 才算有效 AP**。
3. **量化 B2 怎么实现**：位宽 INT8/FP16/FP32 × 粒度 per-tensor/per-channel × 对象 W-only/W+A × 校准器 minmax/percentile；**框架用 TRT-auto 全局精度，而非枚举手工 per-stage 混精**（per-stage 在 4090 上 AP 有正向点但被 TRT-auto 支配，Pareto 无用）。
4. **硬件维度 D 怎么调控**：设备路由 GPU/DLA、TRT tactic、对齐、调度；**D↔B2 双向硬约束传播**——"路由 DLA → 强制 per-tensor+INT8+W+A"，反向"选 per-channel → 禁 DLA"（`propagation.py`）。这是硬件维度调控量化/剪枝合法性的核心机制。
5. **为什么必须联合而非串行**：三者存在**耦合陷阱**（剪枝×量化×硬件互相抵消收益），局部最优组装出整体次优；只有联合搜索 + 事前约束过滤（物理硬/经验硬/软惩罚三类）能规避。kernel-cliff（ISS-014）是实证。

### 技术点 3 · Pareto 前沿设计 + 5 指标预测器构建（框架的"评判 + 决策"）

- **5 指标预测器**：统一一套模型预测 (AP, latency, throughput, energy, model_size)，多场景复用。现状诚实写：AP 预测器主模型 R²=0.94 可作排序；**latency LGB 跨数量级崩塌已弃用 → rule-based**；throughput/energy 预测器待建（energy 从 E4 真测起步，throughput 非流水线场景 ≈1/latency 可派生）。
- **Pareto 前沿设计**：5 个一级目标轴，**AP 是常驻纯目标轴不作约束**（用户拍板 v2）；默认主前沿 (AP↑, latency↓) 双核心 + energy；throughput≥FPS下限 + size≤显存预算作 SLA 约束。
- **regime 条件 selector**：NSGA-II 在前沿选点；**RSU/吞吐-binding regime 把 throughput 切为目标轴**；按 SLA 推荐 anchor。
- **跨硬件 Pareto 对比**：同一网络在 4090 / Orin 上独立搜出的前沿揭示最优解结构差异（4090 偏 per-channel+sparse TC，Orin 偏 DLA 子图+per-tensor）。

### （可选小节）技术点 4 · 时延感知闭环仿真 + 算力分离测试

- **时延感知回灌**：按真实推理时延后推帧对齐，无路测信息时 ego 沿用上一帧感知；CARLA 闭环跑 时延×driving score/碰撞率。
- **算力分离测试**：CARLA 与推理分 GPU/分设备，避免仿真器抢占污染时延测量。
- **放置建议**：这部分简单，**可作 Method 末尾小节，或并入 Experiments 的时延/Pareto 部分**（闭环 driving score 视进度决定是否进正文，否则进 appendix）。

**全章必须解释"为什么会快"**：替代昂贵模块（CUDA-NMS 代替串行 NMS）、复用预训练（剪枝 finetune）、降搜索空间、利用稀疏/对称/低秩，以及**为什么联合搜索能规避耦合陷阱**（局部最优≠全局最优）。

## B.5 Analysis（理论/机制——AAAI 很加分）

无纯理论定理，则给**机制级 + 成本级**分析：
1. **搜索空间量级**论证（为什么必须 predictor+selector，不能穷举）。
2. **耦合陷阱 kernel-cliff 机理**（ISS-014）：TRT 逐层 profile 实证 stage0 grouped-conv kernel-selection cliff，惩罚**非解析、对齐 LUT 不可预测 → 必须真测**——这是"为什么要联合搜索"的硬证据。
3. **M2 跨平台 latency 映射 f 函数**（4090→Orin，R²>0.995）：给框架"通用/可移植"以可量化支撑。
4. **成本分解**：prune/quant/deploy 各自贡献的延迟与能耗份额（如 INT8 省 30–52% J/frame）。

## B.6 Experiments（同时报"效果指标 + 成本指标"，缺一不可）

1. **Main Results**：4090 + Orin × {Pyramid, F-Cooper, AttFuse, V2X-ViT} 的 Pareto 前沿；对比 QuantV2X / 手工调参 baseline。
2. **Ablation**：拆掉联合搜索→串行（技术点 2）；拆掉 D↔B2 约束传播→事后崩；拆掉预测器→穷举不可行（技术点 3）。每个技术点都要有对应消融。
3. **Efficiency**：wall-clock、engine size、throughput(fps)、energy(J/frame)、显存。
4. **Robustness/Generalization**：跨硬件（4090↔Orin）、跨网络（卷积融合→attention→transformer 复杂度谱系）、异构 GPU∥DLA 多进程并行（1.34× 真硅片重叠）。
5. **诚实负结果（加分）**：Pyramid/DAIR 过参数化下 **AP 近常数、INT8 近免费、剪枝难样本代价不放大**——按 ISS-015 判据诚实呈现为"前沿沿 AP 轴塌缩"，不硬凑。
6. **Reproducibility**：硬件、TRT 版本、随机种子、stage_a AP 金标准、代码链接。

> **数据真实性边界**（写进 caveat，别越界）：完整 (lat+AP) 点 58 行、5 指标完整 50 行、独立锚点 ~5 架构；剪枝+INT8 总加速 6.4–6.7× 在原始横向对比里标的是"预测/估算"，**非真测**，引用必标。
