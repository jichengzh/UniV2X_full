## 3.1 阶段一：面向部署的网络–硬件协同刻画

### 动机

剪枝（B1）、量化（B2）与部署（D）三维联合的协同搜索空间，必须先确定其**合法配置集合**才能枚举，而该集合由**网络结构**与**目标加速器**共同决定。剪枝率只能挂载在结构上被强制同时剪除的通道组上；一个模块可行的量化粒度取决于它被映射到的硬件 IP；设备路由空间本身则由算子白名单所能接纳的子图来界定。因此，阶段一执行一次性的、面向部署的协同刻画，把一个*理论上*可配置的网络翻译为*具体的*搜索变量及其可行取值范围。它由两条并行扫描构成——硬件能力扫描（A）与网络计算图扫描（B）——二者的产物汇合为一份分区清单（partition manifest），供阶段二的联合搜索消费。

### 硬件能力刻画（子流程 A）

我们将每个目标加速器抽象为一份机器可读的能力描述 $\mathcal{H}=\langle\mathcal{I},\mathbf{a},\mathcal{Q},\mathcal{T}\rangle$：其中 $\mathcal{I}$ 枚举可用计算 IP（GPU、DLA 核、或厂商 NPU），各自标注支持精度，并在适用时附带算子白名单 $W$；$\mathbf{a}$ 给出 Tensor-Core 的通道对齐要求（如 $a_{\text{int8}}=32,\ a_{\text{fp16}}=8$）及其强制模式 $\{\textit{hard},\textit{soft},\textit{auto}\}$；$\mathcal{Q}$ 刻画量化约束（对称性、是否支持逐通道激活、可行位宽与粒度）；$\mathcal{T}$ 记录锁定的工具链版本以保证可复现。关键在于，该描述是**能力驱动**而非设备特定的：当目标硬件不含 DLA 时，设备路由轴自动退化为仅 GPU，所有由 DLA 引入的约束被一并移除——因而同一套流程无需改动即可特化到异构硬件。

### 计算图依赖分区（子流程 B）

主流 V2X 检测器把稠密、定形的卷积子网络，与稀疏、数据依赖的阶段（如柱状体素化、Lift-Splat-Shoot 投影）以及多智能体融合交织在一起。我们通过一个**每模型的薄 trace 适配器**，仅隔离出**稠密、通道耦合的核心**——这是唯一可做结构化剪枝与静态追踪的部分：稀疏编码器被排除在追踪之外，通道保持的协同融合则经其单智能体路径被绕过（它不改变通道基数）。在该核心上，我们采用 DepGraph 的算子耦合分析构建依赖图，自动识别出**通道必须联合剪除的最小层集合**——由残差相加、张量拼接与分组卷积所诱导的耦合。由此在同一张图上派生出三个视图：

1. **B1——剪枝组。** 每个依赖组 $g$ 是一个结构上可剪的最小单元，标注其代表通道宽度 $w_g$、由硬件导出的**剪枝粒度对齐** $\lfloor w_g\rfloor_a$（合法剪宽步长，对分组卷积取 $a_{\text{int8}}$ 与组数的最小公倍数）、由此得到的最大剪枝率 $r^{\max}_g=(w_g-\lfloor w_g\rfloor_a)/w_g$，按层类型推断的候选重要性准则集合，以及一个**与剪枝粒度正交的 INT8 可建对齐** $a^{\text{int8}}_g=\text{打包因子}\times\text{组数}$（dp4a/WMMA 沿 per-group 输入轴的打包约束：$w$ 可建 INT8 当且仅当 $a^{\text{int8}}_g\mid w$）。二者分离是关键——一个宽度可"结构上合法可剪（$\lfloor w_g\rfloor_a$）却不可建 INT8（$a^{\text{int8}}_g$）"，这正是剪枝×量化耦合陷阱的载体。$a^{\text{int8}}_g$ **不叠加** $a_{\text{int8}}$（后者是 TRT 张量 tiling，只进剪枝粒度）：两模型实测交叉定标确认（分组 Pyramid $4{\times}32{=}128$；标准卷积 CoDriving $4{\times}1{=}4$ 全可建，若误叠 $\mathrm{lcm}(32,4){=}32$ 会假判窄宽度不可建）。
2. **B2——量化单元。** 将层映射到语义桶（backbone / BEV-encoder / neck / heads），每个量化单元定义为该桶内**若干完整 B1 组的并集**。这保证量化边界永不切碎一个耦合组，从而使 B1 与 B2 视图**由构造保持一致**；可行位宽与粒度继承自 $\mathcal{Q}$。
3. **D——路由标注。** 每个算子标注其类型，并在给定 $\mathcal{H}$ 时由白名单 $W$ 标注其 DLA 可达性。

**计算图扫描模块的输出**形式化为一份**三视图分区** $\mathcal{G}=\langle \mathrm{B1},\mathrm{B2},\mathrm{D}\rangle$（与硬件扫描输出 $\mathcal{H}$ 对称）：其中 $\mathrm{B1}=\{\,g=(w_g,\ \lfloor w_g\rfloor_a,\ a^{\text{int8}}_g,\ r^{\max}_g,\ \text{crit}_g,\ \text{grouped}_g,\ \text{coupled}_g)\,\}$ 为带剪枝粒度对齐 $\lfloor w_g\rfloor_a$、与之正交的 INT8 可建对齐 $a^{\text{int8}}_g$、及耦合标注的剪枝组集合；$\mathrm{B2}=\{\,u_j=\bigcup\{g\in\text{桶}_j\}\ \text{附}\ (\text{bits}_j,\text{gran}_j,\text{quantizable}_j)\,\}$ 为完整 B1 组并集构成的量化单元集合；$\mathrm{D}=\{\,(\text{算子},\ \text{device}\in\{\mathrm{GPU},\mathrm{DLA}\})\,\}$ 为逐算子路由标注。$\mathcal{G}$ 与 $\mathcal{H}$ 即两条并行扫描的产物。

我们强调，分组由**数据流耦合**而非模块名决定：这能够还原出基于名称的分区会遗漏的跨模块依赖——例如主干 stem 被强制与 BEV 编码器的第一个残差 stage 联合剪除。

### 从结构真相到搜索变量

依赖组构成可独立剪除单元的*结构最小集*，但若将每个组都视作自由变量，将产生不可枚举的空间：设自由依赖组数为 $G$、每组离散合法剪枝档数约 $b$（由 $r^{\max}_g$ 按对齐步长离散得到），则自由空间规模 $\prod_{g}|R_g|\approx b^{\,G}$；我们最大的模型 pyramid-lidar 有 $G=43$ 个自由组、$b\approx 6$，故约 $6^{43}\approx 10^{33}$。为此我们引入一个**整合层**，区分*结构真相*与*搜索旋钮*。沿用 UPAQ 的"每组统一剪枝率"原则与剪枝感知 NAS 中常见的按 stage 分配策略，我们把共享同一语义桶与 stage 索引的组绑定为单一剪枝率旋钮；由于绑定只放弃自由度，故始终合法。整合后的旋钮继承成员中*最紧*的上界 $r^{\max}=\min_g r^{\max}_g$，及成员准则集合的*交集*。对称地，逐算子的路由标注被折叠为**最大连续可路由子图**——这才是真实的决策粒度，因为每一次 GPU$\leftrightarrow$DLA 切换都会引入一次重排（re-format）开销——从而把路由决策压缩为少数几段的放置选择。该整合把 $G$ 个组绑定为 $K$ 个 stage 旋钮（$K\!\ll\!G$），搜索空间随之从 $b^{\,G}$ 降为 $b^{\,K}$，压缩比约 $b^{\,G-K}$：以 pyramid-lidar 计，$43\!\to\!5$ 旋钮即 $6^{43}\!\to\!6^{5}$，$6^{5}\approx 7.8\times10^{3}\approx 10^{4}$，压缩比 $\approx 6^{38}$。即把剪枝搜索空间从约 $10^{33}$ 压缩到约 $10^{4}$，同时保留结构视图（$\mathrm{B1}$ 全集）作为事实依据。

### 双向耦合、有效性校验与产出

两条扫描双向耦合。硬件约束网络视图（$A\!\rightarrow\!B$：对齐固定剪枝下限，量化约束固定可行位宽，白名单固定可路由性）；网络反向塑形硬件侧决策空间（$B\!\rightarrow\!A$：算子集合裁剪扫描范围，算子标注*定义*路由分段，参数/激活足迹对照显存预算构成 SLA 可行性闸门）。由路由诱导的精度约束被记录为 D 与 B2 视图之间的显式传播边（被映射到 DLA 的模块被强制为 INT8/per-tensor），因而分区清单是一个**耦合结构**而非三张相互独立的列表。本阶段的一切*合法性*耦合均为结构性的；**逐候选**的性能反馈推迟到搜索回路。

### 基线延迟刻画（描述性旁注）

结构视图回答了"哪些单元可调、合法取值是什么"，但没有回答"时间花在哪、先动哪个最值"。为此，我们在分区扫描内再嵌一步**一次性、面向目标加速器的基线延迟刻画**：复用上述前向，对未优化基线的每个稠密算子施加计时探针（GPU 上以 CUDA-Event 链式计时），再沿**与结构视图同一套层名**把逐算子时延聚合回 B1 搜索旋钮与 B2 量化单元，使每个搜索变量都附带一个"它占多少延迟"的权重。这一权重供阶段二**优先把压缩预算投向高占比单元**（呼应 NetAdapt/AMC 的延迟-查表思路）。需强调的是，它是**描述性旁注而非合法性约束**：它刻画的是*基线*的静态延迟分布（与硬件能力刻画同性质，皆为搜索的*输入先验*），与搜索回路里*逐候选实测*的动态反馈截然不同——因而并不破坏本阶段"只做结构耦合"的边界。延迟须在空闲的目标加速器上实测，并连同口径（子模块/端到端、是否含体素化与 NMS）与设备占用快照一并记录；无法在目标硬件实测时如实标注为未测，不以代理硬件冒充。

最后，每份分区通过一次"试剪"加以校验：以 $0.5$ 的比率对稠密核心做物理通道剪除并执行一次前向，确认所声明的组确实可联合剪除且对齐得以保持；失败被如实记录而非掩盖。**整合与校验模块的输出**形式化为一份分区清单 $\mathcal{M}=\langle \mathcal{H},\ \mathcal{G},\ \Theta,\ \lambda,\ \kappa,\ v\rangle$（汇合前两模块的 $\mathcal{H}$ 与 $\mathcal{G}=\langle\mathrm{B1},\mathrm{B2},\mathrm{D}\rangle$，并新增四项）：其中 $\Theta$ 为**整合后的搜索变量**——约 $K$ 个 per-stage 剪枝率旋钮、$2\!-\!4$ 个连续路由段、各量化单元的合法位宽/粒度，即真正交付阶段二枚举的低维空间（$|\Theta|\approx10^{4}$）；$\lambda$ 为附在各旋钮上的基线延迟权重（描述性输入先验）；$\kappa$ 为**逐旋钮的内外环耦合分数**（见下）；$v$ 为试剪校验状态。$\mathcal{M}$ 即为阶段二联合搜索的输入。

**逐旋钮耦合分数 $\kappa(\theta)$ —— 驱动阶段二内环预算的分流信号。** 阶段二是一个"外环（软件 $P\times Q$）× 内环（调度 $S$）"的嵌套搜索；对全部旋钮无差别地付内环（调度自动调优）代价高昂，但并非每个旋钮都值得。我们让阶段一为每个搜索旋钮输出一个**纯结构推导**的耦合分数 $\kappa(\theta)\in[0,1]$，由两项构成：(i) **量化-可建悬崖** $\propto\log_2(a^{\text{int8}}_g/\lfloor w_g\rfloor_a)$——当 INT8 可建对齐严于剪枝粒度时，剪宽（$P$）决定 INT8（$Q$）是否可达，即 $P\times Q$ 耦合（解析量，直接来自对齐数）；(ii) **调度调优余量**——分组/非标卷积的快核命中与可融合性随宽度重建，调优余量大、且依赖宽度，即 $P\times S$ 耦合（结构先验，由跨模型实测 TVM 增益定标：分组 $\approx\!8.7\times$ vs 标准 $\approx\!2\times$；有逐块实测则优先）。阶段二据此**逐旋钮**分流：$\kappa\!\ge\!\tau$ 的高耦合旋钮，其宽度与调度**联合搜**；$\kappa\!<\!\tau$ 的旋钮，在默认调度下锁定外环最优、**串行**处理以省内环预算。这把全局"联合 vs 串行"细化为**逐块自适应**——耦合在哪儿、联合搜的预算就花在哪儿。**关键：可分离性是被测量的、不是被规定的。** 在 Pyramid 上，$\kappa$ 自动把三个分组 BEV 旋钮判为联合搜、其余串行（恰好复现了消融实验里真正被联合搜的宽度轴）；在 CoDriving / V2X-ViT 上，全部旋钮 $\kappa$ 低于阈值 → 全可串行（与"串行即最优"的实测判决一致）。整条链路（导入网络 → 自动建空间 → 算耦合分数 → 阶段二分流）已打通并经回归/等价/跨架构/新架构四项验收。

## 图 1 配图说明（Figure 1 caption）

**图 1. 阶段一：面向部署的网络–硬件协同刻画流程。** 左侧为硬件能力扫描（A），将目标加速器刻画为能力描述 $\mathcal{H}$（IP 列表、对齐、量化约束、算子白名单）；右侧为网络计算图扫描（B），经薄 trace 适配器隔离稠密核心后，由 DepGraph 依赖分析在同一张图上派生三视图——B1 剪枝组、B2 量化单元（=完整依赖组并集）、D 路由标注。中部"汇合"将二者耦合：实线箭头表示硬件约束软件取值（$A\!\rightarrow\!B$），虚线箭头表示网络反向塑形硬件侧（$B\!\rightarrow\!A$），D 与 B2 之间的双向边表示路由–精度硬约束传播。整合层把 B1 的 $N$ 个结构耦合组按 stage 绑定为约 5 个剪枝率旋钮、把逐算子路由标注折叠为 2–4 个连续路由段，将搜索空间由约 $10^{33}$ 压缩至约 $10^{4}$。底部经"试剪 0.5 + 前向"校验后，输出分区清单（partition manifest）供阶段二联合搜索消费。虚线灰块（稀疏编码器、多智能体融合）为不可追踪部分，被排除在结构化分区之外。
