> ⚠️ 本文是**早期 6 点视图**(`sources/complete_points_pyramid_v1.csv`)的指标词典, 列含义仍适用; **最终完整表是 `dataset_v2.{csv,parquet}`(65 行 × 93 列, v2 schema), 列定义以 `schema_v2.md` 为准**。
> ★**2026-06-12 维度精简**: 给模型学习用 `dataset_v2_learning.{csv,parquet}`(全表减 28 列: 8 开环冗余 + 20 闭环非核心, 并剔 norsu 行), **开环每维度只留一个规范值** —— 精度`ap70` / 延迟`lat_p50_ms` / 吞吐`throughput_fps` / 能耗`energy_per_frame_mj` / 体积`engine_size_mb`; **闭环只留 `cl_driving_score`(DS) + `cl_route_completion`(RC)**(+`latency_inject_ms` 作 τ 特征)(详见 `schema_v2.md §双表结构`)。本文下方"latency/accuracy 标签"小节列出的多档值(ap30/50/70、lat p99/mean 等)与全部闭环 23 列在 **全表 `dataset_v2`(最全面)** 仍保留, **学习时只用上述规范列**。`cl_` 列现 0 行(`CL_INGEST=False`), 时延补全后填。
> 对象: `sources/complete_points_pyramid_v1.csv` (6 行完整点) 为主, 兼述共用列。
> 全部 PyramidFusion @ RTX4090。列序已按「标识 → 配置(剪枝/量化/硬件) → 标签 → 溯源 → 次要诊断」重排, 全空/诊断列(如 `fail_reason`)统一在末尾。
> 关键口径: **lat = 模型体 (subnet) 真测, 非端到端; AP = DAIR val 1789 全集真测(已 finetune)**。

## 一、为什么有空白 (先解释 6 条数据的空白)
这 6 条是从 `doe_real`(延迟管线, 54 列) ⋈ `stage_a`(AP) 来的, 延迟管线带了一些**只在特定场景才填**的列, 对这 6 条均匀精度 / body-only 测量不适用, 故空白:

| 全空列 | 为什么空 |
|---|---|
| `q_bits_per_stage` | 仅**分模块混合精度**配置才填; 这 6 条是均匀精度 → 空 |
| `d_builder_opt_level` | 本次 build 未设/未记录 TRT builderOptimizationLevel |
| `n_collected` / `n_skipped` | e2e 管线采集 voxel 的统计; body-only 测量未跑真实 voxel → 空 |
| `real_voxels_mean` / `real_voxels_p99` | 同上, 真实点云 voxel 数, body-only 不涉及 |
| `fail_reason` | 仅 `build_success=False` 时填; 6 条全 build 成功 → 空 |

部分填充: `int8_layer_pct` 仅 **base INT8** 一行有(94.8%), 其余未做 DETAILED 重建无法事后introspect。

## 二、列含义 (按重排后顺序)

### 标识
| 列 | 含义 |
|---|---|
| `anchor_id` | 配置唯一名 (如 `rtx4090_base_fp16`) |
| `triplet` | 剪枝档名 (T1_base / 各剪枝档) |
| `strategy` | DoE 采样策略归属 (baseline / sens / pareto) |
| `sig` | 配置签名 `s0_s1_s2_precision`, join 键 |

### 配置 — 剪枝 (B1)
| 列 | 含义 / 单位 |
|---|---|
| `stage0/1/2_planes` | 三个 stage 的输出通道数 (剪枝维度核心; 须 %32 对齐) |
| `prune_rate` | 名义剪枝率 (0.0=未剪) |
| `prune_object` | 剪枝对象 (channel / 2:4 / head / none) |
| `sparse_mask` | 是否稀疏 (dense=结构化剪枝, 非 mask) |
| `params_total_new` | 剪枝 rebuild 后总参数量 (个) |

### 配置 — 量化 (B2)
| 列 | 含义 |
|---|---|
| `q_bits` | 请求位宽 (FP16 / INT8 / FP32) |
| `effective_bits` | 应用约束后**实际生效**位宽 (敏感层回退后) |
| `q_granularity` | 量化粒度 (per-tensor / per-channel / none) |
| `q_object` | 量化对象 (W-only / W+A / none) |
| `calibrator` | 校准器 (minmax / percentile / none; entropy 已禁用) |
| `trt_precision` | TRT engine 精度模式 (fp16 / int8 / mixed) |
| `q_tag` / `prec_flag` | 量化标签 / 精度 flag (派生标识, 冗余可读) |

### 配置 — 硬件部署 (D)
| 列 | 含义 |
|---|---|
| `hardware` / `device` | 目标硬件 (rtx4090 / orin_agx) |
| `d_scheme` | 设备路由 (GPU / DLA0 / DLA1 / dual...) |
| `d_tactic` | TRT tactic 来源 (default / cublas_lt...) |
| `d_workspace_gb` | TRT workspace 上限 (GB) |
| `d_tag` | D 维组合标识 |
| `max_voxels` | voxelize 上限 (前处理参数) |

### ★ 标签 — latency (y1, 模型体真测)
| 列 | 含义 / 单位 |
|---|---|
| `lat_p50_ms` | 延迟中位数 (ms) **主指标** |
| `lat_p99_ms` | 延迟 p99 (ms, 长尾) |
| `lat_mean_ms` / `lat_std_ms` | 均值 / 标准差 (ms) |
| `throughput_fps` | 吞吐 (1000/lat_mean) |

### ★ 标签 — accuracy (y2, DAIR val 1789 真测)
| 列 | 含义 |
|---|---|
| `ap30` / `ap50` / `ap70` | IoU 阈值 0.3/0.5/0.7 下的检测 AP (0~1) |

### 标签 — 其它
| 列 | 含义 |
|---|---|
| `engine_size_mb` | TRT engine 文件大小 (MB) |
| `int8_layer_pct` | 真正跑 INT8 的层占比 (%); 仅 base INT8 测了 94.8% |
| `build_secs` | engine build 耗时 (秒) |

### 溯源 / 元信息
| 列 | 含义 |
|---|---|
| `is_real_measured` | **是否真实测** (True=可用数据点) |
| `source` | 逐标签来源 (如 `lat:trt_build_bench;ap:...`) |
| `exec_path` | 剪枝执行路径 (depgraph / handwritten) |
| `build_success` | engine 是否 build 成功 |
| `n_warmup` / `n_measure` | latency 测量的预热/测量次数 (200/200) |
| `onnx_path` / `engine_path` | 产物文件路径 |
| `ts` | 测量时间戳 |
| `pipeline_note` | 备注 (如 "REAL measured on RTX4090 GPU5") |

### 次要 / 诊断 (末尾, 多为空)
`q_bits_per_stage` · `d_builder_opt_level` · `n_collected` · `n_skipped` · `real_voxels_mean` · `real_voxels_p99` · `fail_reason` — 见第一节空白说明。

## 三、用这 6 条时的注意
1. **训预测器的 y**: latency 用 `lat_p50_ms`, accuracy 用 `ap50` (或 ap30/70)。
2. **x (特征)**: planes ×3 + prune_rate + q_bits/granularity/object + d_* + params_total_new。
3. **body latency ≠ e2e**: 这 6 条 latency 不含 voxelize/NMS, 比端到端小; 做 e2e Pareto 需另加前后处理耗时。
4. `p25 FP16` 的 2.43ms 是**非 32 对齐导致的反常慢点**, 是合法 Pareto 数据(说明对齐约束的重要性), 不是异常值要剔除。
