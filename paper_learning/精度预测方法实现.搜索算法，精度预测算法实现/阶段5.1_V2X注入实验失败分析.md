> **日期**: 2026-05-01

## 一、实验目的

验证 §阶段5.1 报告 §四.3 路径 A:**注入 coop_tiny ep30 的 V2X 融合权重**(24 keys),消除当前 merge pipeline 中"随机初始化 V2X 主导噪声"假设。

- 注入后**整体 F1 下降**且**剪枝带来"提升"** → 信号被注入操作破坏

## 四、根因分析

### 假设(已证伪)

> "随机 V2X 在 eval 时引入 ~0.5pt 噪声"

### 实际机制

1. **V2X 模块的训练分布与 merge 后输入分布不一致**:
   - `coop_tiny ep30` 中 V2X 与 `model_ego_agent`(coop_tiny 训出)+ `model_other_agent_inf`(coop_tiny 训出)**联合训练**
   - 我们的 merge 是 `stage1 ego` + `stage2 inf`,两者**独立训练**,query/feature 分布与 coop_tiny 的不同
   - 训练好的 V2X 是为"分布 X"学的非线性变换,作用于"分布 Y"会**主动失真**

2. **随机初始化 V2X 在 `strict=False` 加载下接近"零信息透传"**:
   - `cross_agent_align`(线性层 256×265)随机权重作用于 ego query → 输出几乎纯噪声,在 cross_agent_fusion 后被加到 ego query 上
   - 但因 V2X 残差权重小(典型 transformer 残差结构),整体接近 ego-only 的输出
   - 这意味着 0.1325 的"baseline"其实是 **ego-only 的天花板**,而非"V2X 真值"

3. **剪枝带来的轻微 ego features 偏移,被训练好的 V2X 放大**:
   - B1 剪枝 25% heads,ego query 略变
   - 训练好的 V2X 对错误分布的 query 反应不可控,某些样本反而"变好"(假阳性减少)
   - 导致 B1 反超 baseline 的悖论

## 五、教训与决策

### 教训

- **联合训练的模块不能用"权重移植"还原**:V2X 必须**与具体的 ego/inf 联合微调**才能给出有意义的输出
- **当前 merge pipeline `stage1_ego + stage2_inf` 不能用作 coop ckpt 的 drop-in 替换**:V2X 路径无效信息,但 ego-only 仍可工作(天花板 0.1325)
- **"信号 vs 噪声"的诊断需要对照实验**,不能只凭"missing key 数量"判断

### 决策

- ❌ **路径 A(V2X 注入)弃用**:已证不可行,反而恶化 SNR
- ✅ **当前 stage5_run_one_config.sh 已回滚**(commit message 中标注理由)
- ✅ **V2X-injected metrics 已隔离至 `data/phase4/stage5_metrics_v2x_inject_test/`**,作为反例保留
- ✅ **CSV `data/phase4/stage5_baseline_v2.csv` 数据有效**(基于回滚前的 merge 生成)

## 六、新方向: 路径 B'(待与用户确认)

### 思路

不再"merge stage1+stage2",而是**直接在 coop_tiny ep30 上应用剪枝**,保留 V2X 与 inf 不变。

```
coop_tiny ep30 (ego_coop, inf_coop, v2x)
   ↓ extract ego_coop sub-state
   ↓ build sub_vehicle_tiny model + load ego_coop weights
   ↓ apply prune (Torch-Pruning + custom_pruners)
   ↓ pruned_ego_coop
   ↓ rebuild full coop ckpt: pruned_ego_coop + inf_coop + v2x_coop
   ↓ eval → metrics
```

### 优势

- V2X 模块保持原训练状态,只承受"轻微剪枝偏移"(本应是我们想测量的)
- inf 完全不变,基线噪声归零
- 剪枝 → ego 偏移 → V2X 输出变化 → F1 变化:**直接因果链**

### 工作量

- ~30-60 min:写一个 `tools/prune_coop_ego.py` 脚本,绕过 stage1+stage2 merge
- ~20 min:重跑 baseline + B1 验证 SNR

### 预期

- baseline F1 应回到 0.1325 附近(因为 baseline 其实就是 coop_tiny ep30 本身)
- B1 应给出**真实**的剪枝 F1 下降信号
- 如 SNR 仍低 → 转向路径 B(shape mismatch 修复)或路径 D(收 30 configs 接受 SNR)
