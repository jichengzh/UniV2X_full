## 二、硬件基础

### 2.1 RTX 4090 (`configs/hardware/rtx4090.yaml`)

- 架构: Ada Lovelace
- IP: GPU only (无 DLA)
- 精度支持: FP32 / FP16 / INT8
- Tensor Core: 第 4 代 (支持 Sparse TC,可用 2:4 sparsity)
- 对齐约束: `alignment_enforcement = hard`(channel 必须 32 整除,Tensor Core IMMA 要求 wpg ∈ pow2)
- 部署运行时: TensorRT 10.13

### 2.2 Orin AGX (`configs/hardware/orin_agx.yaml`)

- 架构: Ampere
- IP: GPU + DLA0 + DLA1
- 精度支持: GPU={FP32, FP16, INT8},DLA={FP16, INT8}
- Tensor Core: 第 3 代 (支持 Sparse TC)
- 对齐约束: `alignment_enforcement = soft`(N2v2 实证 wpg=3/6/12 慢 <1%,容许)
- 部署运行时: TensorRT 8.5.2.2

## 三、搜索空间总览(per-stage 剪枝口径)

剪枝按 ResNeXt backbone 三个 stage 独立采样,因此 B 子空间按 `prune_object` 分支展开;量化和部署目前仍为全局维度。

| 大类 | 维度 | schema 字段 | 取值集合 |
|------|------|-------------|---------|
| **B 剪枝** | B1 剪枝对象 | `prune_object` | {channel, 2:4, none} |
| | B2a stage0 planes | per-stage(`prune_object=channel`) | 4090:{16,24,32,40,64} \| Orin:{16,24,32,40,48,56,64} |
| | B2b stage1 planes | per-stage(`prune_object=channel`) | 4090:{16,24,32,40,64,72,128} \| Orin:{16,24,32,40,48,56,64,72,96,104,128} |
| | B2c stage2 planes | per-stage(`prune_object=channel`) | 4090:{16,24,32,40,64,72,128,136,256} \| Orin:{16,24,32,40,48,56,64,72,96,104,128,136,192,200,256} |
| | B3 stage 2:4 mask | per-stage(`prune_object=2:4`) | 每 stage ∈ {2:4, dense},去除两个等价情况 → 6 partial + 1 all-on |
| **Q 量化** | Q1 位宽 (全局) | `q_bits` | {INT8, FP16, FP32} |
| | Q1' 位宽 (per-stage) **[暂定 / 待验证]** | `q_bits_per_stage` | (s0,s1,s2) ∈ {FP16, INT8}³ — 8 种 / 含 FP32 则 27 种 |
| | Q2 粒度 | `q_granularity` | {per-tensor, per-channel, none} |
| | Q3 目标 | `q_object` | {W-only, W+A, none} |
| **D 部署** | D_scheme IP 路由 + 流水线 | `d_routing` | {单 IP GPU / DLA0 / DLA1, 双 IP A / B, 三 IP C}(按硬件能力派生,见 §5) |
| | D_tactic TRT tactic_sources | — | 4090 (TRT 10): 5 取值 \| Orin (TRT 8.5): 4 取值 |
| | D_workspace TRT workspace | — | 4090: {1,2,4,8,16}GB \| Orin: {1,2,4,8}GB |
| | 其他 D 维度 **[暂定/未纳入]** | — | GPU fallback policy / power mode / CUDA Graph 等,详见 §5.3 |

> **Q1' per-stage 量化** 利用 TRT `IBuilderConfig.PREFER_PRECISION_CONSTRAINTS` + `layer.precision = trt.int8/half` 实现,工程入口已在 `m4_8_trt_build_bench.py --mixed-fp16-substr` 就绪。状态: **暂定**,先在 3 个代表 triplet × 8 个 per-stage 组合上验证 Pareto 改善后再决定是否纳入完整搜索空间。本文档第六节总数统计 **仍按全局 Q1 (=9) 计算**,per-stage Q1' 不重复计入。

## 四、强约束(维度间耦合)

非独立笛卡尔,以下耦合约束必须先施加再统计:

| # | 约束规则 | 影响维度 |
|---|----------|---------|
| C1 | `prune_object = none` ⇒ 所有 stage planes = baseline (64,128,256),无 2:4 mask | B2/B3 ⇐ B1 |
| C2 | `prune_object = channel` ⇒ per-stage planes 从对应池采样,2:4 mask 全 dense | B2 启用 / B3 关闭 |
| C3 | `prune_object = 2:4` ⇒ per-stage 2:4 mask 启用,planes = baseline | B3 启用 / B2 关闭 |
| C4 | `q_bits = FP32` ⇒ `q_granularity = none, q_object = none` | Q2, Q3 ⇐ Q1 |
| C5 | `q_bits ∈ {INT8, FP16}` ⇒ `q_granularity ∈ {per-tensor, per-channel}`, `q_object ∈ {W-only, W+A}` | Q2, Q3 ⇐ Q1 |
| C6 | 硬件无 DLA ⇒ `d_routing = GPU` 唯一 | D1 ⇐ 硬件 |
| C7 | 硬件无 sparse_tc ⇒ `prune_object ≠ 2:4` | B1 ⇐ 硬件 |
| C8 | `alignment_enforcement = hard` ⇒ ResNeXt width_per_group ∈ {1,2,4,8,16,32} | B2 ⇐ 硬件 |
| C9 | channel 剪枝后 planes 必须 8 整除 | B2 |
| C10 | 跨层梯度: \|r_i - r_{i+1}\| ≤ 0.30 (i ∈ {0,1},相邻 stage diff,源自 `p0_pyramid_random_bench.enumerate_triplets`) | B2 |
| C11 | `prune_object = 2:4` ⇒ `d_routing` 必须落 sparse_tc IP(Orin: GPU;DLA 无 Sparse TC) | B1 × D1 |
| C12 备注 | **不在此处加 C12a/b/c 手写约束**。算子-硬件兼容性、DLA banks 阈值、流水线 throughput 增益条件等规律由 **LGB 预测器从 bench 数据中学习**,通过 build_success / lat / throughput 多目标预测自动暴露给搜索器。framework 的硬约束 (C1-C11) 仅覆盖**结构性物理约束**(对齐、宽度、跨层梯度等),**不预设硬件知识**。撤回 v1 错误概括"C12: V2X 整模型 DLA 不兼容"+ v2 提议的"C12a/b/c per-operator 约束"。 | — |

## 五、BQD 子空间拆解

### 5.1 RTX 4090

**B 子空间(剪枝,per-stage 展开)**

| prune_object | per-stage 展开 | 子空间大小 |
|--------------|---------------|-----------|
| none | 单一 baseline 配置 | 1 |
| channel | (s0, s1, s2) ∈ 5 × 7 × 9 = 315 笛卡尔,经 C10 跨层梯度 ≤30% 过滤 | **98** |
| 2:4 | per-stage 2:4 mask 2³ = 8,扣除 all-off (≡ none) 和 all-on(单全局点) → 6 partial + 1 all-on | **7** |
| **B 总** | 1 + 98 + 7 | **106** |

**Q 子空间(量化)** — 已经 Part A 验证纳入 per-stage Q1'

| q_bits 类型 | 子空间组成 | 子空间大小 |
|-------------|-----------|-----------|
| FP32 (全局) | 1 × 1 (粒度=none × 目标=none) | 1 |
| FP16 (全局) | 2 × 2 (per-tensor/per-channel × W-only/W+A) | 4 |
| INT8 (全局) | 2 × 2 (同上) | 4 |
| **Q1' per-stage** | (s0,s1,s2) ∈ {FP16,INT8}³ — 2³ | 8 |
| **Q 总(全局 + per-stage)** | | **17** |

> 注: Part A 验证(`results/perstage_quant_pareto.md`)显示 18/18 个 per-stage 配置在 Pyramid + 4090 上均比全 INT8 慢 17-43%(reformat overhead 显著),**但它们仍是搜索空间合法成员** — 搜索器的工作是在 17 个量化选项中找 Pareto frontier,LGB 训练数据应覆盖正负样本。详见 `results/search_space_v2_validation.md` §0.1。

**D 子空间(部署)** — 三个维度共同构成 D 空间

| D 维度 | 取值 | 子空间大小 | 跟 B/Q 的交互 |
|--------|------|-----------|----------------|
| **D_scheme**(IP 路由 + 流水线一体化) | {单 IP GPU}(4090 无 DLA,IP=1 必然 D_scheme 退化为单一选项) | **1** | — |
| **D_tactic**(TRT 10.13 tactic_sources) | {default, default+CUDNN, default+CUBLAS_LT, CUBLAS_LT only, all enabled} | **5** | **强耦合 Q**: 2:4 sparsity 需 CUBLAS_LT、per-channel 需 EDGE_MASK,Sparse INT8 比旧 INT8 快 1.5-2× |
| **D_workspace**(TRT workspace) | {1GB, 2GB, 4GB, 8GB, 16GB}(4090 24GB VRAM,16GB 留 8GB 活动张量与 I/O,16GB 之上不合理) | **5** | **资源 Pareto 轴**:小 workspace 意味着可部署到低配硬件(论文 §C 论点之一) |
| **D 总(三维度笛卡尔)** | | **1 × 5 × 5 = 25** | |

> Part B-4090.2 实证只在 baseline triplet × {FP16, INT8} 上跑了 4 个 tactic/workspace combo,得到 spread 0.8%~4.1%。**但此结果不覆盖 2:4 / per-channel 这些跟 Q 强耦合场景**,真实 spread 在 sparse 量化路径上可能 10%+。数据是 LGB 训练样本,不是"移出搜索空间"的依据。

**4090 上其他 D 维度判定**(整合自旧 §五·补.1):

| D 维度 | 是否存在 | 说明 |
|--------|---------|------|
| GPU fallback policy | 不存在 | 无 DLA,无 fallback 概念 |
| MIG profile | 不存在 | Ada Lovelace 不支持 MIG(A100/H100/B200 专有) |
| Power mode | 不可调 | 桌面卡 power 由系统/驱动管理 |
| MPS active% | 单进程场景不用 | Pyramid 单实例推理,无并发 |
| CUDA Graph | **移出搜索空间** | runtime 调度(capture+replay),只在推理时启用,不参与 engine build;实测 -4~9% 对所有 config 等比改善,不影响 Pareto 形状。若 paper 要展开可作为正交维度补充。 |

### 5.2 Orin AGX

**B 子空间(剪枝,per-stage 展开)**

Orin 的 `alignment_enforcement = soft` 让 wpg ∈ {3, 6, 12} 也被接受(N2v2 实证慢 <1%),所以每 stage planes 池比 4090 大:

| stage | Orin 合法 planes | 数量 |
|-------|-----------------|------|
| s0 | {16, 24, 32, 40, 48, 56, 64} | 7 |
| s1 | {16, 24, 32, 40, 48, 56, 64, 72, 96, 104, 128} | 11 |
| s2 | {16, 24, 32, 40, 48, 56, 64, 72, 96, 104, 128, 136, 192, 200, 256} | 15 |

| prune_object | per-stage 展开 | 子空间大小 |
|--------------|---------------|-----------|
| none | 单一 baseline 配置 | 1 |
| channel | (s0, s1, s2) ∈ 7 × 11 × 15 = 1155 笛卡尔,经 C10 跨层梯度 ≤30% 过滤 | **315** |
| 2:4 | per-stage 2:4 mask 2³ = 8,扣除 all-off (≡ none) 和 all-on(单全局点) → 6 partial + 1 all-on(注: 2:4 仅 GPU,不能落 DLA,见 C11) | **7** |
| **B 总** | 1 + 315 + 7 | **323** |

**Q 子空间(量化)** — 同 4090,扩展到 17 维(全局 9 + per-stage 8)

| q_bits 类型 | 子空间组成 | 子空间大小 |
|-------------|-----------|-----------|
| FP32 (全局) | 1 × 1 | 1 |
| FP16 (全局) | 2 × 2 | 4 |
| INT8 (全局) | 2 × 2 | 4 |
| **Q1' per-stage** | (s0,s1,s2) ∈ {FP16,INT8}³ | 8 |
| **Q 总** | | **17** |

**D 子空间(部署)** — 三个维度,取值集合按硬件 capability 派生

| D 维度 | 取值 | 子空间大小 |
|--------|------|-----------|
| **D_scheme**(IP 路由 + 流水线一体化) | {单 IP GPU, 单 IP DLA0, 单 IP DLA1, 双 IP A (backbone→DLA0 + collab→GPU), 双 IP B (backbone→DLA1 + collab→GPU), 三 IP C (stage0/1→DLA0 + stage2→DLA1 + collab→GPU)} | **6** |
| **D_tactic**(TRT 8.5.2.2 tactic_sources) | {default, default+CUDNN, default+CUBLAS_LT, all enabled}(无 JIT_CONVOLUTIONS,TRT 10+ 才引入) | **4** |
| **D_workspace**(TRT workspace) | {1GB, 2GB, 4GB, 8GB}(Orin AGX 64GB 共享内存,8GB 留给 TRT 是合理上限,留 ≥48GB 给 OS + weight + 其他进程;再高不合理) | **4** |
| **D 总(三维度笛卡尔)** | | **6 × 4 × 4 = 96** |

> **不预删 D_scheme**: 即便 单 IP DLA0 / DLA1 在 Pyramid V2X 模型上几乎必然触发大量 GPU fallback(collab module 含 GridSample/Einsum/Where 算子不在 DLA 白名单),仍把它们留在搜索空间内。framework 不写手写的"V2X 模型与 DLA 不兼容"规则 —— 这种知识让 **LGB build_success / lat 预测器从 bench 数据中学到**(整图 DLA 必然慢 / fallback 率高 → build_success 概率低 → 搜索器自动避开)。这才是 hardware-aware search 的真正含义。
>
> 此前提议的 C12a/b/c (V2X 算子 DLA 兼容性)、C13a (DLA banks 阈值)、C13b (DLA bottleneck 流水线无价值) **均不写入 `framework/constraints.py`**。

**Orin 上其他 D 维度判定**(整合自旧 §五·补.2):

| D 维度 | 是否存在 | 取值集合 | 当前状态 | 说明 |
|--------|---------|----------|---------|------|
| GPU fallback policy | **存在(Orin 独有)** | {strict, permissive} | [暂定 / 待 Part B-Orin.2 验证后纳入] | DLA 算子白名单触发,与 D_scheme=DLA* 强耦合 |
| Power mode (nvpmodel) | **存在(Orin 独有)** | {MAXN, 30W, 50W, custom} | 暂未纳入(论文不展开) | 影响 freq/power,跨配置乘性影响 |
| Clock governor | 存在 | {locked, userspace} | 暂未纳入(N2v2 实证用 locked 锁频) | 不锁频会引入测量噪音 |
| MIG profile | 不存在 | — | 不适用 | iGPU 不支持 MIG |
| MPS active% | 单进程场景不用 | — | 不适用 | Pyramid 单实例推理,无并发 |
| CUDA Graph | **移出搜索空间** | — | 同 4090 | runtime 调度,跟 build 无关。要纳入可作为正交 yes/no 维度. |

### 5.3 D 空间派生原则汇总(整合自旧 §五·补.3)

D 维度集合是**硬件 capability ∩ 部署场景**的函数,不是先验固定的 27 维全集。`survey_raw_2/d_space_nvidia.md §7` 的 27 维表是"NVIDIA 栈所有可能维度的并集",真正派生到具体硬件时通常 ≤6 维参与笛卡尔积 + 1-2 维待纳入。

| 派生规则 | 适用场景 |
|---------|---------|
| **R1**: IP 数 = 1 ⇒ D_scheme 退化为单一 GPU,IP-间流水线维度不存在 | RTX 4090 / Orin Nano |
| **R2**: 无 DLA ⇒ GPU fallback policy 维度不存在,DLA 路由维度不存在 | RTX 4090 |
| **R3**: 非数据中心卡 (Ada/Ampere consumer 或 iGPU) ⇒ MIG 不存在 | RTX 4090 / Orin |
| **R4**: 嵌入式平台 ⇒ power mode / clock governor 维度存在(桌面卡 power 由系统管) | Orin |
| **R5**: 单模型推理场景 ⇒ MPS / 多 stream 并发维度不存在 | Pyramid 当前场景 |
| **R6**: GPU 通用维度 (TRT workspace / TRT tactic_sources) 总是存在 | 所有 NVIDIA 硬件 |
| **R7**: 不靠经验/启发式预删搜索空间 D 维度取值 | framework 通用原则; 仅当物理上不可行(如 16GB > 4090 24GB VRAM 留余量)才删 |

→ paper 引用 D 维度数时,应明确写"**4090 派生 D 空间 = 1 × 5 × 5 = 25 维 / Orin AGX = 6 × 4 × 4 = 96 维**",不是 NVIDIA 栈并集 27 维。

## 七、引用规范

- **paper / report 引用"搜索空间大小"** 必须标注口径(理论 / 实证 + 硬件名 + per-stage 或 1-module)
- **正确写法示例**:
  - "Pyramid on RTX 4090: **45,050 theoretical configurations** (B 106 × Q 17 × D 25,其中 D = D_scheme × D_tactic × D_workspace = 1 × 5 × 5)"
