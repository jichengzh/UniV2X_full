## 一、总览 — 我们的方法学定位

论文的 B (剪枝) × Q (量化) × D (部署) 联合搜索框架不创新具体的剪枝/量化算法,而是 **复用已被验证的成熟方法,把它们作为搜索空间的合法成员**。framework 的贡献在 **C1 capability schema / C2 双向硬约束传播 / C3 联合搜索 / C4 三模型 Pareto 对比** (见 `00_故事评估与实验路线_v1.md §1.2`),不在"提出更好的剪枝准则"或"提出更好的校准器"。

剪枝和量化方法的取舍原则:

| 原则 | 含义 |
|------|------|
| **复用而非新增** | 剪枝准则只用 L1-norm + Torch-Pruning,量化只用 TensorRT 官方 calibrator + QuantV2X PTQ 移植代码 |
| **结构化优先** | channel pruning 走 dense rebuild (改 `num_filters`),不留 mask;2:4 sparsity 由 TRT SPARSE_WEIGHTS 自动检测,不手工 mask |
| **TRT-native 校准** | 主路径用 `trt.IInt8EntropyCalibrator2` / `trt.IInt8MinMaxCalibrator`;扩展路径用手工 `tensor.dynamic_range` API 实现 percentile |
| **PyTorch 实现是 reference,TRT 是 truth** | QuantV2X-style PTQ (per-channel, per-group, AdaRound) 留在 PyTorch 侧用于 amota 评估;TRT engine 上用 calibrator 直出 INT8 |

## 二、剪枝方法 (B 维度)

### 2.1 B1 — 通道结构化剪枝 (channel pruning)

**思路**: 按 L1-norm 排序每个 conv layer 的输出通道, 取 top-N 保留, **dense rebuild** (重建一个更小的 `num_filters` 子模型, 不留 mask)。

**两条实现路径** — 一条给 HEAL Pyramid, 一条给 UniV2X:

| 模型 | 入口脚本 | 准则 | 落地方式 |
|------|---------|------|---------|
| **HEAL Pyramid_DAIR_m1** | `tools/structural_prune_pyramid.py` (line 1-25) | **L1-norm only** (line 77-88, conv3 输出通道) | dense rebuild — `num_filters [64,128,256] → 任意 (s0,s1,s2)`; weight slicing 保留 ResNeXt groups=32 约束 (line 156-293) |
| **UniV2X** | `projects/mmdet3d_plugin/univ2x/pruning/prune_univ2x.py` (line 4) | **L1-norm / L2-norm / FPGM / Taylor 四选一** (line 108-132), 通过 `importance_criterion` 字段配置 | dense rebuild via Torch-Pruning DepGraph |

**per-stage planes 的取值池** (搜索空间 §三, RTX 4090): s0 ∈ {16,24,32,40,64}, s1 ∈ {16,24,32,40,64,72,128}, s2 ∈ {16,24,32,40,64,72,128,136,256} — 受硬件对齐约束 `channels % 8 == 0` + Tensor Core IMMA `width_per_group ∈ pow2` (`framework/constraints.py`) 过滤。

**参考来源**:

| 引用 | 来源 | 备注 |
|------|------|------|
| L1-norm 通道剪枝 | Li et al. *Pruning Filters for Efficient ConvNets*, ICLR 2017 | 论文里"权重 L1 范数 ≈ 通道重要性"的经典 baseline,与 `pruning_x_hardware.md §0.2` 提到的"CNN+ReLU 偏 L1" 一致 |
| Torch-Pruning DepGraph | [VainF/Torch-Pruning](https://github.com/VainF/Torch-Pruning) (Fang et al. *DepGraph: Towards Any Structural Pruning*, CVPR 2023) | UniV2X 侧直接 `import torch_pruning`, 自定义 pruner 给 `MultiScaleDeformableAttention` 等 CUDA 算子做适配 (`custom_pruners.py:1-3`) — 因为 torch.fx 无法穿透 CUDA kernel |
| HEAL Pyramid 模型基底 | [yifanlu0227/HEAL](https://github.com/yifanlu0227/HEAL) (Lu et al. *HEAL: Heterogeneous Alliance...*, ICLR 2024) | Pyramid 侧 ResNeXt Bottleneck 定义、参数公式从 HEAL repo 直接复用 (`tools/structural_prune_pyramid.py:38`) |

**framework v1.5 中的角色**: 对应 §0.2 B1 三轴中的"剪枝粒度 = channel" + §0.5 "BEV backbone CNN 偏 L1"。

### 2.2 B1' — 2:4 N:M 结构化稀疏 (sparsity)

**思路**: 每 4 个权重保留 2 个 (NVIDIA Ampere/Ada Sparse TC 硬件支持), 在 cuSPARSELt INT8 GEMM 路径上理论 1.5-2× 加速。

**当前状态**: **TRT engine flag 通路打开, 但权重 pre-sparsification 算法占位未实装**。

| 代码位置 | 状态 |
|---------|------|
| `scripts/phase1/m4_8_trt_build_bench.py:250-264` | `BuilderFlag.SPARSE_WEIGHTS` flag 设置 (`int8_sparse` / `fp16_sparse` mode) — TRT 自动检测权重是否 2:4 模式, 是则用 sparse kernel |
| **缺失**: 权重 2:4 mask 应用 (例如 NVIDIA ASP `apply_sparsity()` 或 cuSPARSELt prune 函数) | 没有, 当前 SPARSE_WEIGHTS flag 在 dense weights 上无效 — 实测加速 ≈ 0 (M4.6 阶段 `data/baseline_4090.parquet` 已验证) |

**参考来源** (将要实装时):

| 引用 | 来源 | 备注 |
|------|------|------|
| 2:4 sparsity 理论 | Mishra et al. *Accelerating Sparse Deep Neural Networks*, arXiv:2104.08378 (NVIDIA 2021) | A100 Sparse TC 白皮书的方法论基础 |
| NVIDIA ASP (Automatic Sparsity) | [NVIDIA/apex `apex.contrib.sparsity`](https://github.com/NVIDIA/apex/tree/master/apex/contrib/sparsity) | 训练时插入 2:4 mask 的标准实现 |
| DL4AGX SparsityINT8 | [NVIDIA-AI-IOT/DL4AGX `AV-Solutions/SparsityINT8`](https://github.com/NVIDIA-AI-IOT/DL4AGX) | 2:4 + INT8 联合 PTQ/QAT 流程; HEAL Pyramid 移植路径已规划在 §4.4 M4 子任务 |

**framework v1.5 中的角色**: 搜索空间一览 §三 B3 字段, 4090 子空间 7 配置, Orin 7 配置 (C11 约束)。**当前是"搜索空间合法成员但实测加速 = 0 的负样本"**, 对应反思 #29 "搜索空间 ≠ Pareto frontier" 论点的活案例。

### 2.3 剪枝后微调 (fine-tune)

**思路**: 剪枝重建小模型后, 用 HEAL/UniV2X 原训练流程做短期微调 (3-30 epoch) 恢复 AP。

**实现**:

| 入口 | 用途 | 关键参数 |
|------|------|--------|
| `tools/finetune_pruned.py:1-100` | UniV2X 微调入口 | `--epochs` (默认 3), `--lr-scale` 0.1×, `--train-modules` 冻结策略, `--skip-aux-heads` |
| HEAL `train.py` (直接调) | Pyramid 微调入口 | 全字段沿用 HEAL config; M4.8 阶段 `scripts/phase2/extend_ft_training_v2.py` 把 epoches 48→78 |

**当前已知问题**: 自训 ckpt fine-tune schedule 让中间激活分布比官方 ckpt 宽 2-3×, 触发 INT8 entropy 校准 AP 崩塌 (详见 `data/问题.md §问题 1`)。**多训 30 epoch 验证为无效** (问题.md §1.5.1)。

**参考来源**:

| 引用 | 来源 |
|------|------|
| HEAL 训练 schedule | HEAL repo `opencood/tools/train.py`, 模型权重 `Pyramid_DAIR_m1_base_2023_08_14_11_42_29` |
| Pruning + Finetune 双阶段范式 | He et al. *Channel Pruning for Accelerating Very Deep Neural Networks*, ICCV 2017 (经典 baseline; framework v1.5 §0.5 提到的"准则评估必须在量化后做"即来源于此线) |

## 三、量化方法 (Q 维度)

### 3.1 Q1 — 位宽 (precision)

**取值**: FP32 / FP16 / INT8 (搜索空间一览 §三)。

**实现**: TensorRT IBuilderConfig flag — `BuilderFlag.FP16` / `BuilderFlag.INT8` 控制 build 时 layer 精度。FP32 是默认 fallback。

代码位置: `scripts/phase1/m4_8_trt_build_bench.py:238-260`, `tools/build_trt_int8_univ2x.py:330-360`。

### 3.2 Q1' — Per-stage 混合精度 (mixed-precision)

**思路**: 每个 ResNeXt stage 独立选 FP16 或 INT8 — 8 种组合 (s0,s1,s2) ∈ {FP16,INT8}³。

**实现**: TRT `IBuilderConfig.PREFER_PRECISION_CONSTRAINTS` flag + 逐层 `layer.precision = trt.int8 / trt.float16` 显式设置, 按 layer name 子串匹配 stage。

| 代码 | 作用 |
|------|------|
| `scripts/phase1/m4_8_trt_build_bench.py:238-249` | `--precision mixed --mixed-fp16-substr` CLI 入口 |
| `scripts/phase1/m4_8_trt_build_bench.py:293-310` | `_set_layer_precision()` — 遍历 QUANTIZABLE_KINDS 层按 substr 匹配 |
| `scripts/phase1/m4_8_trt_build_bench.py:309` | `PREFER_PRECISION_CONSTRAINTS` (软约束, 不支持的 layer fallback) |
| `scripts/phase2/p0_perstage_quant_bench.py:42-51` | 6 种 per-stage 配置 (c3-c8) 定义 |

**Part A 验证结果**: 18/18 个 per-stage 组合均比全 INT8 慢 17-43% (reformat overhead, `results/perstage_quant_pareto.md`), 但**仍是搜索空间合法成员** (LGB 负样本)。

**参考来源**: TensorRT 官方 [Mixed Precision API](https://docs.nvidia.com/deeplearning/tensorrt/developer-guide/index.html#mixed-precision-c) — 没有引用具体论文, 是 NVIDIA 工程实践。

### 3.3 Q2 — 量化粒度 (per-tensor / per-channel)

**取值**: per-tensor / per-channel (搜索空间一览 §三; per-group 因 TRT 不支持已剔除 v1.5 §0.2)。

**TRT 默认行为**: **per-channel weight + per-tensor activation** (NVIDIA 推荐, 也是 Orin DLA 唯一支持的组合)。

| 代码 | 作用 |
|------|------|
| `projects/mmdet3d_plugin/univ2x/quant/quant_layer.py:55-82` | PyTorch 侧 `UniformAffineQuantizer.channel_wise=True` (用于 amota 评估, 不参与 TRT engine 路径) |
| `projects/mmdet3d_plugin/univ2x/quant/quant_layer.py:107-143` | `_quantize_per_group()` per-group 实现 (modelopt-style, 仅 PyTorch reference) |

**项目中 TRT engine 路径**: **没有自定义 granularity 覆盖**, 全部走 TRT 默认 (per-channel W + per-tensor A)。framework v1.5 §0.2 也明确"per-channel activation 在 GPU GEMM 不支持"作为硬约束。

### 3.4 Q3 — 量化对象 (W-only / W+A)

**取值**: W-only / W+A (搜索空间一览 §三)。

**实现状态**: **W+A 完全实装, W-only 在搜索空间但代码未实装**。

| 配置 | 状态 | 代码 |
|------|------|------|
| W+A (权重+激活都 INT8) | ✅ 完全实装 | 所有 INT8 calibration 路径默认行为 |
| W-only (仅权重 INT8, 激活 FP16) | ⚠️ 未实装 | NVIDIA modelopt 支持但项目未集成; QuantV2X PTQ 框架也聚焦 W+A 不含 W-only 分支 |

**为什么 W-only 没实装**: 项目继承 QuantV2X PTQ 方法体系 (移植关系见 §3.6), QuantV2X 的研究焦点在 mixed precision W+A 不是 W-only LLM 量化场景。framework 把 W-only 留在搜索空间是为了暴露给 LGB 当负样本 — 对应反思 #29 "搜索空间 ≠ Pareto frontier"。

### 3.5 校准方法 (calibrator)

> **决议 (2026-05-15, 见 `data/问题.md §1.5`)**:
> - **主路径**: `trt.IInt8MinMaxCalibrator` (方案 1)
> - **备选**: 手工 `tensor.dynamic_range` API + Percentile p99.99 (方案 2)
> - **禁用**: `trt.IInt8EntropyCalibrator2` — 自训 ckpt 上触发 AP 崩塌 (0.02), 见问题 1

| 校准器 | 状态 | 适用 |
|--------|------|------|
| MinMax | ✅ **主路径** | 论文所有 INT8 anchor / Pareto 数据收集 / LGB 训练数据 |
| Percentile p99.99 | ⏸ 备选 | calibrator-family 消融实验, 当作 LGB 补充数据点 |
| Entropy KL | ✗ 禁用 (自训 ckpt) | 仅保留 4 个官方 ckpt 上有效的历史数据作为负样本对照 |

**三条路径并存的代码** — 主路径用 TRT 官方, 扩展路径用手工 dynamic_range:

#### (1) Entropy calibration (KL divergence minimization)

| 代码 | 作用 |
|------|------|
| `tools/build_trt_int8_univ2x.py:49` | `UniV2XInt8CalibratorImpl(trt.IInt8EntropyCalibrator2)` |
| `scripts/phase1/m4_8_trt_build_bench.py:139-140` | `NumpyCalibratorEntropy` 工厂类 |
| `tools/build_trt_int8_univ2x.py:206-207` | 从 `calibration/bev_encoder_inputs.pkl` (4.0GB) 加载 |
| `tools/build_trt_int8_univ2x.py:109-120` | `read_calibration_cache` / `write_calibration_cache` cache 生命周期 |

**引用**: TensorRT 官方 `IInt8EntropyCalibrator2` 实现的 KL 散度最小化, 基于 Migacz *8-bit Inference with TensorRT*, GTC 2017。

#### (2) MinMax calibration

| 代码 | 作用 |
|------|------|
| `scripts/phase1/m4_8_trt_build_bench.py:139-140` | `NumpyCalibratorMinMax` 工厂类 (`trt.IInt8MinMaxCalibrator`) |
| `scripts/phase1/m4_8_trt_build_bench.py:70-79` | 多输入支持 `--calib-multi name:path` |

**引用**: TensorRT 官方 `IInt8MinMaxCalibrator` — 直接取激活 |max|, 等价于 percentile=100%。

#### (3) Percentile calibration via manual dynamic_range API (方案 2)

| 代码 | 作用 |
|------|------|
| `scripts/phase2/build_percentile_e2e_engine.py:1-11` | 设计文档 — 绕开 IInt8 Calibrator |
| `scripts/phase2/build_percentile_e2e_engine.py:81-89` | `collect_percentile_scales()` — PyTorch hook BN+ReLU+Conv2d 输出取 p99.99 |
| `scripts/phase2/build_percentile_e2e_engine.py:257-275` | 遍历 TRT 网络 Conv/Activation/Elementwise 层, 调用 `tensor.dynamic_range = (-scale, +scale)` |
| `scripts/phase2/build_percentile_e2e_engine.py:366-375` | `UniformAffineQuantizer.perform_percentile_search()` — `torch.quantile()` 实现 |

**引用**:

| 引用 | 来源 | 备注 |
|------|------|------|
| Percentile-based clipping | McKinstry et al. *Discovering Low-Precision Networks Close to Full-Precision Networks for Efficient Embedded Inference*, arXiv:1809.04191 (2018) + NVIDIA modelopt 的 `percentile` calibrator 选项 | p99.99 是 NVIDIA modelopt 默认值 |
| TRT `tensor.dynamic_range` API | TensorRT C++/Python 公开 API | 不需要继承 IInt8Calibrator, 直接手工写入 scale |

**适用场景**: entropy KL 校准对"宽分布"过敏时 (见 `data/问题.md §问题 1`), percentile 提供 fallback 路径。已验证恢复 4 个自训 ckpt 的 INT8 entropy AP 从 0.02 → 0.58-0.65。

## 六、与论文 contribution 的对应
