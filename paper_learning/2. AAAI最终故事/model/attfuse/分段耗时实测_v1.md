# AttFuse (HEAL OPV2V LiDAR baseline) 全网络分段耗时实测

> **本文档为 AttFuse baseline 真权重 (HEAL HF 发布 `bestval_at15`) 在 RTX 4090 上的
> 完整分段耗时实测**，格式与 `pyramid_fusion/分段耗时实测_v1.md` 对齐。
>
> **架构同质性 caveat（必读）**：AttFuse 与 F-Cooper/V2VNet/V2X-ViT/Where2Comm 共享 HEAL
> `HeterModelBaseline` 框架，**encoder_m1 + backbone_m1 + shrinker_m1 stride 完全一致**
> (PointPillar + [3,5,8] BaseBEVBackbone + stride 1 shrinker)，仅 `fusion_net` 不同。
> 详见 `V2X_baselines_横向对比_v3.md` §架构同质性声明。
>
> 关键发现：AttFuse 的 single-layer self-attention fusion 占 e2e **3.4%**，NMS 占 **77%**
> — 与 F-Cooper / Pyramid m1 一致的瓶颈模式。本框架 P0 (CUDA NMS) 可拿到 **~4.3×** 加速。

## 三、关键结论

### 3.1 NMS 是绝对主因 (77% e2e)

与 F-Cooper / Pyramid m1 一致——AttFuse 的 self-attention 让 fusion 输出特征略不同，
但 heads 维度相同 → box 数量分布相近 → NMS workload 也相近 (78.58 vs F-Cooper 69.10)。

### 3.2 AttFusion 的算子分解

`opencood/models/fuse_modules/fusion_in_one.py:AttFusion`：

```python
x = warp_affine_simple(...)                     # grid_sample, 约 0.5 ms
x = x.view(cav_num, C, -1).permute(2, 0, 1)     # reshape, ~0.05 ms
h = self.att(x, x, x)                            # ScaledDotProductAttention, ~2.5 ms
h = h.permute(1, 2, 0).view(...)[0, ...]         # back to (C, H, W), ego pixel
```

**关键**：注意力在每个像素 (H×W=100×352=35200 个) 上做 cav_num × cav_num self-attention。
当 cav_num=2 时，attention 算量为 2×2×256 = 1024 dot-products × 35200 pixels = 36M ops × few constants.

对比 F-Cooper 的 max-pool（35200 个 max 操作）：**AttFuse 比 F-Cooper 重 2.1 ms (≈ 2.5×)**。

### 3.3 forward 内部分解

| forward 内部分解 | mean (ms) | 占 forward 18.48ms |
|---|---|---|
| encoder + backbone + shrinker (RSU 子模型) | 14.81 | 80.2% |
| fusion_net (AttFusion) | 3.49 | 18.9% |
| heads | 0.18 | 1.0% |
| **CNN+Attention 合计** | **18.48** | **100%** |

## 四、加速优先级（按 ROI 排序）

| 优先级 | 方法 | 攻击对象 | 节省 | e2e 加速 |
|---|---|---|---|---|
| **P0** | MMCV `nms_rotated_cuda` 替换 Shapely NMS | NMS 78.58 ms | → ~1 ms | **102.30 → 24.7 ms = 4.1×** |
| P1 | 50% prune encoder+backbone+shrinker + finetune | 14.81 ms (RSU) | → 8.9 ms | e2e ~1.05× (after P0) |
| P2 | TRT INT8 (RSU 子模型) | 14.81 ms | → 5.9 ms | e2e ~1.1× |
| P3 | TRT INT8 (含 AttFusion attention) | 18.48 ms | → 8 ms | e2e ~1.15× (after P0) |
| P4 | **fusion_net (AttFusion) 头剪枝 + INT8** | 3.49 ms | → 1.8 ms | e2e ~1.02× |

⚠️ **P4 caveat**：`ScaledDotProductAttention` 的 softmax 对 INT8 量化敏感，需 mixed-precision (Q/K FP16, V INT8) 或 calibration 精细调。

**结论**：P0 单点拿 4.1× e2e 加速；叠加 P1+P2 (剪枝+INT8 RSU) 到 ~5×（e2e ≈ 20 ms）。

| 指标 | Pyramid m1 | F-Cooper | **AttFuse** | 备注 |
|---|---|---|---|---|
| encoder_m1 | 3.01 | 3.02 | **3.24** | 一致 (相同 PointPillar) |
| backbone_m1 | 2.12 (ResNet) | 5.58 (BaseBEV) | **6.06 (BaseBEV)** | F-Cooper/AttFuse 同 |
| aligner / shrinker_m1 | 0.02 (AlignNet) | 5.45 | **5.51** | F-Cooper/AttFuse 同 |

### 6.2 关键观察

- **P0 单点拿 4.0× e2e 加速** — 比 F-Cooper 的 3.7× 略高，因 AttFuse baseline NMS workload 更重 (78.6ms vs 69.1ms)
- **NMS 32.7× 加速**: 78.58 → 2.40 ms — CUDA NMS 加速倍数与 box 数量正相关
- **e2e 25.6 ms = 39.0 FPS** — 接近 F-Cooper P0 (40.8 FPS)
- **AttFuse + P0 ≈ F-Cooper + P0**: P0 消除 NMS 差异后，两个模型的 e2e 仅差 1.1 ms (来自 fusion 的 2 ms)

## 七、Caveats

1. **score_threshold = 0.2**：与原 HEAL eval 一致。
2. **NMS 78.58 ms > F-Cooper 69.10 ms**：AttFusion 训练后 cls_head 阈值通过率略高 → 候选框数量更多 → NMS 工作量更大。
3. **AttFusion 参数 0.26M**：远小于 Pyramid 的 3.79M，但能显著提升 AP (论文表)。
4. **P0 加速倍数 (4.0×) > F-Cooper P0 (3.7×)**：因 baseline NMS 比 F-Cooper 重 (NMS 占 e2e 77% vs 77%, 但绝对量大 9ms)。
5. **未测精度**：参考 HEAL 论文 Table 2，AttFuse AP70 ≈ 0.81。
6. **原始数据**：baseline 在 `data/v2x_baseline_timing/attfuse_real.json`，P0 在 `attfuse_p0.json`。
