# V2X-ViT (HEAL DAIR-V2X baseline) 全网络分段耗时实测

> **本文档为 V2X-ViT baseline 真权重 (HEAL HF 发布 DAIR `bestval_at17`) 在 RTX 4090 上的
> 完整分段耗时实测**，格式与 `pyramid_fusion/分段耗时实测_v1.md` 对齐。
>
> **架构同质性 caveat（必读）**：V2X-ViT 与 F-Cooper/AttFuse/V2VNet/Where2Comm 共享 HEAL
> `HeterModelBaseline` 框架，encoder_m1/backbone_m1 配置相同，但 **shrinker_m1 stride=2** (输出 50×176 BEV,
> 比 F-Cooper/AttFuse stride 1 的 100×352 小 4×) — 这是 transformer fusion 必须的算力让步。
> 详见 `V2X_baselines_横向对比_v3.md` §架构同质性声明。
>
> ⚠️ **数据集差异**：与 F-Cooper / AttFuse (OPV2V) 不同，本测在 **DAIR-V2X-C** 上完成
> (HEAL HF 不发布 OPV2V LiDAR V2X-ViT 权重)。延时数据**仅可与 V2X-ViT 自身对照**，
> 与 OPV2V 上其他模型横向对比时需考虑数据集差异 (DAIR 范围 / agent 数量 / 点云密度都不同)。
>
> 关键发现：V2X-ViT 的 transformer fusion 占 e2e **44%**，是 6 个模型中 fusion 占比最高的。
> 但实测 fusion = 27.4 ms（远低于此前随机权重 OPV2V 估算的 148 ms）。

## 三、关键结论

### 3.1 V2X-ViT 是 fusion-heavy 模型 (44% e2e)

唯一一个 fusion 占 e2e > NMS 的模型：
- fusion: **27.39 ms (44.3%)**
- NMS:    23.75 ms (38.4%)
- 其他:   10.72 ms (17.3%)

P0 单独优化 NMS 只能省 38%；要再加速必须**剪 transformer fusion**。

### 3.2 V2X-ViT 的算子分解

`opencood/models/fuse_modules/fusion_in_one.py:V2XViTFusion`：

```python
class V2XViTFusion(nn.Module):
    def __init__(self, args):
        self.fusion_net = V2XTransformer(args['transformer'])
        # depth = 3 encoder layers
        # num_blocks = 1 per layer
        # cav_att (HMSA): heads=8, dim=256, dim_head=32
        # pwindow_att (MSwin): heads=[16,8,4], window=[4,8,16], split_attn
        # feed_forward: mlp_dim=256
```

每个 encoder layer 包含：
- **HMSA (Heterogeneous Multi-Scale Attention)** — agent 间 attention (区分 vehicle/infra)
- **MSwin (Multi-Scale Window Attention)** — 3 个 window size (4/8/16) 的金字塔 attention
- **FFN** — 标准 transformer feed-forward
- 3 层 stack → 3 × (HMSA + MSwin + FFN)

p99 = 111 ms vs mean = 27 ms — **方差 4×**，因 transformer 对 scene 复杂度敏感（attention pattern 不均匀）。

### 3.3 forward 内部分解

| forward 内部分解 | mean (ms) | 占 forward 34.24 ms |
|---|---|---|
| encoder + backbone + shrinker (RSU 子) | 6.78 | 19.8% |
| **fusion_net (V2X-ViT)** | **27.39** | **80.0%** |
| heads | 0.06 | 0.2% |
| **合计** | **34.24** | **100%** |

**fusion_net 占 forward 80%**——这是 V2X-ViT 的核心成本。

## 四、加速优先级（按 ROI 排序）

| 优先级 | 方法 | 攻击对象 | 节省估计 | e2e (after) |
|---|---|---|---|---|
| **P0** | MMCV `nms_rotated_cuda` 替换 Shapely NMS | NMS 23.75 ms | → 1 ms | **61.86 → 39.1 ms = 1.6×** |
| **P1** ⭐ | **V2X-ViT transformer 剪枝 (head + dim)** + finetune | fusion 27.39 ms | → 15 ms | **after P0+P1 = 27 ms (2.3×)** |
| P2 | TRT FP16 transformer fusion | fusion 27 ms | → 18 ms | after P0+P2 = ~32 ms |
| P3 | INT8 (encoder+backbone+shrinker) | 6.78 ms | → 3 ms | after P0+P1 = ~24 ms |
| P4 ⚠️ | INT8 transformer (mixed precision) | fusion | uncertain | ~20 ms（精度风险） |

⚠️ **P4 caveat**：V2X-ViT 的 transformer 中 softmax 量化对 attention quality 极敏感，
INT8 attention 一般会掉 5-10 AP 点。需 Q/K 保 FP16 + V 量化 + finetune。

**结论 (vs F-Cooper/AttFuse)**：
- F-Cooper/AttFuse: P0 拿 3.7-4.0× e2e 加速 (NMS dominant)
- V2X-ViT: P0 仅 1.6× (NMS 比例小)，**必须 prune fusion 才能再赢 2×**

## 五、与 F-Cooper / AttFuse 对比（注意数据集差异！）

| 指标 | F-Cooper (OPV2V) | AttFuse (OPV2V) | **V2X-ViT (DAIR)** | 备注 |
|---|---|---|---|---|
| 数据集 | OPV2V test | OPV2V test | **DAIR-V2X val** | ⚠️ 不同集 |
| agents/scene | 1.39 | 1.39 | **2.00** | DAIR 固定 2 (V2I) |
| encoder_m1 | 3.02 | 3.24 | **2.90** | DAIR 点云略稀疏 |
| backbone_m1 | 5.58 | 6.06 | **2.99** | V2X-ViT shrinker stride 2 后 backbone 输入小 |
| shrinker_m1 | 5.45 | 5.51 | **0.89** | stride 1 vs 2 |
| fusion_net | 1.41 | 3.49 | **27.39** | 3 层 transformer 是 ConvGRU/SDP 的 8-20× |
| nms | 69.10 | 78.58 | **23.75** | DAIR scene 中 box 数少很多 |
| **e2e** | **89.81** | **102.30** | **61.86** | DAIR 反而比 OPV2V 快 (因 NMS 少, fusion 较重) |

**洞察**：DAIR vs OPV2V 不能简单 e2e 比较，必须分阶段。fusion_net 是模型本质属性 (与数据集弱相关)，
encoder/NMS 是数据集属性。**V2X-ViT 模型的"复杂度成本"清晰可见在 fusion = 27.4 ms 这一列上**。

## 六、Caveats

1. **数据集不同**：本测在 DAIR-V2X，与 F-Cooper/AttFuse 在 OPV2V 数据集不直接可比。**仅 fusion_net 数字可作为模型属性参考**。
2. **score_threshold = 0.2**：与原 HEAL eval 一致。
3. **agents/scene = 2.00**：DAIR-V2X 是 V2I 数据集，固定 vehicle + infrastructure 2 agents。
4. **fusion_net p99 = 111 ms (mean 27.4 ms)**：transformer 对场景复杂度敏感，方差大。
5. **未测精度**：V2X-ViT 在 DAIR-V2X 的 AP 见 HEAL 论文 Table 4 (DAIR AP70 ≈ 0.55-0.60)。
6. **HEAL 不发布 OPV2V LiDAR V2X-ViT 权重**：所以无法在与 F-Cooper/AttFuse 同一数据集做严格横向对比。
7. **原始数据**：`data/v2x_baseline_timing/v2xvit_dair_real.json`。
